# Nanite 离线预处理与全 Mesh 管线方案（任务书）

> 状态：未开始 | 目标读者：渲染 / 构建系统维护者
> 关联文档：[10.Nanite实现分析.md](../HugEngine引擎介绍/10.Nanite实现分析.md)（Nanite 现有算法与数据格式的数学推导，本文不重复）

## 1. 背景与目标

### 1.1 现状

引擎的 Nanite 模块已经实现了「簇切分 → LOD/DAG → 量化打包 → BVH → 软/硬光栅 → 分页流式」的**大部分算法**，但**簇/DAG/量化/BVH 全部在运行时构建**：

- `Engine/Render/Nanite/NaniteUpload.cpp`：`BuildNaniteClusters()` / `BuildNaniteClusterDAG()` / `PackNaniteClusters()` / `BuildNaniteAssetFromGeometry()` / `BuildNaniteClusterBVH()`（RHI-free，头文件注释已声明是"离线簇切分（CPU 侧）"）；
- `Engine/Render/Nanite/NaniteRenderer.cpp:517-591`：每次加载几何时调用 `BuildNaniteAssetFromGeometry` 生成资产字节镜像；
- `Engine/Render/Nanite/NaniteStream.h`：页池、页表、反馈环、LRU 驱逐已存在；
- `Engine/Render/Pipeline/GBufferRenderer.cpp`：可选的 mesh 版 GBuffer（`HE_GBUFFER_MESH=1`），但仍是"整网格按 64 三角形切组"，且几何主路径默认走 IA/VS。

### 1.2 问题

1. **加载期成本**：`meshopt_buildMeshlets`、简化、量化、BVH 构建都在运行时做，大场景加载慢、内存峰值高；
2. **不可缓存**：同一资产每次启动都要重建，无法进 DDC/构建缓存；
3. **全 MS 未闭环**：GBuffer 的 IA 路径仍是默认，阴影/深度 pass 没有 MS 版本，Nanite 资产也只服务软/硬光栅的一部分场景；
4. **构建参数不可复现**：运行时构建受 CVar/环境影响，产物不稳定。

### 1.3 目标（按优先级）

| # | 目标 | 验收 |
|---|---|---|
| G1 | 把纯 CPU 的资产构建抽成独立库（`NaniteBuild`），工具与单测共用 | 全量构建 + `Tests/TestNaniteBuilder` 通过 |
| G2 | 新增离线工具 `Tools/MeshPreprocess` 与资产容器 `.hnm` | 工具可对 `Content/gltf` 生成 `.hnm` |
| G3 | 运行时优先读 `.hnm`，缺失时回退运行时构建 | 同一场景两条路径画面一致 |
| G4 | 构建期生成资产（hash 增量、缓存、失败回退） | `ProcessMeshes` 目标可重复执行 |
| G5 | 延迟管线几何主路径改走 Nanite（MS），支持"全 MS"开关 | `r.Nanite.Enable=1` 下 GBuffer 无 IA/VS |
| G6 | 阴影/深度 pass 的 MS 变体（可选阶段） | CSM/点光阴影无 IA 依赖 |
| G7 | 分页流式参数调优（页大小/池大小/限流） | 大场景显存峰值与加载时间达标 |

### 1.4 非目标

- 不改 Nanite 的误差度量、DAG 割判据、软光栅数学（见文档 10）；
- 不做运行时资产编辑/热重载（后续单独任务）；
- 不重写分页流式（已存在，只做参数与格式对接）。

## 2. 总体方案

```
Content/gltf/*.gltf ──(离线，Tools/MeshPreprocess)──▶ Content/Processed/*.hnm
                                                         │
运行时：NaniteAssetLoader 读 .hnm ──▶ GPU 缓冲（现有 NaniteRenderer 上传路径）
        ├─ 页表/页池（NaniteStream，已存在）
        ├─ DAG 遍历 + 剔除（NaniteCull，已存在）
        ├─ 硬光栅 MS（NaniteRaster，已存在）/ 软光栅（已存在）
        └─ GBuffer / 阴影 pass（本方案新增 MS 变体）
```

**关键设计决定**：

1. **CPU 构建代码抽成静态库 `NaniteBuild`**，工具与引擎测试都链它（而不是把代码搬进 `Tools/` 后引擎看不见）；
2. `.hnm` 容器**复用现有 Nanite 字节镜像布局**（`NaniteTypes.h` 的 `NaniteClusterRecord` / 量化格式），只加容器头、页表、DAG/BVH 段与版本/hash；
3. 运行时**优先读文件、缺失回退运行时构建**：程序化网格（地形/编辑器实时改网格）仍走回退路径；
4. 全 MS 分阶段：先 GBuffer 几何（Nanite 接管），再阴影/深度，最后移除 IA 依赖。

## 3. 资产容器 `.hnm`

### 3.1 容器布局

```
Header
  magic "HNM1", version, settingsHash, sourceHash
  clusterCount, dagNodeCount, pageCount, streamCount
  bboxMin/bboxMax, rootNode, flags
Sections[]（按 offset/size 索引）
  ClusterRecord[]        // 复用 NaniteTypes.h 的 NaniteClusterRecord
  DagNode[]              // 层级节点：childOffset/childCount/maxError/bounds/pageIndex
  PositionStream         // 簇局部量化（u16×3），按 cluster 连续
  OctNormalStream        // 八面体 10+10 位
  UVStream               // R16G16_UNORM
  TriangleStream         // 3×u16 进 u32[2]（现有格式）
  MaterialStream         // 材质/对象索引
  ClusterBVH[]           // 资产级局部空间 BVH（实例级 BVH 运行时建）
  PageTable[]            // 页：offset/size/streamType/firstCluster/clusterCount
  FallbackMesh           // 低模（IA 回退 / RT 代理）
```

### 3.2 版本与缓存

- `version`：格式主版本，任何布局变更 +1；
- `settingsHash`：构建参数（簇大小、量化位数、页大小、简化阈值）的哈希，参数变更自动失效；
- `sourceHash`：glTF + 引用的 bin 内容哈希，源变更自动失效；
- 页表先写入但 P3 之前运行时全量驻留（页表只用于后续流式）。

## 4. 离线工具 `Tools/MeshPreprocess`

### 4.1 组成

```
Tools/MeshPreprocess/
  main.cpp          # CLI：读 glTF → NaniteBuild → 写 .hnm；--stats/--verbose
  CmakeLists.txt    # 链 NaniteBuild + meshoptimizer（+ 可选 glTF 读取）
```

### 4.2 参数

```
MeshPreprocess <in.gltf> <out.hnm>
  --cluster-triangles=128 --cluster-vertices=255
  --cone-weight=0.5
  --position-bits=16 --normal-bits=20   # 八面体 10+10
  --page-bytes=131072
  --simplify-ratio=0.5 --simplify-lock-border=1
  --fallback-ratio=0.02
```

### 4.3 构建步骤（与 `NaniteBuild` 对应）

1. 读 glTF primitive（顶点位置/法线/UV/索引、材质）；
2. 三角形列表校验（非列表需展开）、`baseVertex` 预加、按空间局部性重排；
3. `BuildNaniteClusters()`（meshopt_buildMeshlets + optimizeMeshlet + computeMeshletBounds）；
4. `BuildNaniteClusterDAG()`（简化 + 层级 + 误差）；
5. `PackNaniteClusters()`（量化 + 打包）；
6. `BuildNaniteClusterBVH()`（资产局部空间）；
7. 切页 + 写页表 + 写 fallback 网格；
8. 写容器，打印统计（簇数/DAG 节点数/三角形数/字节数/页数）。

## 5. 运行时改造

### 5.1 `NaniteBuild` 抽库

- 新文件 `Engine/Render/Nanite/NaniteBuild.{h,cpp}`：把 `BuildNaniteClusters` / `BuildNaniteClusterDAG` / `PackNaniteClusters` / `BuildNaniteAssetFromGeometry` / `BuildNaniteClusterBVH` 原样移入；
- `NaniteUpload.{h,cpp}` 只保留生命周期桩 + `.hnm` 读取 + GPU 上传；
- `Tests/TestNaniteBuilder.cpp` 改为链 `NaniteBuild`（保持 RHI-free）；
- CMake：`add_library(HugEngineNaniteBuild STATIC ...)`，`HugEngineRender` 与工具都链它。

### 5.2 资产加载

- 新 `NaniteAssetLoader`：读 `.hnm` → 校验 version/hash → 填充现有 `NaniteAsset` 字节镜像 → 走 `NaniteRenderer` 现有上传路径；
- 开关：`HE_NANITE_OFFLINE=1`（默认优先离线资产）；文件缺失/校验失败 → 打警告 + 回退 `BuildNaniteAssetFromGeometry`。

### 5.3 构建期集成

- CMake `ProcessMeshes` 目标（类似 `CompileShaders`）：扫描 `Content/gltf`，按 `sourceHash+settingsHash` 增量生成 `Content/Processed/*.hnm`；
- 输出目录 gitignore；失败不阻塞构建（运行时回退）。

### 5.4 全 MS 接线

| 阶段 | 内容 |
|---|---|
| MS-1 | `NaniteRenderer` 接管 deferred 的几何写入（`r.Nanite.Enable=1`），GBuffer 的 IA 路径不再参与 |
| MS-2 | 阴影/深度 pass 增加 MS 变体：读同一簇数据，按光源 dispatch（CSM 每级、点光每面） |
| MS-3 | 有 Nanite 资产且设备支持 MS 时，不再创建 GBuffer 的 IA PSO；无资产/无 MS 设备回退 |

## 8. 风险与开放问题

| 风险 | 对策 |
|---|---|
| `.hnm` 格式频繁变动 | 版本号 + `settingsHash`，旧文件自动失效；格式集中在 `NaniteAssetFile.h` |
| glTF 读取重复实现 | 复用 `Engine/Asset/glTFLoader` 的解析（工具链 Asset 库），或抽最小读取器 |
| 程序化/动态网格 | 保留运行时构建回退；编辑器保存/导入时构建 |
| 单测依赖 | 测试链接 `NaniteBuild`，保持 RHI-free |
| MS 输出上限 | 簇大小按 `maxMeshOutputVertices/Primitives` 配置，默认 128 tri / 255 vert |
| 现有分页与新页表重复 | 复用 `NaniteStream` 的页池/反馈，只对接 `.hnm` 页表 |
| 资产体积 | 量化已压缩；后续可加 zstd/lz4（P5 之后） |

**开放问题**

1. `.hnm` 是随资产提交，还是构建期生成并缓存？（建议：构建期生成、不入库，与 shader 一致）
2. 工具是否支持多网格/多材质合批（一个 glTF 多个 primitive）？建议按 primitive 生成、运行时合并。
3. 阴影 MS 变体是复用主光栅的簇数据，还是按光源重新剔除？（建议：复用可见簇 + 每光源单独视锥剔除）
4. 是否需要 task/amplification shader 做簇剔除？（建议：先不做，compute 剔除已够）

## 9. 与 UE5 Nanite 的对应关系

| UE5 | 本方案 |
|---|---|
| `NaniteBuilder`（构建期 DDC） | `Tools/MeshPreprocess` + `Content/Processed` 缓存 |
| 簇切分（128 tri） | `NaniteBuild::BuildNaniteClusters`（现有算法） |
| 量化/多流 | `PackNaniteClusters`（现有格式） |
| Cluster DAG / 连续 LOD | `BuildNaniteClusterDAG`（现有算法，已实现） |
| 页与流式 | `NaniteStream`（已存在）+ `.hnm` 页表对接 |
| 硬件光栅（MS）+ 软光栅 | `NaniteRaster`（已存在），本方案补全 pass 覆盖 |
| 运行时层级遍历/剔除 | `NaniteCull`（已存在） |
