# 05.LLMScene 示例功能与实现细节

> 基于 `Samples/05.LLMScene/05.LLMScene.cpp` 与 `Engine/AI` 模块实际代码的分析（只读，未修改任何文件）。

## 一、功能定位

`05.LLMScene` 是 HugEngine 的第 5 个示例：**用一句话 prompt 让 DeepSeek 大模型生成一个 3D 场景，引擎把它翻译成真实的 Entity/Component 并渲染出来**。它是 `Engine/AI` 模块（LLM 场景生成 MVP）的端到端冒烟演示，也是整个引擎里第一个接入大模型的程序。

```bash
05.LLMScene.exe "一个黄昏下的中世纪村庄"
```

## 二、前置条件与运行流程

1. **设置环境变量** `DEEPSEEK_API_KEY`（密钥不硬编码，未设置则打印提示退出，返回码 -1）；
2. **命令行参数作为 prompt**（缺省用内置默认：`"一个黄昏下的中世纪村庄，几间石屋、一口井和一盏温暖的篝火"`）；
3. 启动引擎 → 调用 LLM 生成场景 JSON → 构建 ECS 世界 → 用 **ForwardPipeline（非 RenderGraph 模式）** 渲染；
4. 窗口叠加 ImGui 面板显示 FPS / 实体数 / 当前 prompt；WASD + 右键拖拽 + 滚轮自由相机观察。

## 三、代码结构（`Samples/05.LLMScene/05.LLMScene.cpp`，247 行）

### 1. 中文参数防乱码（第 40-62 行）
Windows 下 `main` 的 `argv` 由 CRT 按系统 ANSI 代码页（中文系统为 GBK 936）转换，直接用中文 prompt 会乱码。解决：用 `CommandLineToArgvW` 取回 UTF-16 参数 → `WideCharToMultiByte(CP_UTF8,...)` 转成 UTF-8，与工程 `/utf-8` 编译约定对齐；同时 `SetConsoleOutputCP(CP_UTF8)` 修正控制台输出代码页。

### 2. 引擎与 RHI 初始化（第 85-107 行）
标准样板：`Engine` 引导 → `rhi::CreateDevice(Vulkan)` → `CreateSwapChain`（1280×720、vsync、非 HDR）。

### 3. ★ 核心：LLM 生成场景（第 109-129 行）
```cpp
he::ai::DeepSeekClient llm{String(key)};                    // OpenAI 兼容客户端
result = he::ai::PromptToScene(llm, world, sceneGraph, prompt);  // 端到端胶水
```
- 整体 try/catch 兜底：任何异常打印 `HE_CORE_ERROR` 后退出，不崩溃；
- 失败时 `result.error` 给出原因（JSON 解析失败 / 缺 choices / 缺 content 等）。

### 4. 渲染（第 131-239 行）
- `ForwardPipeline`：关闭 RenderGraph 与多线程录制、关闭 GPU/视锥剔除（LLM 场景规模小）；
- 每帧：ShadowSystem（含 `he::SyncPhysicalSkyToSun(world)` 物理天空太阳同步）→ `pipeline.Render` → ToneMap Pass → ImGui 叠加（FPS/实体数/prompt）→ Submit + Present；
- 窗口 resize 回调同步 SwapChain、管线与相机宽高比。

## 四、端到端数据流（AI 模块链路）

```
用户 prompt
  │
  ▼
PromptToScene（Engine/AI/PromptToScene.cpp）
  │  1) 拼接 system prompt：角色设定 + JSON 格式模板
  │     + BuildTypeSchema()（可用组件"词汇表"）+ 规则
  │     （"只使用上述类型/字段，不要发明新类型；至少一个光源和一个地面；只输出 JSON"）
  │  2) 调 ILLMClient::Chat
  ▼
DeepSeekClient（Engine/AI/DeepSeekClient.cpp）
  │  WinHTTP → POST https://api.deepseek.com/chat/completions
  │  请求体：model=deepseek-chat, messages=[system,user],
  │          response_format={"type":"json_object"}（强制合法 JSON）,
  │          stream=false, temperature=0.2（低温度，生成稳定）
  │  响应：OpenAI 兼容格式 choices[0].message.content
  ▼
PromptToScene 解析出场景 JSON 文本（非法响应即失败返回）
  │
  ▼
SceneBuilder::BuildScene（Engine/AI/SceneBuilder.cpp）
  │  JSON → 真实 ECS：逐实体 CreateEntity + TransformComponent
  │  按 components[].type 创建：Cube / Sphere / DirectionalLight /
  │  PointLight / PhysicalSky（含材质参数 baseColor/metallic/roughness）
  │  挂到 SceneGraph 根节点（与 glTF 导入器一致）
  ▼
ForwardPipeline 渲染 → 窗口显示 LLM 生成的场景
```

## 五、关键实现细节

| 细节 | 实现 |
|------|------|
| **LLM 客户端接口** | `ILLMClient`（`LLMClient.h`）只抽象"对话"一个动作，返回原始 HTTP 响应 JSON，便于测试用 FakeLLM 替换（`TestPromptToScene.cpp`） |
| **网络层** | WinHTTP（Windows 内置，`#pragma comment(lib, "winhttp.lib")`），HTTPS 直连 `api.deepseek.com`，UTF-8→宽字符转换后走 Bearer 鉴权 |
| **容错（LLM 输出不可靠）** | `SceneBuilder` 所有字段读取做类型检查（`is_number/is_array/is_string`），缺省/非法用默认值降级；未知组件类型跳过并告警；非法 JSON 直接失败不产生半成品实体 |
| **防崩溃** | DeepSeekClient 网络调用整体 try/catch；05 主程序再包一层，双保险 |
| **几何重建** | 立方体/球体参数（halfExtent/radius）在赋值后手动调 `OnCreate()` 重建网格缓冲 |
| **无设备可测** | `MeshComponent::SetMeshData` 无 RHI 设备时跳过几何创建，因此 SceneBuilder/WorldModel 可脱离 GPU 单测 |

## 六、构建与依赖

`05.LLMScene/CMakeLists.txt` 链接 `HugEngineCore/RHI/Shader/Scene/Render/Editor/AI + stb`，并 `add_dependencies(CompileShaders)` 保证嵌入式着色器头先于编译生成；`Samples/CMakeLists.txt` 注册了 `05.LLMScene` 子目录（顺序在 04 之后、Editor 之前）。

## 七、配套测试

同批落地了 6 组 doctest 单元测试（`Tests/`）：`TestSceneBuilder`（合法/非法/未知类型 JSON）、`TestPromptToScene`（FakeLLM 端到端）、`TestDeepSeekProtocol`（请求体含 model 与 json_object）、`TestWorldModel`（反射快照/词表）、`TestInferenceScheduler`、`TestAIModule`——其中 `TestPromptToScene` 用假 LLM 验证"一个球"→ Sphere 组件 + 位置断言，与 05 的在线流程共用同一接口。

## 八、定位与局限

- **定位**：AI 模块"最小竖切"的演示——整个链路（prompt→LLM→JSON→ECS→渲染）一次打通，验证了"AI 与渲染共享同一个反射类型化 World"的架构方向；
- **局限**：`SceneBuilder` 目前是硬编码组件映射（仅 5 种程序化组件），不走反射注册表；无撤销（`he::Command` 未接入）；非流式（`stream=false` 阻塞等待）；无编辑器面板。这些正是 `docs/AI相关/7.HugEngine LLM创建场景实现计划.md` 结尾标注的后续演进项（SceneBuilder 泛型化到 `ClassInfo::factory` + AIGC 平台）。
