## 1. 结论速览

| 维度 | 现状 |
|---|---|
| 资产模块的规模 | `Engine/Asset` 只有 **一个加载器**：`glTFLoader.h` + `glTFLoader.cpp`（`Engine/Asset/CMakeLists.txt:4-7`） |
| 解析后端 | cgltf **1.14**（`cgltf.h:1-4`），以单头文件方式仅在加载器这一个翻译单元展开（`glTFLoader.cpp:21-22`；包含路径见 `Engine/Asset/CMakeLists.txt:18`） |
| 支持格式 | `.glb`（二进制）与 `.gltf`（JSON + 外部 `.bin`/base64），由 `cgltf_parse_file` 自动识别（`glTFLoader.cpp:439`、`glTFLoader.cpp:436-437` 零初始化 `cgltf_options`） |
| 公开入口 | 只有一个函数：`asset::LoadGLTF(World&, SceneGraph&, const String&) → glTFResult`（`glTFLoader.h:49`） |
| 图元范围 | **仅三角形**（`cgltf_primitive_type_triangles`），其余类型告警后丢弃（`glTFLoader.cpp:269-272`） |
| 顶点属性（静态路径） | POSITION / NORMAL / TEXCOORD 三种；TANGENT、COLOR 明确不处理（`glTFLoader.cpp:275-290`、注释在 `:288`） |
| 静态顶点布局 | `StaticVertex { float3 position; float3 normal; float2 uv; }` = 32 B（`MeshComponent.h:19-23`） |
| 资产→实体映射 | 每个节点 → 一个 `Entity` + `TransformComponent`；每个 primitive → 一个**子** `Entity` + `MeshComponent`（`glTFLoader.cpp:394-407`、`:414-417`、`:298-303`） |
| 坐标系/单位 | 加载器**不做任何轴交换或单位换算**，顶点/TRS/矩阵原样拷贝（`glTFLoader.cpp:55-83`、`:336-344`）；引擎自身约定 Y-up + 米制（`Engine/Physics/Physics/JoltConversions.h:6`） |
| 材质 | glTF metallic-roughness 全套 + alphaMode/doubleSided/unlit + `KHR_materials_ior / clearcoat / specular / sheen / anisotropy / transmission / volume`（`glTFLoader.cpp:89-223`） |
| 纹理 | 加载器**只存 `image->uri` 字符串**（`glTFLoader.cpp:104-110` 等 5 处）；解码/上传/bindless 登记全部由各 Sample 自己做（`03.Sponza-Forward.cpp:341-412`） |
| 骨骼 | **支持**：`skins` → `SkeletonAsset`（关节层级 + 逆绑定矩阵 + 静态 TRS + 蒙皮顶点）（`glTFLoader.cpp:559-744`、`SkeletonAsset.h:107-113`） |
| 动画 | **支持两套并行**：节点级 `AnimationComponent`（TRS 关键帧驱动 `TransformComponent`，`glTFLoader.cpp:483-556`）+ 关节级 `AnimationClip`（`glTFLoader.cpp:682-735`）；morph/weights 通道不支持（`:728-729`） |
| 蒙皮节点 | 引用 `skin` 的节点**不建静态网格**（`glTFLoader.cpp:413`），改由 `SkeletonAsset` 承载、`SkeletalMeshComponent` 渲染 |
| 到 GPU | `MeshComponent::SetMeshData` 直接建 VB/IB（`MeshComponent.cpp:32-45`）；`MeshBatcher` 再做**第二次**合并（`MeshBatcher.cpp:18-139`） |
| 合批排除项 | `indexCount==0` 的网格（`MeshBatcher.cpp:30-32`）、`SkeletalMeshComponent`（`MeshBatcher.cpp:113-114`） |
| **最值得注意的三处事实** | ① 静态路径**不生成**缺失的索引缓冲 ⇒ 非索引 glTF 图元在合批与 GPUScene 里都被整条丢弃（`glTFLoader.cpp:349-357` + `MeshBatcher.cpp:30-32` + `GPUScene.cpp:58`）；② 纹理只认 `uri`，GLB 内嵌图像（bufferView）拿不到路径（`glTFLoader.cpp:107` 等）；③ 贴图一律 `RGBA8_UNORM`，无 sRGB 解码（`03.Sponza-Forward.cpp:355`、格式枚举另有 `Format::RGBA8_SRGB` 见 `Engine/RHI/RHI/Types.h:114`） |

## 3. glTF 加载器实现

### 3.1 入口与错误处理

| 阶段 | 行为 | 代码位置 |
|---|---|---|
| 解析文件 | `cgltf_parse_file(&options, path, &data)`；`options` 是全零结构体（不注册任何自定义 IO / 扩展处理器） | `glTFLoader.cpp:436-439` |
| 解析失败 | `result.error = "cgltf 解析失败: " + 可读错误 + " (" + 路径 + ")"`，记 `HE_CORE_ERROR`，直接返回（`success` 保持 `false`，`entities`/`skeletons` 均为空） | `glTFLoader.cpp:440-445` |
| 错误码翻译 | `CgltfResultToString` 覆盖 10 个 `cgltf_result` 取值，含 `cgltf_result_legacy_gltf → "旧版 glTF 1.0（不支持）"` | `glTFLoader.cpp:32-46` |
| 加载缓冲区 | `cgltf_load_buffers` 失败 → 同样早退，并先 `cgltf_free(data)`（无泄漏） | `glTFLoader.cpp:448-454` |
| 选场景 | 优先 `data->scene`，为空则取 `data->scenes[0]`；两者都没有 → 错误 `"glTF 文件中没有场景"` | `glTFLoader.cpp:457-467` |
| 遍历根节点 | `for (i < scene->nodes_count) ProcessNode(scene->nodes[i], kInvalidEntity, ...)` | `glTFLoader.cpp:476-480` |
| 成功标志 | 走到最后**无条件** `result.success = true`（`result.entities` 为空也算成功） | `glTFLoader.cpp:749` |
| 清理 | `cgltf_free(data)`：所有 CPU 数据在返回前已拷进 `MeshComponent` / `SkeletonAsset` | `glTFLoader.cpp:747` |

返回结构：`glTFResult { TArray<Entity> entities; usize meshCount; bool success; String error; std::vector<std::shared_ptr<SkeletonAsset>> skeletons; }`（`glTFLoader.h:30-37`）。`meshCount` 的语义是**primitive 数量**（每次 `LoadPrimitive` 成功末尾 `++result.meshCount`，`glTFLoader.cpp:375`），不是 glTF 的 `meshes_count`。

### 3.2 节点与变换

- 实体命名：`node->name`，缺名则 `"glTF_Node"`（`glTFLoader.cpp:394-396`）。
- 每个节点都挂 `TransformComponent`，父节点有效时 `sceneGraph.SetParent`（`glTFLoader.cpp:399-405`）。
- 变换来源优先级（`ApplyNodeTransform`，`glTFLoader.cpp:55-83`）：
  - `node->has_matrix` → `glm::make_mat4(node->matrix)`（列主序，与 `glm::mat4` 内存布局一致）后用 `glm::decompose` 拆成 TRS，skew/perspective 被丢弃（`:58-63`）；
  - 否则读独立的 `translation / rotation / scale` 字段（`:64-82`）。
- 四元数顺序：cgltf 按 glTF 规范存 `{x,y,z,w}`，写入 GLM 时显式重排为 `quat(w,x,y,z)`（`glTFLoader.cpp:71-75`，注释在 `:53-54`）。**递归处理子节点**用同一 `ProcessNode`（`:421-424`）。
- `nodeEntityMap`（`unordered_map<const cgltf_node*, Entity>`）建立节点指针 → 实体的映射，注释标明"供未来蒙皮/动画等扩展使用"，**当前只被动画阶段读取**（`glTFLoader.cpp:408`、`:497-499`）。

### 3.3 网格与图元（静态路径）

`LoadPrimitive`（`glTFLoader.cpp:261-376`）逐步骤：

1. **类型过滤**：仅 `cgltf_primitive_type_triangles`，否则 `HE_CORE_WARN("跳过非三角形图元 …")` 后返回（`:269-272`）。
2. **属性定位**：遍历 `prim.attributes`，只挑 `position / normal / texcoord` 三类，其余（含 TANGENT/COLOR/JOINTS/WEIGHTS）落进 `default: break`（`:275-290`，注释 `:288`）。注意三个指针的赋值是**无条件覆盖**的：同一 primitive 若同时声明 `TEXCOORD_0` 与 `TEXCOORD_1`，最终生效的是在数组里更靠后的那个（`:279-290` 的循环体无 break）。
3. **缺 POSITION 直接跳过**：`HasAttribute(posAttr)` 要求 `attr && attr->data && attr->data->count > 0`（`:226-228`、`:292-295`）。
4. **建实体**：名字 `"Prim_" + std::to_string(result.meshCount)`，挂默认 `TransformComponent`，父级 = 该 mesh 所在节点实体（`:298-303`）。
5. **位置**：`cgltf_accessor_unpack_floats`，分量数取 `cgltf_num_components(accessor->type)`（`:306-308`）。该函数族自动处理组件类型、normalized、byteStride、sparse（注释 `:252-258`）。
6. **法线（可选）**：同样 unpack；随后组装顶点时**固定按 3 分量索引**（`normalFloats[i*3]`，`:339-341`）。
7. **UV（可选）**：分量数存进 `uvComps`，`hasUV = (unpacked > 0)`——unpack 返回 0 时即使属性存在也走默认值（`:320-329`）。
8. **顶点组装**：`StaticVertex` 逐字段填充；缺法线用 `(0, 1, 0)`"默认朝上"，缺 UV 用 `(0, 0)`（`:332-346`）。
9. **索引（可选）**：先以 `nullptr` 调 `cgltf_accessor_unpack_indices` 查询数量，再按 `u32` 解包（`:349-357`）。**无索引时不生成任何顺序索引**。
10. **建组件**：`world.AddComponent<MeshComponent>` → `SetMeshData(vertices, indices)`；`prim.material` 非空才 `ApplyMaterial`（`:360-368`）。
11. 日志：`Primitive[i]: N vertices, M indices, hasNormal=..., hasUV=...`（`:371-373`）。

**多 primitive / 多材质**：不做任何拆分或合并——一个 primitive 对应一个实体和一个 `MeshComponent`（`:414-417`），所以"一个网格多种材质"天然被表达成多个兄弟实体，各自带自己的 `MeshComponent` PBR 字段。材质为空时 `MeshComponent` 的默认值生效（`MeshComponent.h:45-54`：baseColor `(1,1,1,1)`、metallic `0.0`、roughness `0.8`、alphaCutoff `0.5`）。

### 3.4 节点级动画（→ `AnimationComponent`）

对 `data->animations` 每段动画（`glTFLoader.cpp:483-556`）：

- 按**目标节点**分组：`nodeAnimMap[targetNode]`（`:488`）；
- 首次遇到某目标节点时 `AddComponent<AnimationComponent>` 并压入一个 clip，名字取 `anim.name` 或 `"Anim_<下标>"`，`looping = true`（`:501-514`）；
- `++animCount` 是"**clip 创建次数**"语义，日志文案为"加载 N 个动画, M 个被驱动节点"（`:513`、`:554-556`）；
- 关键帧读取：`sampler.input->count` 个时间戳（`cgltf_accessor_read_float` 逐个读，`:518-522`），再按 `target_path` 分派到 `AddTranslationKey / AddRotationKey / AddScaleKey`（`:524-543`）；旋转同样做 `{x,y,z,w} → quat(w,x,y,z)` 重排（`:534-535`）；
- 所有 channel 处理完后对每个新组件 `FinalizeClip()` 并 `playing = true`（`:546-552`）。
- `channel.sampler` 被直接解引用（`*channel.sampler`，`:492`），无空判断。
- 该阶段**不看 skin**：任何被动画的节点（包括关节节点）都会拿到 `AnimationComponent`。

### 3.5 蒙皮（→ `SkeletonAsset`）

对 `data->skins` 每个 skin（`glTFLoader.cpp:559-744`）：

- 资产名 = `skin.name` 或 `"Skin_<下标>"`（`:562-564`）。
- **关节**（`:567-588`）：name 取 `jn->name` 或 `"Joint_<下标>"`；父关节通过**在 `skin.joints` 里按指针查找**得到下标（找不到 / 无父 → `-1`，`:573-578`）——不使用 `skin.skeleton`（公共根）字段；静态 TRS 来自 `ExtractNodeTRS`（`:579`）；逆绑定矩阵用 `cgltf_accessor_read_float(…, 16)` 读成 `glm::make_mat4`，无 `inverse_bind_matrices` 时置单位阵（`:580-586`）。
- `ExtractNodeTRS`（`:232-249`）与 `ApplyNodeTransform` 不同：matrix 节点走"列长 = 缩放 / 归一化列 `quat_cast` = 旋转 / 第 4 列 = 平移"的简单分解，**注释明确说明忽略剪切**（`:230-231`、`:233-242`）。
- **蒙皮网格**（`:590-679`）：遍历 `data->nodes` 找 `n->skin == &skin && n->mesh` 的节点（`:591-593`），其 mesh 的**全部** primitive 顺序追加进同一份 `SkeletonAsset`：
  - 需要 POSITION + JOINTS_0 + WEIGHTS_0，缺任一则告警跳过（`:599-624`）；同样只处理三角形（`:597`）；
  - `baseVertex = skel->vertices.size()`（`:627`）；
  - 位置/法线/UV 分别按 `vc*3 / vc*3 / vc*2` unpack（法线/UV 缺省值同静态路径，`:629-636`）；
  - 权重按 `vc*4` unpack，关节索引用 `cgltf_accessor_read_uint(…, 4)` 逐顶点读（`:637-649`）；
  - `SkinnedVertex.joint[k] = min(joint, 255)`：关节索引被**夹到 u8 上限 255**（`:652`）；
  - 权重和 > `1e-6` 时逐分量归一化（`:650-657`）；
  - 索引跨 primitive 追加并加 `baseVertex` 偏移（`:662-670`）；**无索引时生成顺序索引 `baseVertex + i`**（`:671-676`）——这正是静态路径没有的兜底；
  - 每个 primitive 打一条 `[Skeleton] <名> primitive: N 蒙皮顶点`（`:677`）。
- **动画剪辑**（`:681-735`）：对每个 `data->animations` 新建 `AnimationClip`，只收**目标属于本 skin 关节**的 channel（关节下标在 `skin.joints` 里线性查找，找不到 `continue`，`:687-695`）；时间戳逐点读（`:698-705`）；translation / rotation / scale 三条路径分别填 `translations / rotations / scales`，**其他路径（weights/morph）直接 `continue`**（`:707-730`）；`clip.duration = max(duration, times.back())`（`:731`）；`channels` 为空则不收这段剪辑（`:734`）。
- 收尾：`joints` 非空才把资产 push 进 `result.skeletons` 并 `++skinCount`（`:737-744`），日志"加载 N 个蒙皮骨架"。

**注意**：同一个 glTF 的同一段动画数据会被解析**两次**——一次进节点级 `AnimationComponent`（3.4），一次进 `SkeletonAsset::clips`（本节）。

## 4. 顶点与索引约定

### 4.1 顶点布局

```cpp
// MeshComponent.h:19-23
struct StaticVertex {
    float3 position;
    float3 normal;
    float2 uv;
};
```

| 项 | 值 | 代码位置 |
|---|---|---|
| 静态顶点字段 | position / normal / uv | `MeshComponent.h:19-23` |
| 字节数 | $3\times4 + 3\times4 + 2\times4 = 32$ B（`sizeof(StaticVertex)` 由 RHI 描述直接使用） | `MeshComponent.cpp:33-36` |
| GPU 侧属性槽 | `location 0 = float3 inPosition`、`1 = float3 inNormal`、`2 = float2 inUV` | `PBR.vert.slang:7-9` |
| 蒙皮追加槽 | `location 3 = uint8_t4 inJoints`、`4 = float4 inWeights` | `PBR.vert.slang:10-12` |

蒙皮顶点是**另一套布局**，不走 `StaticVertex`：

```cpp
// SkeletonAsset.h:20-26
struct SkinnedVertex {
    float3 position;
    float3 normal;
    float2 uv;
    u8     joint[4];
    float  weight[4];
};
```

上传时以**原始字节**直接建缓冲，`stride = sizeof(asset::SkinnedVertex)`（`SkeletalMeshComponent.cpp:20-40`）。`u8 joint[4]` 与 shader 的 `uint8_t4 inJoints` 对应（`PBR.vert.slang:11`）。

### 4.2 坐标系与单位

- 加载器**没有任何**轴交换、手性翻转、单位缩放的代码：位置/法线/UV 逐分量直拷（`glTFLoader.cpp:336-344`），节点 TRS 逐字段直拷（`:64-82`），矩阵直接 `make_mat4`（`:60`、`:234`）。
- 引擎的坐标/单位约定在物理转换层被集中写明："Jolt 同为 Y-up 米制，与 glm（RH、Z 深度）一致"（`Engine/Physics/Physics/JoltConversions.h:6`）。加载器沿用同一约定，因此 glTF 数据**不需要**换算。
- 索引绕序同样不做调整：加载器原样拷贝索引（`glTFLoader.cpp:349-357`、`:662-670`）；引擎自身生成的几何按 CCW 正面写入（`SplineMeshComponent.cpp:59` 注释"绕序使法线朝上，与引擎 CCW 正面一致"）。

### 4.3 是否预变换

**不预变换**。`LoadPrimitive` 写入的顶点就是 accessor 原始坐标（`glTFLoader.cpp:336-338`），节点变换留在 `TransformComponent` 上（`:399-400`）。渲染侧按 `worldMatrix` 变换：

- 合批几何明确"**未施加任何变换**（与 GPUScene 的 per-object 变换配套）"（`MeshBatcher.h:85-87`）；
- `SceneRenderer::Prepare` 把 `e.worldMatrix` 写进 `GPUObjectData`（`SceneRenderer.cpp:127-129`），顶点着色器做 `mul(worldMatrix, float4(inPosition,1))`（`PBR.vert.slang:86-91`）。

后果：同一个 glTF 被加载两次会得到两套独立实体与独立缓冲；同一 mesh 被多个节点引用时也会**各自建一份**顶点数据（`glTFLoader.cpp:298-303`、`:414-417` 没有实例化共享）。

### 4.4 索引处理

| 情形 | 静态路径（`LoadPrimitive`） | 蒙皮路径（skin 循环） |
|---|---|---|
| 有 `prim.indices` | `unpack_indices` 成 `u32`（`:349-357`） | `unpack_indices` → 追加到 `skel->indices` 并 `+baseVertex`（`:662-670`） |
| 无 `prim.indices` | **不做任何处理** ⇒ `indices` 为空（`:349-357` 的 `if`） | **生成顺序索引** `baseVertex + i`（`:671-676`） |
| 结果索引类型 | 统一 `u32`（缓冲 `stride = sizeof(u32)`，`MeshComponent.cpp:40-45`） | 统一 `u32`（`SkeletalMeshComponent.cpp:42-48`） |

无索引静态网格的连锁后果（三处代码可核实）：`MeshComponent::SetMeshData` 把 `m_IndexCount = indices.size() = 0`（`MeshComponent.cpp:15-16`）→ `MeshBatcher::collect` 首行 `if (idxCount == 0 || vtxCount == 0) return;`（`MeshBatcher.cpp:30-32`）→ `GPUScene` 收集时同样 `if (comp.GetIndexCount()==0) return;`（`GPUScene.cpp:58`）。即：**这类图元不会被绘制，也不会进 GPUScene**。

### 4.5 多 primitive / 多材质

- 每个 primitive 一个实体：`ProcessNode` 对 `node->mesh->primitives[p]` 逐个调 `LoadPrimitive`（`glTFLoader.cpp:413-418`）。
- 每个 primitive 一个 `MeshComponent`，其 PBR 字段来自 `prim.material`，未设材质则保持组件默认值（`:360-368`、`MeshComponent.h:45-54`）。
- 命名不含材质名，只有 `"Prim_<meshCount>"` 计数器（`:299`），多 primitive 之间靠实体层级（同一父节点）区分。

### 5.2 纹理路径解析

- 加载器只把 `image->uri` 原文拷成字符串，条件链是"texture 非空 && texture->image 非空 && image->uri 非空且非空串"（`glTFLoader.cpp:104-110`，其余 4 处同构：`:113-119`、`:123-129`、`:132-138`、`:146-152`）。
- **相对路径的解析发生在 Sample 侧**：`(std::filesystem::path(gltfPath).parent_path() / uri)`（`03.Sponza-Forward.cpp:343`、`05.Sponza-PathTracing.cpp:398`），即"相对 glTF 文件所在目录"。
- 由于只认 `uri`，`image->buffer_view`（GLB 内嵌图像）路径**永远不会**被写入组件（`glTFLoader.cpp:107` 的条件里没有 buffer_view 分支）。
- 引擎内**没有**纹理资产模块：解码用 `stb_image`（`03.Sponza-Forward.cpp:46-47` 定义 `STB_IMAGE_IMPLEMENTATION`，`:347` 调 `stbi_load`），`Engine/Asset` 里没有任何解码/上传代码（`Engine/Asset/CMakeLists.txt:4-7`）。

### 5.3 bindless 登记时机与槽位约定

- **时机**：在管线初始化**之前**、加载 glTF **之后**，遍历 World 做一次性登记（`03.Sponza-Forward.cpp:398-413`；`05.Sponza-PathTracing.cpp:474-489`；`07.Nanite.cpp:449-462` 同构）。
- **默认占位纹理必须先设**：`SetDefaultTexture(tex, sampler)` 的注释写明"必须在注册材质纹理之前"（`Bindless.h:64-65`；实现见 `03.Sponza-Forward.cpp:378-396`）。`ForwardPipeline::Initialize` 自己也做一遍占位 + **预分配 materialID=0 的 4 个槽**（`ForwardPipeline.cpp:184-192`），保证无纹理网格有有效纹理。
- **每材质 4 个连续槽**：BaseColor / Normal / MetallicRoughness / Occlusion；**首次 `RegisterTexture` 的返回值即 `materialID`（基索引）**，shader 按 `texBase+0..3` 采样（`03.Sponza-Forward.cpp:404-411`）。
- **材质 SSBO 侧的索引换算**：`materialID` 是纹理基索引，元素索引 = `materialID >> 2`（`ForwardPipeline.cpp:644`、`:680-685`），并按 `materialID` 去重（`:647-649`）。
- **寄存器语义**：`RegisterTexture/Sampler/Buffer` 返回该类型数组内索引并自动标记待 flush；`Flush` 在帧边界把变更写进已登记的描述符集（`Bindless.h:34-37`、`:57-58`）。槽位回收是可选接口（`ReleaseTexture/Sampler/Buffer` + `BeginFrame`，`Bindless.h:39-49`），并注明"资源本身也要延迟同样帧数再销毁"。
- **emissive 没有槽位**：加载器解析了 `emissiveTexture`（`glTFLoader.cpp:146-152`），`SceneRenderer` 也把它拷进 `PBRMaterial`（`SceneRenderer.cpp:125`），但各 Sample 的登记代码一律只注册 4 张（bc / n / mr / ao，`03.Sponza-Forward.cpp:400-410`）⇒ **emissive 贴图不进 bindless 堆**。
- **缺失纹理的降级**：`loadTexture` 对空 URI 直接返回 `{nullptr,nullptr}`，加载失败告警后也返回 `{nullptr,nullptr}`（`03.Sponza-Forward.cpp:342`、`:348`）→ `RegisterTexture(nullptr, nullptr)` → 堆侧回退到默认占位纹理（`Bindless.h:64-65`）。另一个降级在 shader 侧：纹理存在性被压成 `textureMask` 位掩码（bit0=BaseColor / bit1=Normal / bit2=MetallicRough / bit3=Occlusion，`MeshBatcher.cpp:64-65` 注释 + `ComputeMaterialTextureMask`，`:83`），无纹理的槽不被采样，避免占位纹理污染（`SceneRenderer.cpp:120`、`ForwardPipeline.cpp:660`）。
- **RT/PT 的"有效材质"平均值**：光栅路径逐像素采样贴图，而 RT/PT 的 ClosestHit 只能按实例查因子，于是由**解码贴图的一方**（Sample）算出均值回填 `MeshComponent::baseColorAvg / metallicAvg / roughnessAvg / hasMaterialAvg`（字段与理由见 `MeshComponent.h:55-65`；计算见 `05.Sponza-PathTracing.cpp:408-440`、`:491-500`）。
- **纹理格式**：各 Sample 都用 `rhi::Format::RGBA8_UNORM`（`03.Sponza-Forward.cpp:355`、`04.Sponza-Deferred.cpp:377`、`05.Sponza-PathTracing.cpp:420`、`06.GILab.cpp:402`、`07.Nanite.cpp:405`），mip 级数按 $1 + \lfloor \log_2 \max(w,h) \rfloor$ 估算（`03.Sponza-Forward.cpp:350-352`），采样器 min/mag/mip 全 Linear、address Repeat、`maxLod = mipLevels`（`:364-370`）。RHI 里存在 `Format::RGBA8_SRGB`（`Engine/RHI/RHI/Types.h:114`），但资产路径没有用它 ⇒ 基础色/自发光贴图**没有做 sRGB→线性解码**。

### 6.2 资产 → 组件

- `glTFLoader` **不创建** `SkeletalMeshComponent`：结果通过 `glTFResult::skeletons` 交给调用方（`glTFLoader.h:36`、`glTFLoader.cpp:738`）。
- 调用方手工装配（`02.Cube.cpp:433-451`）：
  `skeletons[0]` → `AddComponent<SkeletalMeshComponent>` → `SetSkeleton(foxSkeleton)` → `PlayClip(1, true)` / `CrossFadeTo(2, 1.5f, true)`；材质因子随后由调用方在组件上直接改（`02.Cube.cpp:444-446`）。
- `SetSkeleton`（`SkeletalMeshComponent.cpp:14-53`）：保存 `shared_ptr`、重置 `currentClip = -1` / `clipTime = 0`、按关节数分配 `jointWorldMatrices`；顶点/索引为空时清零计数并返回（`:22-26`）；包围盒由绑定姿势顶点算出（纯 CPU，`:31-32`）；缓冲用 `BufferUsage::Vertex | AccelerationStruct` / `Index | AccelerationStruct`（`:36-48`，与静态网格一致，支持 BLAS 构建）。
- 播放控制：`PlayClip(clipIndex, loop)` 越界或 `-1` 一律降级为绑定姿势，并 `ClearBlendLayers()`（单剪辑与混合互斥，`SkeletalMeshComponent.cpp:55-66`）。

### 6.3 采样与蒙皮矩阵

- 采样器（`SkeletalMeshSystem.cpp:20-48`）：向量通道线性插值
  $$v(t) = \mathrm{mix}(v_i, v_{i+1}, k), \quad k = \frac{t - t_i}{\max(t_{i+1} - t_i,\ 10^{-9})}$$
  四元数通道 `glm::slerp` 后 `normalize`；越界取首/末帧；空通道返回调用方给的默认值（即关节静态 TRS，`SkeletalMeshSystem.h:27` 注释）。
- 层级合成（`ComposeSkinMatrices`，`SkeletalMeshSystem.cpp:63-110`）：逐关节采样 → `TRSToMatrix`（`T·R·S`，`:51-56`）→ 反复扫直到全部解析（`world[i][3].w != 0` 作已解析标记，兼容任意关节顺序）→ 孤儿关节（父环/父越界）回退为本地矩阵防死循环（`:96-100`）。
- 蒙皮矩阵 $M_i = W_i \cdot \mathrm{invBind}_i$（`SkeletalMeshSystem.cpp:102-105`）。
- 顶点着色器按权重混合 4 个矩阵（`PBR.vert.slang:76-84`）：
  $$M = \sum_{k} w_k \, B_{j_k}, \qquad world = obj.worldMatrix \cdot M$$
  即"局部空间累加 4 根骨骼的加权蒙皮矩阵，再乘实体世界矩阵"（该处注释说明 glTF 骨骼定义在网格节点局部空间，`PBR.vert.slang:77-78`），与 `SkeletonAsset.h:32` 注释的公式一致。
- 顶点权重在加载时已归一化（`glTFLoader.cpp:650-657`）。

### 6.4 剪辑混合

- 层上限 `kMaxBlendLayers = 4`（`SkeletalMeshComponent.h:30`）。
- `SetBlendLayers` 截断到上限、把未用层清空、重置交叉淡入状态（`SkeletalMeshComponent.cpp:98-112`）；`SetBlendLayer` 对越界层/越界剪辑**拒绝且不改状态**（`:114-131`）。
- `CrossFadeTo(toClip, duration, loop)`：出层 = 第 0 层（无层时用单剪辑状态合成），入层 `weight = 0 → 1`、`time = 0`；`duration ≤ 0` 时直接就位（`SkeletalMeshComponent.cpp:141-178`）。
- 混合规则（`SkeletalMeshSystem.cpp:112-118` 注释 + `:119-160` 实现）：平移/缩放线性加权后按 $\sum w$ 归一化；旋转"符号对齐到首个参与层 → 加权求和 → 归一化"（加权 nlerp，避免 $q$ 与 $-q$ 相互抵消）；`clipIndex < 0`、权重 ≤ 0、剪辑越界的层**不参与**；**全部层都不参与 ⇒ 退回关节静态 TRS（绑定姿势）**。
- 归一化权重可查询：`GetBlendWeights`（`SkeletalMeshComponent.cpp:180-192`）。
- 驱动：`SkeletalMeshSystem::Update(world, dt)` 每帧推进时间（`fmod` 循环 / 播完停在末帧并 `playing = false`）、计算蒙皮矩阵、置 `bBonesDirty`（`SkeletalMeshSystem.cpp:372-467`）。该函数**由调用方每帧调用**（`02.Cube.cpp:1076`），管线内部不自动 tick。

### 6.5 重定向（`RetargetProfile`）

- 构建（`SkeletalMeshSystem.cpp:232-251`）：按**关节名字**匹配（`targetToSource[i] = 第一个同名源关节`），名字为空/对不上 → `-1`（保持目标绑定姿势）；注释说明"索引在不同骨架之间没有任何对应关系"。
- 采样（`:253-306`），三段：
  1. 旋转：只借源相对自己绑定姿势的偏移，再叠到目标绑定姿势上
     $$R_{out} = \mathrm{normalize}\!\left(R^{bind}_{t} \cdot \mathrm{normalize}\!\left(\overline{R^{bind}_{s}} \cdot R^{anim}_{s}\right)\right)$$
     （`:284-285`；源无旋转通道时偏移退化为单位四元数，结果即目标绑定姿势，注释 `:283`）
  2. 平移（`retargetTranslation` 打开时）：$t_{out} = t^{bind}_{t} + (t^{anim}_{s} - t^{bind}_{s}) \cdot k$，其中 `autoProportion` 时 $k = \mathrm{translationScale} \cdot |t^{bind}_{t}| / |t^{bind}_{s}|$（源长度 ≈ 0 时取 1）（`:289-297`）
  3. 缩放（`retargetScale` 打开时）：$s_{out} = s^{bind}_{t} \cdot (s^{anim}_{s} / s^{bind}_{s})$，逐分量相除、源分量接近 0 时整轴取 1（`:300-305`）
- 未映射/越界的目标关节 ⇒ 返回目标静态 TRS，不崩溃（`:258-273`）。
- 层级合成与 `inverseBind` **始终用目标骨架**（注释 `:314`；`ComputeSkinMatricesRetargeted` `:308-320`）。
- 组件侧装配：`SetAnimationSource(source, profile)`；`profile == nullptr` 时按名字自动构建；设置后 `currentClip / clipTime / blendLayers[].clipIndex` 一律指向**源骨架**的剪辑表（`SkeletalMeshComponent.cpp:70-89`、`SkeletalMeshComponent.h:52-64`）。
- 用法示例（含程序化改绑定姿势后重算逆绑定矩阵）：`02.Cube.cpp:457-486`（`tallSkeleton` 平移 ×1.5 → `RebuildInverseBindMatrices` → `SetAnimationSource(foxSkeleton)` → `PlayClip(1)`）。
- `RebuildInverseBindMatrices`：用绑定姿势跑一次层级合成，取世界矩阵的逆（`SkeletalMeshSystem.cpp:357-370`）；头文件注释说明"否则蒙皮矩阵 ≠ 单位，连绑定姿势都会变形/炸开"（`SkeletalMeshSystem.h:98-101`）。

### 6.6 骨骼矩阵上传

`ForwardPipeline.cpp:1195-1254`：

- 每帧遍历 `SkeletalMeshComponent`：条件为 `skeleton && GetIndexCount() > 0 && !boneMatrices.empty()`（`:1202`）；
- 容量够 → `Map` 原地覆盖（句柄不变）；容量不够 → 重建 + `ReleaseBuffer(旧句柄)` + `RetireBoneBuffer()`（N 帧延迟释放），再 `RegisterBuffer` 拿新句柄（`:1204-1220`；`SkeletalMeshComponent.h:86-105` 的字段与 `FrameRetireQueue`）；

## 7. 从资产到渲染

### 7.1 组件→缓冲（第一次上传）

`MeshComponent::SetMeshData`（`MeshComponent.cpp:11-51`）：

1. 记录 `m_VertexCount` / `m_IndexCount`（`:15-16`）；
2. **纯 CPU** 算 AABB（"视锥剔除在无设备场景下也可用"，`:18-22`）——单元测试因此不依赖 RHI（`Tests/TestSceneBuilder.cpp:5`、`Tests/TestSplineMesh.cpp:5` 都写明这一点）；
3. 无 RHI 设备时打印错误并返回（计数与包围盒仍然有效，`:25-29`）；
4. 建 VB：`usage = Vertex | AccelerationStruct`、`stride = sizeof(StaticVertex)`、`initialData = vertices.data()`（`:32-37`）；
5. 建 IB：`usage = Index | AccelerationStruct`、`stride = sizeof(u32)`（`:40-45`）；
6. 日志含顶点数、索引数与包围盒 min/max（`:47-50`）。

### 7.2 合批（第二次上传）

`MeshBatcher::Build`（`MeshBatcher.cpp:18-139`）：

- 清空 5 个输出容器（顶点、索引、命令、DGC token、材质快照）后，用同一个 `collect` lambda 依次遍历组件类型（`:103-114`）：
  `MeshComponent → CubeComponent → SphereComponent → BillboardComponent → TextRenderComponent → (可选) DecalComponent → InstancedMeshComponent`，注释写明"追加在最后（与 `GPUScene::Collect` 的枚举顺序一致，保证 objectIndex 对齐）"（`:106`）。
- `collect` 把原 VB/IB `Map()` 出来拷进 CPU 侧的合并数组，索引统一加 `baseVertex` 偏移（`:40-57`），随后压入一条 `IndirectDrawCommand{indexCount, 1, baseIndex, (i32)baseVertex, 0}`（`:60`）。
- 同一次调用里产出 `MergedMeshMaterial` 材质快照（因子直取组件字段 + 纹理掩码 + `bindlessTextureBase = materialID`），注释强调"与 `GetDrawCommands()` **同序、同长**"、"只增不改"（`:62-86`、`MeshBatcher.h:40-63`）。
- DGC 模式额外产出 `DGCDrawToken`，`objectIndex = m_DGCTokens.size()`（即按 Build 顺序递增，`:88-97`；结构 `alignas(16)`，`MeshBatcher.h:31-38`）。
- 排除项：`indexCount==0`（`:30-32`）、`SkeletalMeshComponent`（`:113-114`，注释"顶点布局不同（SkinnedVertex），不适合合批——蒙皮 Pass 单独绘制"）。
- 合并结果建成单个 VB/IB（`usage = Vertex` / `Index`，**不带 AccelerationStruct**，`:119-132`），并打印 meshes/verts/indices 与 KB 数（`:134-137`）。
- `FillGPUScene` 只回填 `indexCount / firstIndex / vertexOffset` 三个字段（`:141-149`；`GPUScene.cpp:46-49` 注释"由 MeshBatcher 填充"）。
- 触发条件："GPU 模式要靠它填 IndirectDraw 参数；否则也要 Build 供 Lumen 的 SDF / Nanite 的资产使用"（`Engine/Render/Pipeline/DeferredPipeline_FrameGraph.cpp:103-115`；Forward 侧 `ForwardPipeline.cpp:1028`）。

### 7.3 材质与物体数据

- `SceneRenderer::Prepare`：`GetDefaultMaterial()` 起手，把 `MeshComponent` 的 `baseColorFactor / emissiveFactor / metallicFactor / roughnessFactor / aoFactor / alphaCutoff / alphaMode / doubleSided / unlit` 与 5 条纹理路径拷进 `PBRMaterial`，`FillObjectData` 摊平进 `GPUObjectData`，再补 `materialID` 与世界 AABB（`SceneRenderer.cpp:105-141`）。**注意**：`MeshComponent` 的 Disney 扩展字段（`ior/anisotropic/subsurface/specular/specularTint/sheen/clearcoat/clearcoatGloss/transmission/attenuation*`，`MeshComponent.h:68-83`）在这段拷贝里**没有出现**——即加载器写进组件的这些扩展参数，在光栅路径的物体数据里没有对应槽位。
- `ForwardPipeline::UploadMaterialBindless`：按 `materialID` 去重 → 每材质一份 `GPUMaterialData` → buffer 元素索引 = `materialID >> 2`，空槽位填零值保证索引对齐；材质数变化才重建 buffer，否则复用；注册到 bindless 堆（`ForwardPipeline.cpp:645-699`）。
- 骨骼蒙皮不走合批，走独立 SSBO + 独立 PSO（见 6.6）。

## 10. 已知边界与未实现

以下每条都由代码位置支撑；描述的是"当前代码的状态"，不是"待办"。

1. **没有加载器注册表 / 资产类型分派**。`Engine/Asset` 的源码列表只有 `Asset/glTFLoader.h` 与 `Asset/glTFLoader.cpp`（`Engine/Asset/CMakeLists.txt:4-7`），公开符号只有一个自由函数 `LoadGLTF`（`glTFLoader.h:49`）。扩展名与格式的判断完全在 cgltf 内部（`glTFLoader.cpp:439`），引擎侧没有可注册的 loader 接口。
2. **没有 cook / 打包 / 磁盘缓存**。每次 `LoadGLTF` 都重新 `cgltf_parse_file` + `cgltf_load_buffers`（`glTFLoader.cpp:439`、`:448`），并把顶点/索引**重新建一遍 RHI 缓冲**（`MeshComponent.cpp:37`、`:45`）；没有任何"已导入资产"的序列化产物或哈希比对。`MeshComponent` 家族在反射系统里是**空注册**（`SceneReflect.cpp:57-58`、`:61-62`、`:65-66`），因此网格与材质字段不进存档/编辑器属性表。
3. **没有 FBX / USD / MaterialX / OBJ 加载器**。`Engine/Asset` 里除 glTF 外无其它格式代码（`Engine/Asset/CMakeLists.txt:4-7`）；外部目录里虽然有 `fast_obj.h`、`sdefl.h`（`Engine/External/meshoptimizer/extern/`），但它们不在 meshoptimizer 的编译源列表里（`Engine/External/meshoptimizer/CMakeLists.txt:23-41` 只列 `src/*`），引擎侧也没有任何引用。
4. **网格资产不做任何优化/简化/LOD**。资产路径不调用 meshoptimizer：它只被 Nanite 的资产构建使用（`Engine/Render/Nanite/NaniteUpload.cpp:30`、`Engine/Render/CMakeLists.txt:237`）；加载器只 include `cgltf.h`（`glTFLoader.cpp:22`）。
5. **纹理只认 `uri`**。5 处提取全部要求 `image->uri` 非空（`glTFLoader.cpp:107`、`:116`、`:126`、`:135`、`:149`），没有 `image->buffer_view`（GLB 内嵌图像）分支，也不处理 `KHR_texture_basisu` 的 KTX2 容器。
6. **纹理解码链在 Sample 侧重复实现**。至少 5 个 Sample 各有一份 `loadTexture` lambda（`03.Sponza-Forward.cpp:341`、`04.Sponza-Deferred.cpp:364`、`05.Sponza-PathTracing.cpp:396`、`06.GILab.cpp:389`、`07.Nanite.cpp:392`）与一份 default texture 初始化（`:378`、`:415`、`:451`、`:440`、`:443`）；引擎侧无纹理解码/重采样/缓存模块（`Engine/Asset/CMakeLists.txt:4-7`）。
7. **无 sRGB 解码**。glTF 基础色/自发光贴图按 `RGBA8_UNORM` 上传（`03.Sponza-Forward.cpp:355`），RHI 已有的 `Format::RGBA8_SRGB`（`Engine/RHI/RHI/Types.h:114`）未被资产路径使用。
8. **emissive 贴图没有 bindless 槽**。加载器解析（`glTFLoader.cpp:146-152`）、`SceneRenderer` 拷贝（`SceneRenderer.cpp:125`），但登记代码只注册 4 张（`03.Sponza-Forward.cpp:400-410`）。
9. **非三角形图元被丢弃**：`cgltf_primitive_type_lines / points / strip / fan` 一律告警跳过（`glTFLoader.cpp:269-272`）。
10. **静态路径不生成缺失索引** ⇒ 无索引图元不被绘制。`LoadPrimitive` 只在 `prim.indices` 存在时填索引（`glTFLoader.cpp:349-357`），`m_IndexCount` 因此为 0（`MeshComponent.cpp:15-16`），`MeshBatcher`（`MeshBatcher.cpp:30-32`）与 `GPUScene`（`GPUScene.cpp:58`、`:87`）双双跳过。**蒙皮路径则生成了顺序索引**（`glTFLoader.cpp:671-676`）——两条路径口径不一致。
11. **TANGENT / COLOR 未加载**（`glTFLoader.cpp:288` 注释），vertex color 与切线空间都没有进 `StaticVertex`（`MeshComponent.h:19-23`）。
12. **TEXCOORD 的赋值是无条件覆盖**：属性循环对每个 `cgltf_attribute_type_texcoord` 都赋值 `uvAttr`（`glTFLoader.cpp:286-287`），多套 UV 时最终用的是数组里最后一个。
13. **morph target 与 animation `weights` 通道不支持**：`AnimationClip` 只收 TRS 三条路径（`glTFLoader.cpp:707-730`，注释 `:729` 写明"其他路径（weights/morph）暂不支持"），`SkeletonAsset`/`SkinnedVertex` 也没有 morph 数据字段（`SkeletonAsset.h:20-26`、`:107-113`）。
14. **关节索引硬上限 255**：超出的索引被夹到 255（`glTFLoader.cpp:652`），因为 `SkinnedVertex::joint` 是 `u8`（`SkeletonAsset.h:24`）。
15. **Draco 压缩资产没有解码器**。cgltf 1.14 只把 `KHR_draco_mesh_compression` 解析成元数据（`cgltf.h:567-571`、`:3313-3316`），解码需要外部实现；HugEngine 侧 `cgltf_options` 零初始化、不注册任何处理器（`glTFLoader.cpp:436-437`）。（**后果未实测** → 见第 11 节。）
16. **`LoadGLTF` 只装载、不驱动**。它不创建 `SkeletalMeshComponent`（骨架结果经 `glTFResult::skeletons` 返回，`glTFLoader.h:36`），也不推进任何动画；`AnimationComponent` 需要调用方每帧 `Update`（`03.Sponza-Forward.cpp:672-675`），骨骼需要每帧 `SkeletalMeshSystem::Update`（`02.Cube.cpp:1076`）。
17. **关节点没有名字去重的防护**：重定向按名字匹配时"重名取第一个"（`SkeletalMeshSystem.cpp:244-247`），关节名相同的骨架会静默错配。
18. **`success` 的语义偏弱**：只要解析/缓冲区/场景三步过了，即便所有 primitive 都被跳过、没有任何实体，最终仍是 `result.success = true`（`glTFLoader.cpp:749`）。调用方若想判"到底加载到了什么"必须看 `entities.size()` / `meshCount` / `skeletons`（如 `03.Sponza-Forward.cpp:150-151`）。
19. **没有异步 / 多线程加载**：整条链（cgltf 解析 → unpack → `SetMeshData` 建缓冲）都在调用线程同步完成（`glTFLoader.cpp:432-751`、`MeshComponent.cpp:11-51`），没有 job/流式接口。
20. **同一资产重复导入会重复占显存**：没有去重表；实体的顶点数据按节点×primitive 展开（`glTFLoader.cpp:298-303`、`:414-417`），每次 `LoadGLTF` 都新建 VB/IB（`MeshComponent.cpp:32-45`）。
21. **"场景物体列表 / 合并绘制命令 / 材质收集"三处的组件集合并不完全相同**（都由代码可核实，后果见第 11 节）：
    - 物体列表 `SceneRenderer::Prepare`：Mesh / Cube / Sphere / Billboard / TextRender / Decal / **SplineMesh** / InstancedMesh / SkeletalMesh（`SceneRenderer.cpp:36-71`）；
    - 合并缓冲 `MeshBatcher::Build`：多出 Decal（可选），但**没有 SplineMesh**，且对 SkeletalMesh 是显式的空 lambda（不产命令）（`MeshBatcher.cpp:103-114`）；
    - 材质收集 `ForwardPipeline::UploadMaterialBindless`：显式包含 SplineMesh 与 SkeletalMesh（`ForwardPipeline.cpp:671-676`）；
    - `GPUScene::Collect`：含 SkeletalMesh（`GPUScene.cpp:82`）、不含 SplineMesh。
    三处都各自声明"与另两处口径一致以保证 objectIndex 对齐"（`MeshBatcher.cpp:106`、`:109-111`；`GPUScene.cpp:78`），但集合差异是代码事实。
