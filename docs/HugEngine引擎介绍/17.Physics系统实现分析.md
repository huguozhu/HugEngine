## 1. 结论速览

| 维度 | 现状 | 边界 |
|---|---|---|
| 物理后端 | Jolt Physics **5.6.1**（`Engine/External/JoltPhysics/Jolt/Core/Core.h:8-10`） | 只用了刚体一支：无软体 / 车辆 / 关节 / `CharacterVirtual` |
| 模块 | 静态库 `HugEnginePhysics`，链 `HugEngineScene` / `HugEngineCore` / `Jolt`（`Engine/Physics/CMakeLists.txt:33-37`） | 单向依赖：`HugEngineScene` 不链 Jolt（`Engine/Scene/CMakeLists.txt:95-100`） |
| 世界 | 进程级静态单例 `PhysicsWorld s_World`（`Engine/Physics/Physics/PhysicsSystem.cpp:31`） | MVP 单 world，多 world 无容器 |
| 步进 | 固定步长 $1/120$ s，单帧最多 8 步（`PhysicsSystem.cpp:35-37`、`116-120`） | 超上限的时间被**丢弃**（不追赶）；**无插值** |
| 形状 | 球 / 盒 / 胶囊（`RigidBodyComponent.shape` = 0/1/2，`PhysicsSystem.cpp:40-46`） | 动态盒只有**单一** `halfExtent`（正方体），无凸包 / 三角网格 |
| 碰撞层 | 2 层：`NON_MOVING`=0 / `MOVING`=1（`PhysicsWorld.h:34-41`） | 无通道掩码、无传感器（sensor）语义 |
| 查询 | **CPU 侧纯数学**：`CollisionSystem` 的 Overlap / Contains / Raycast（`Engine/Scene/Scene/CollisionSystem.cpp:8-17`） | 线性遍历全部实体，无宽相加速；**不经过 Jolt** |
| 角色移动 | 手写积分 + 向下射线地面检测（`MovementSystem.cpp:37-95`） | 无水平碰撞滑移（可穿墙）、无加速度平滑、无 step-up |
| 调试可视化 | `CollisionDebugSystem` 复用 `CollisionSystem::ExtractWorldShape`（`CollisionDebugSystem.cpp:201`） | 只画 `CollisionComponent`，**不画 Jolt 刚体** |
| 组件反射 | `RigidBodyComponent` 11 个属性全带 AI 注解（`PhysicsReflect.cpp:14-48`） | AI 词表只列 9 个字段（`TypeSchema.cpp:22`） |

> **最容易踩的三处事实**
> ① 引擎里存在**两套互不相通的碰撞世界**：Jolt 只认 `RigidBodyComponent` 与"无刚体的 `CollisionComponent` 静态体"，所有查询（射线 / 重叠 / 包含）走 CPU 的 `CollisionComponent`（§6.1）；
> ② `RigidBodyComponent.enabled` 这个字段**没有任何消费者**（§5.4）；
> ③ 动态胶囊与静态胶囊的 `height` 语义**不一样**：动态总高 = `height + 2·radius`，静态总高 ≈ `height`（§5.2）。

## 3. PhysicsWorld（Jolt 封装）

### 3.1 `JoltRuntimeGuard`：为什么注册必须发生在"基类"

Jolt 的 `JPH::Allocate` / `JPH::Free` / `Factory::sInstance` 都是**全局函数指针**，由 `RegisterDefaultAllocator()` + `new Factory` 建立；未建立时是 nullptr，而 `JPH_OVERRIDE_NEW_DELETE` 让大量 Jolt 类型（含 `JPH::PhysicsSystem`）的 `new/delete` 直接调用它们。本工程的 `s_World` 是**进程级静态对象**（`PhysicsSystem.cpp:31`），其析构在进程退出时**必然执行**，与有没有调用过 `Initialize()` 无关；若此时分配器未注册，`~JPH::PhysicsSystem` 的 `delete[]` 会经宏调用空的 `JPH::Free` → 跳转地址 0（`PhysicsWorld.h:80-90` 记录了完整根因链）。

因此注册被提到**基类构造函数**：成员构造发生在构造函数体之前，"在构造函数体里注册"来不及，基类先于成员构造（`PhysicsWorld.h:91-92`）。落地为 `PhysicsWorld : private JoltRuntimeGuard`（`:101`），`JoltRuntimeGuard::JoltRuntimeGuard()` 调 `EnsureJoltRegistered()`（`PhysicsWorld.cpp:32`），注册本身用函数内 `static` 保证幂等（`PhysicsWorld.cpp:20-28`：`RegisterDefaultAllocator()` → `Factory::sInstance = new Factory()` → `RegisterTypes()`）。`Initialize()` 里仍会再调一次（`:36`）。

### 3.2 初始化：上限、分配器、作业系统、重力

`PhysicsInitDesc` 默认值（`PhysicsWorld.h:24-29`）：

| 字段 | 默认值 | 传给 Jolt 的位置 |
|---|---|---|
| `maxBodies` | `1024` | `PhysicsWorld.cpp:41` 第 1 参 |
| `maxBodyPairs` | `65536` | `PhysicsWorld.cpp:41` 第 3 参 |
| `maxContactConstraints` | `10240` | `PhysicsWorld.cpp:41` 第 4 参 |
| `gravity` | `-9.81f` | `PhysicsWorld.cpp:43` `SetGravity(Vec3(0, gravity, 0))` |

第 2 个实参是硬编码的 `0`（`PhysicsWorld.cpp:41`）。对照 Jolt 签名 `Init(uint inMaxBodies, uint inNumBodyMutexes, uint inMaxBodyPairs, uint inMaxContactConstraints, ...)`（`Engine/External/JoltPhysics/Jolt/Physics/PhysicsSystem.h:59`），第 2 参是 `inNumBodyMutexes`，其文档写明"取值 `0` 表示自动探测"（同文件 `:53`）——这个 `0` 是交给 Jolt 自决，不是漏填。其余资源：

- `JPH::JobSystemThreadPool(1024, 8, 2)`（`PhysicsWorld.cpp:38`）——按 Jolt 构造语义为 maxJobs=1024、maxBarriers=8、**2 个工作线程**；头文件注释同样标注"2 工作线程"（`PhysicsWorld.h:119`）。冒烟测试留了一条环境备注："`JobSystemSingleThreaded` 在本环境会导致 `Update` 挂起"（`Tests/TestJoltSmoke.cpp:105`）。
- `JPH::TempAllocatorImpl(10 * 1024 * 1024)`（`PhysicsWorld.cpp:39`）——窄相检测用的 10 MB 临时分配器（`PhysicsWorld.h:120`）。
- `Initialize` 幂等：`if (m_Ready) return true;`（`PhysicsWorld.cpp:35`）。

### 3.3 碰撞层过滤（2 层，静态-静态不碰）

对象层与宽相层都是同名的 0/1 两层（`PhysicsWorld.h:34-41`）：

```cpp
namespace Layers            { NON_MOVING = 0; MOVING = 1; }   // PhysicsWorld.h:35-36
namespace BroadPhaseLayers  { NON_MOVING(0); MOVING(1); }      // PhysicsWorld.h:39-40
```

| 实现类 | 位置 | 判据 |
|---|---|---|
| `BPLayerInterfaceImpl` | `PhysicsWorld.h:44-57` | 对象层 → 宽相层恒等映射（`:47-48`），层名供 Profiler（`:52-54`）；层数 2（`:50`） |
| `ObjectVsBroadPhaseLayerFilterImpl` | `PhysicsWorld.h:60-66` | $\mathrm{ShouldCollide}(l,bp)=\begin{cases} bp=\mathrm{MOVING} & l=\mathrm{NON\_MOVING}\\ \mathrm{true} & l=\mathrm{MOVING}\end{cases}$ |
| `ObjectLayerPairFilterImpl` | `PhysicsWorld.h:69-75` | $\mathrm{ShouldCollide}(l_1,l_2)=\neg\,(l_1=\mathrm{NON\_MOVING}\ \wedge\ l_2=\mathrm{NON\_MOVING})$ |

即：**静态 × 静态不产生碰撞对**（`:72`），动态 × 动态、动态 × 静态都碰。对象层在 body 创建处按 `isDynamic` 决定（`PhysicsSystem.cpp:63`、`:104`）：动态 → `MOVING`，静态 → `NON_MOVING`。

### 3.4 Step 与 Shutdown

- `Step(f32 fixedDt)`：`if (!m_Ready || fixedDt <= 0.0f) return;` 后调 `m_System.Update(fixedDt, 1, m_TempAllocator.get(), m_JobSystem.get())`（`PhysicsWorld.cpp:50-53`）。第 2 参 `1` 是 `inCollisionSteps`，语义为"把 `inDeltaTime` 分成几次迭代做碰撞"（`Engine/External/JoltPhysics/Jolt/Physics/PhysicsSystem.h:157`、`:162`）——**一个固定步 = 1 次碰撞迭代**。
- `Shutdown()`（`PhysicsWorld.cpp:55-63`）只 `reset` JobSystem / TempAllocator 并把 `m_Ready` 置 false；注释写明 body 由 `PhysicsSystem`（T4）负责销毁、Jolt 自身析构会清理内部资源（`:57-58`）。**仓库内没有任何 `PhysicsWorld::Shutdown()` 调用者**（全仓 `Shutdown` 命中全是渲染管线同名方法），`s_World` 也是唯一的 `PhysicsWorld` 实例。

## 4. PhysicsSystem 与 tick 耦合

### 4.1 固定步长累加器

常量（`PhysicsSystem.cpp:35-37`）：`kFixedDt = 1.0f / 120.0f`、`kMaxSteps = 8`（注释"防 spiral of death"）、`kMaxAccum = kFixedDt * kMaxSteps`。每帧逻辑在 `PhysicsSystem.cpp:112-121`：

$$\Delta t_{\mathrm{fix}} = \frac{1}{120}\,\mathrm{s},\qquad \Delta t_{\max} = 8\,\Delta t_{\mathrm{fix}} = \frac{1}{15}\,\mathrm{s}$$

$$A' = \min\left(A + \Delta t,\ \Delta t_{\max}\right),\qquad N = \min\left(\left\lfloor \frac{A'}{\Delta t_{\mathrm{fix}}} \right\rfloor,\ 8\right),\qquad A \leftarrow A' - N\cdot\Delta t_{\mathrm{fix}}$$

对应顺序：`s_Accumulator += dt`（`:113`）→ 夹取 `clampedAccum`（`:114`）→ `while (clampedAccum >= kFixedDt && steps < kMaxSteps) { s_World.Step(kFixedDt); ... }`（`:116-120`）→ 写回余数（`:121`）。可直接推出的三点：

| 现象 | 依据 |
|---|---|
| 渲染 60 fps（$\Delta t = 1/60$）时每帧恰好 **2 步** | $1/60 \div 1/120 = 2$，`:116` |
| $\Delta t > 1/15$ s（< 15 fps）时**多余时间被丢弃**，物理变慢 | 夹取发生在累加后（`:114`），`s_Accumulator` 只保留余数（`:121`） |
| 物理时钟与渲染时钟长期存在**相位残差** $\in[0, 1/120)$ | 余数保留语义（`:121`）+ 回写无插值（§4.4） |

`dt <= 0` 直接返回（`:50`），首次调用惰性初始化世界：`if (!s_World.IsReady()) s_World.Initialize();`（`:51`）。

### 4.2 入口 1：动态 / 静态刚体（`RigidBodyComponent`）

遍历所有带 `RigidBodyComponent` 的实体（`PhysicsSystem.cpp:55-78`），跳过条件为：已在物理世界（`s_Bodies.count(e)`，`:56`）、没有 `TransformComponent`（`:57-58`）。然后一次性填 `BodyCreationSettings`（`:61-71`）：

| Jolt 字段 | 来源 | 行 |
|---|---|---|
| shape | `CreateShape(rb)` | `:60-61` |
| 位置 / 旋转 | `ToJoltPos(xf->position)` / `ToJolt(xf->rotation)` | `:61` |
| 运动类型 | `rb.isDynamic ? Dynamic : Static` | `:62` |
| 对象层 | `rb.isDynamic ? Layers::MOVING : Layers::NON_MOVING` | `:63` |
| 质量 | `CalculateInertia` + `mMassPropertiesOverride.mMass = rb.mass` | `:65-66` |
| `mFriction` / `mRestitution` | `rb.friction` / `rb.restitution` | `:68-69` |
| `mLinearDamping` / `mAngularDamping` | `rb.linearDamping` / `rb.angularDamping` | `:70-71` |

`CalculateInertia` 的语义是"质量取 `mMassPropertiesOverride.mMass`，惯性张量按形状密度计算并缩放到该质量"（`Engine/External/JoltPhysics/Jolt/Physics/Body/BodyCreationSettings.h:25`）。创建后 `SetUserData(e.id)`（`:75`，供回写 / 回收）、`AddBody(id, isDynamic ? Activate : DontActivate)`（`:76`）、落进 `s_Bodies`（`:77`）。`CreateBody` 返回空指针时静默返回（`:74`）——上限打满时**每帧重试**（§10-7）。

**`TransformComponent.scale` 完全不参与**：这段代码只读 `position` / `rotation`（`:61`），形状构造也没有任何缩放因子（`:40-46`）。与之对照，CPU 侧碰撞形状**会**乘最大缩放分量（`CollisionSystem.cpp:255-257`）——两套世界对缩放态度不同（§10-11）。

### 4.3 入口 2：静态碰撞体（`CollisionComponent` 且无刚体）

遍历所有带 `CollisionComponent` 的实体（`PhysicsSystem.cpp:81-110`），四道过滤：`!cc.bEnabled`（`:82`）、已在物理世界（`:83`）、**有 `RigidBodyComponent` 就走入口 1**（`:84`）、缺 `TransformComponent`（`:85-86`）。形状映射（`:88-101`）：

| `CollisionShape` | Jolt 形状 | 尺寸转换 |
|---|---|---|
| `Sphere` | `SphereShape(cc.radius)` | 半径直接用（`:91`） |
| `Capsule` | `CapsuleShape(halfH, cc.radius)` | `halfH = max(cc.height*0.5 - cc.radius, 0.01)`，注释"段半长（Jolt 需 >0）"（`:93-95`） |
| `AABB`（`default`） | `BoxShape(ToJolt(cc.halfExtents))` | **三轴**半尺寸（`:98-100`） |

统一按 `Static` + `NON_MOVING` 建体（`:103-104`），`AddBody(..., DontActivate)`（`:108`）——静态体永不被激活，因而永远不会被回写。

### 4.4 回写 Transform 与 body 回收

回写发生在**所有步进之后一次**（`PhysicsSystem.cpp:123-141`），不是每一步之后：

```cpp
if (bi.IsActive(bid)) {                                        // :136 动态激活才回写
    xf->position = ToGlmPos(bi.GetCenterOfMassPosition(bid));  // :137
    xf->rotation = ToGlm(bi.GetRotation(bid));                 // :138
}
```

`IsActive` / `GetCenterOfMassPosition` / `GetRotation` 都是 `BodyInterface` 的查询（`Engine/External/JoltPhysics/Jolt/Physics/Body/BodyInterface.h:147`、`:192`、`:194`）。用**质心位置**而非 body 原点：当前三个形状质心都在原点所以等价，将来引入质心偏移形状就会错位（§10-18）。`scale` 保持不变；静态体 `IsActive` 恒 false → 位置永远取自创建时刻的 Transform。

回收：遍历 `s_Bodies`，若实体已无 `TransformComponent`（实体被销毁），`RemoveBody(bid)` + `DestroyBody(bid)` + `erase`（`:127-133`）——这就是"销毁实体 → 无泄漏"的实现（`Tests/TestPhysicsBasics.cpp:47-61` 覆盖）。

`PhysicsSystem::Update` 有一个**未使用**的形参 `he::SceneGraph&`（`:49` 匿名形参）。后果：带父级的实体，物理 body 取的是**局部** `TransformComponent.position`，而 CPU 侧 `ExtractWorldShape` 优先取场景图的**世界**矩阵（`CollisionSystem.cpp:251-254`）。示例里物理球显式清了父级（`Samples/02.Cube/02.Cube.cpp:239`）正是为了绕开这一点。

### 4.5 与渲染 tick 的关系（调用方决定顺序，系统内部无 tick）

本模块**没有**自己的 tick 源：`PhysicsSystem::Update` 是静态函数，由调用方每帧驱动一次（`PhysicsSystem.h:26`）。仓库里唯一的引擎级调用点是 `Samples/02.Cube`：`MovementSystem::Update`（`:1056`）→ **`PhysicsSystem::Update`（`:1060`）** → `NavAgentSystem`（`:1063`）→ `SplineMeshSystem`（`:1066`）→ 帧相机解析（`:1070`）→ `TextRenderSystem` / `SkeletalMeshSystem`（`:1073`、`:1076`）→ `CollisionDebugSystem::Update`（`:1079`）。调试 HUD 读激活刚体数：`ImGui::Text("激活刚体: %d", PhysicsSystem::GetActiveBodyCount())`（`:1432`），该函数对 `s_Bodies` 逐项 `IsActive` 计数（`PhysicsSystem.cpp:150-157`）。

**没有插值**：回写取的是物理世界当前状态（`:137-138`），没有 alpha 混合、没有上一帧位置 lerp，`PhysicsWorld` 的公开面（`PhysicsWorld.h:104-111`）也没有任何插值接口。所以渲染帧率与 120 Hz 不同相位时，位置序列会出现 ±1 步的抖动（§10-10）。

## 5. 刚体组件与形状数据表示

### 5.1 字段（纯数据）

| 字段 | 类型 | 默认值 | 语义（照抄注释） | 行 |

## 6. 查询与碰撞

### 6.1 结论：查询走的是 CPU 侧纯数学，不是 Jolt

**证据链**：

1. `CollisionSystem.cpp` 的 include 只有场景侧与数学头（`CollisionSystem.cpp:8-17`），没有任何 `Jolt/…`。
2. `Engine/Scene` 全目录搜索 `physics::` / `NarrowPhaseQuery` / `ContactListener` **无匹配**——场景模块根本不知道物理后端存在。
3. `Engine/Physics` 对 `BodyInterface` 的使用**只有** `CreateBody`（`PhysicsSystem.cpp:73`、`:105`）、`AddBody`（`:76`、`:108`）、`RemoveBody` + `DestroyBody`（`:130-131`）、`IsActive`（`:136`、`:155`）、`GetCenterOfMassPosition`（`:137`）、`GetRotation`（`:138`）；在该目录搜索 `NarrowPhaseQuery` / `SetPosition` / `SetRotation` / `MotionQuality` / `ContactListener` 均无匹配。

**因此**：Jolt 的射线 / 重叠查询（`JPH::NarrowPhaseQuery::CastRay` / `CollideShape`）在本工程**未使用**；角色地面检测、Overlap 触发（示例里的红/绿球）、调试线框全部基于 `CollisionComponent` 的 CPU 数学（§6.2~§6.5）。反过来说，挂 `RigidBodyComponent` 的**动态刚体不参与**任何 `CollisionSystem` 查询——它们身上通常没有 `CollisionComponent`，示例 `02.Cube` 的 4 个物理球就只有 `RigidBodyComponent` + `SphereComponent`（`02.Cube.cpp:219-240`）。

### 6.2 世界空间形状提取（检测与线框的公共语义）

`CollisionSystem::ExtractWorldShape`（`CollisionSystem.cpp:245-284`）：

| 步骤 | 实现 | 行 |
|---|---|---|
| 取组件 | 缺 `CollisionComponent` / `TransformComponent` / `bEnabled == false` → `false` | `:246-248` |
| 世界矩阵 | 优先 `SceneGraph::GetWorldMatrix(e)`（支持父层级），无场景图回退 `xf->GetLocalMatrix()` | `:251-254` |
| 缩放 | `scale = max(sx, sy, sz)`，`<= 0` 时取 1 | `:256-257` |
| 球心 / 半径 | 世界矩阵第 4 列 `float3(wm[3])`；`cc->radius * scale`（**统一乘最大缩放分量**，MVP 约定） | `:260-261` |
| AABB | `AABB(-halfExtents, halfExtents).Transform(wm)` → 世界重轴包围盒（旋转后保守） | `:264-269` |
| Sphere | 只有球心 + 半径（与旋转无关） | `:271-273` |
| Capsule | `halfSeg = max(0, height/2 - radius) * scale`；轴 = `normalize(rotation * (0,1,0))`；`segA/segB = center ± up*halfSeg` | `:274-281` |

### 6.3 Overlap（9 种形状组合全列）

`OverlapShapes`（`CollisionSystem.cpp:67-103`）显式列出每种组合，对称组合直接交换参数复用（`:77-79`、`:86-88`、`:96-98`）：

| 组合 | 判据 | 行 |
|---|---|---|
| AABB × AABB | 三轴区间重叠：$\forall i:\ A_{\min,i}\le B_{\max,i} \wedge A_{\max,i}\ge B_{\min,i}$ | `:68-72` |
| AABB × Sphere | $\left\|\mathrm{clamp}(c_B, A_{\min}, A_{\max}) - c_B\right\| \le r_B$ | `:73-76` |
| AABB × Capsule | 段上取点 → 钳进盒 → 再取回段上最近点，距离 $\le r$（**单次迭代近似**，注释直言 MVP 足够） | `:80-85` |
| Sphere × Sphere | $\left\|c_A-c_B\right\| \le r_A + r_B$ | `:89-91` |
| Sphere × Capsule | 点到段最近距离 $\le r_A + r_B$ | `:92-95` |
| Capsule × Capsule | 段-段最近距离 $\le r_A + r_B$（`SegmentSegmentDistance`） | `:99-101`、`:44-63` |

### 6.5 Raycast（含法线）

入口 `CollisionSystem::Raycast`（`CollisionSystem.cpp:207-237`）：方向归一化、零向量直接未命中（`lenSq < 1e-12f`，`:211-213`）；线性遍历 `world.ForEach<CollisionComponent>`，跳过 `ignore` 实体（`:219-220`）与提取失败者（`:222`）；取 $t$ 最小者（`bestT` 初值 `maxDistance + 1.0f`，`:215`；判定 `t >= 0 && t < bestT`，`:225`）；写入 `outHit` / `outT` / 可选 `outNormal`（`:232-236`），无命中时不改动输出（契约见 `CollisionSystem.h:43`）。

单形状求交 `RaycastShape`（`CollisionSystem.cpp:121-191`）：

| 形状 | 方法 | 法线 | 行 |
|---|---|---|---|
| AABB | slab 法逐轴求进出区间交集，平行轴用 `abs(dir[i]) < 1e-8f` 判退化 | 命中点到 6 个面的最近距离 → 对应轴向法线（只取 $\pm$ 轴） | `:123-152` |
| Sphere | 归一化方向下的二次方程：$\mathrm{disc}=(\mathbf{oc}\cdot\hat d)^2-(\left\|\mathbf{oc}\right\|^2-r^2)$，$t=-\mathbf{oc}\cdot\hat d\mp\sqrt{\mathrm{disc}}$；起点在球内时取**远**交点 | $(\mathbf{hit}-\mathbf{c})/r$ | `:153-167` |
| Capsule | **最近接近近似**：求射线与轴段最接近的参数 $t$（`clamp` 到 $[0,maxDist]$），最近距离 $\le r$ 即命中 | $(\mathbf{closest}-\mathbf{segClosest})/\max(d,10^{-6})$，注释"胶囊侧面指向射线" | `:168-188` |

三点需要注意：

- 胶囊分支注释自己写明局限："MVP：射线与胶囊 = 射线与段的最近距离 <= 半径（端点半球近似，掠射角有误差）"（`:169`）。它返回的 $t$ 是**最近接近参数**而非射线进入胶囊表面的距离——判"脚下有没有地面"够用，求精确命中点则不准。
- AABB 法线只可能是 6 个轴法线之一（`:145-150`），因为 AABB 本身就是重轴包围盒（旋转体用保守包围盒代替，`:266`）。参考用例：从上方下射命中盒顶面得 $n=(0,1,0)$，从 +Z 侧射入得 $n=(0,0,1)$（`Tests/TestCollision.cpp:161-179`）。
- 复杂度 $O(N)$（$N$ = 带 `CollisionComponent` 的实体数）：每个角色每帧一次地面射线就要遍历一遍（`MovementSystem.cpp:76`），无宽相 / BVH / 空间哈希（§10-4）。

### 7.2 每帧五步（`MovementSystem::Update`）

入口 `dt <= 0` 直接返回（`MovementSystem.cpp:38`），只处理有 `TransformComponent` 的实体（`:41-42`）。

**第 1 步 水平速度**（`:45-51`）——长度 >1 时归一化，然后**直接赋值**（无加速度平滑）：

$$\hat w = \begin{cases} w/\left\|w\right\| & \left\|w\right\| > 1\\ w & \text{otherwise}\end{cases},\qquad s=\begin{cases}4.5 & b_{\mathrm{run}}\\ 1.5 & \text{otherwise}\end{cases},\qquad v_x = \hat w_x s,\quad v_z = \hat w_y s$$

（`inputDirection` 是 `float2`，其 `.y` 映射到世界 **z** 轴：`:50-51`。）

**第 2 步 跳跃**（`:53-61`）——边沿触发，仅地面可起跳（空中请求被消费但忽略，无二段跳）：$v_y = \sqrt{2\,g\,\max(h, 0)}$，随后 `bOnGround = false`，对应 `m.velocity.y = std::sqrt(2.0f * m.gravity * std::max(m.jumpHeight, 0.0f));`（`:58`）。默认参数下 $v_y=\sqrt{2\times 9.8\times 0.8}\approx 3.96$ m/s（与 `Tests/TestCharacterMovement.cpp:85-90` 断言一致）。

**第 3 步 重力积分**（`:63-66`）——只在空中：$v_y \leftarrow v_y - g\,\Delta t$。

**第 4 步 位置积分**（`:68-69`）：$\mathbf p \leftarrow \mathbf p + \mathbf v\,\Delta t$。速度先更新、位置后更新（半隐式顺序），所以跳跃最高点会略高于解析解（测试用 $\epsilon=0.05$ 容忍，`Tests/TestCharacterMovement.cpp:101`）。

**第 5 步 地面检测**（`:71-93`）——条件 `m.velocity.y <= 0.0f`（下落或静止才检测，上升阶段不贴地）：$\text{maxDist} = \mathrm{halfHeight} + 0.2$，射线自 `xf->position` 沿 $(0,-1,0)$ 向下；命中且 $\theta = \arccos(\mathrm{clamp}(n_y,-1,1))$（度）$\le \mathrm{maxSlopeAngle}$ 时置 `bOnGround = true`、贴地吸附 $p_y \leftarrow p_y + (\mathrm{halfHeight} - t)$、$v_y \leftarrow 0$（`:82-86`）；法线有效但坡度太大则 `bOnGround = false`（`:88`）；未命中同样 `false`（`:91`）。

实现要点：射线用 `CollisionSystem::Raycast(world, xf->position, (0,-1,0), halfHeight + kGroundTolerance, hit, t, e.id, &groundNormal)`（`:76-78`）——**排除自身**（第 7 参传 `e.id`，对照 `CollisionSystem.h:41` 的 `ignore` 契约）并索取法线用于坡度判断；容差 `kGroundTolerance = 0.2f` 米，注释"射线最大距离 = 半高 + 容差，允许轻微下落贴地"（`:20-21`）；贴地吸附是"把半高误差修正回精确贴地"（`:84-85`）。坡度过滤**是实现了的**（`:79-89`），陡坡分支只把 `bOnGround` 置 false，**不做滑移**（不会沿坡面滑下去）。

### 7.3 半高从哪来

`GetHalfHeight`（`MovementSystem.cpp:24-33`）：`Capsule` → `cc->height * 0.5f`（`:28`）；`Sphere` → `cc->radius`（`:29`）；`AABB` → `cc->halfExtents.y`（`:30`）；无碰撞体 → 默认 `0.5f`（`:26`、`:32`）。因此角色地面检测**依赖 `CollisionComponent`**（头文件亦写明：`CharacterMovementComponent.h:10-11`），与 Jolt 无关。示例角色实体是"胶囊 `CollisionComponent`（radius 0.4 / height 1.6）+ 视觉球"，没有刚体（`02.Cube.cpp:389-394`），半高 = 0.8。

## 8. 物理与渲染的调试可视化

### 8.1 组件与渲染方式

`CollisionDebugComponent` 继承 `MeshComponent`（`CollisionDebugComponent.h:22-36`）：`color = (0.15, 1, 0.45, 0.8)`（青绿半透明，`:26`）、`lineThickness = 0.02f`（世界单位，`:28`），运行时字段 `segmentCount` / `cachedShape` / `cachedThickness` / `bHasCache`（`:31-35`）。**为什么做成 `MeshComponent` 而不是"新 PSO + 线段绘制"**：线框本质是"带颜色的几何"，复用现有网格路径（顶点/索引缓冲 + 材质 + Forward/Deferred 两条管线）就不必往 RHI 里塞线拓扑管线，代价是"线"被三角化成细带（`:12-15`）。

`Ensure()` 补组件时设置调试渲染属性：`unlit = true`、`alphaMode = 2`（`AlphaMode::Blend`）、`doubleSided = true`、`castShadow = false`、`metallic 0 / roughness 1`（`CollisionDebugSystem.cpp:166-172`），即"调试几何不该影响光照与阴影"；没有 `CollisionComponent` 的实体直接返回 `nullptr`（`:161`）。

### 8.2 形状语义的唯一来源

`CollisionDebugSystem::Update` 对每个带 `CollisionComponent` 的实体调 `CollisionSystem::ExtractWorldShape(world, e, shape)`（`CollisionDebugSystem.cpp:200-201`），再 `BuildWireframe` 三角化（`:225`）。这就是"线框画出来的必须就是检测用的那个形状"的落地方式，头文件与实现注释反复强调（`CollisionSystem.h:15-17`、`CollisionSystem.cpp:240-244`、`CollisionDebugSystem.h:11-13`）。

### 8.3 线框几何

单段线 → **十字交叉的两片细带**：8 顶点 / 12 索引（`CollisionDebugSystem.cpp:27-56`；测试断言 `verts.size() == 12*8`、`indices.size() == 12*12`，`Tests/TestCollision.cpp:222-223`）。理由是 billboard 需要相机参数、而两片互相垂直的细带在任意视角都可见（`CollisionDebugSystem.cpp:25-26`）。

| 形状 | 构成 | 线段数 | 行 |
|---|---|---|---|
| AABB | 12 条棱 | 12 | `:98-113` |
| Sphere | 3 个正交大圆（XY / YZ / XZ），每圆 `kCircleSegments = 24` 段 | 72 | `:114-122` |
| Capsule | 上下两圆（2×24）+ 4 条竖线 + 两端各 4 条半球弧（8×8，`kCapArcSegments = 8`） | 116 | `:123-155` |

顶点数 = 线段数 × 8（球 576、胶囊 928），索引数 = 线段数 × 12。退化线段（长度 < `1e-6`）与退化圆（半径 ≤ `1e-6` / 段数 < 3）直接跳过，线宽下限 `1e-4`（`:31`、`:62`、`:76`、`:93`），保证不产生 NaN（`Tests/TestCollision.cpp:272-288` 覆盖）。

### 8.4 缓存与开关

- **形状没变就不重建网格**：把 `min/max/center/segA/segB/radius/shape/lineThickness` 与快照逐一比较（位置类容差 `1e-4`、线宽 `1e-6`），命中即 `return`（`CollisionDebugSystem.cpp:211-221`），目的是"避免每帧重建 GPU 缓冲"（`:211`）。
- **开关语义**：`Update(world, false)` 只清空几何并归零 `segmentCount`，**组件保留**（便于再打开，`:184-193`）；打开时若还没有组件就补一个（`:196-198`）。
- **碰撞体被禁用**：`ExtractWorldShape` 失败 → 清空已有线框（`:202-208`，"线框也要消失"）。
- 示例入口：面板开关 `demoCollisionDebug`（默认 true，`02.Cube.cpp:342`）、每帧 `CollisionDebugSystem::Update(world, demoCollisionDebug)`（`:1079`）、预先用 `Ensure` 给碰撞盒与探测球配色（`:354-355`、`:372-373`）。

### 8.5 可视化覆盖范围的边界

遍历目标是 `world.ForEach<CollisionComponent>`（`CollisionDebugSystem.cpp:181`），所以**只有挂 `CollisionComponent` 的实体**有线框：Jolt 动态刚体（如 `02.Cube` 的 4 个 `PhysBall`，只有 `RigidBodyComponent` + `SphereComponent`，`02.Cube.cpp:219-240`）**没有调试线框**，也没有任何可视化反映 Jolt 侧 body 状态；而线框反映的是 CPU 侧语义（动态胶囊总高差异、`scale` 参与半径，见 §5.2 / §10-13、§10-11），与 Jolt 里真实求解的形状**可能不同**——对 Jolt 有"看起来对、其实另一套"的风险。

## 10. 已知边界与未实现

1. **ragdoll / 物理动画**：完全没有。`Engine/Physics` 搜索 `Ragdoll` 无匹配；模块只 include `SphereShape.h` / `BoxShape.h` / `CapsuleShape.h` / `BodyCreationSettings.h`（`PhysicsSystem.cpp:19-23`），无骨骼映射（`JPH::Skeleton` / `Ragdoll`）代码；`SkeletalMeshSystem` 是纯 CPU 蒙皮，与物理无交互。
2. **坡度过滤**：已实现（`MovementSystem.cpp:79-89`）但**无测试覆盖**（§7.5），且陡坡分支只置 `bOnGround = false`，不产生沿坡面滑移（`:88`）。
3. **水平碰撞滑移**：没有。只有向下一条射线（`MovementSystem.cpp:76`），水平方向直接积分（`:69`），头文件自述"可穿墙"（`CharacterMovementComponent.h:17`）；无 capsule sweep、无 step-up、无蹲伏。
4. **多形状 raycast / 宽相**：每个实体最多一个 `CollisionComponent`（一个形状）；`Raycast` 线性遍历所有实体（`CollisionSystem.cpp:219-230`），无空间加速；角色地面检测即每角色每帧一次全量遍历（`MovementSystem.cpp:76`）。
5. **`RigidBodyComponent.enabled` 无消费者**：见 §5.4（`PhysicsSystem.cpp:143` 只剩一行"由调用方处理"的注释）。
6. **参数 / 形状变更不重建 body**：入口逻辑只有"不存在就创建"（`PhysicsSystem.cpp:56`、`:83`），没有 diff；运行时改 `radius` / `mass` / `shape` 对已建 body **无效**，静态体创建后改 Transform 也不会同步到 Jolt。
7. **`maxBodies` 上限的失败路径**：`CreateBody` 返回空指针就静默 `return`（`:74`、`:106`），无日志、无降级计数；由于映射里没有该实体，**下一帧还会重试**。
8. **单 world**：`s_World` 与 `s_Bodies` 都是进程级静态（`PhysicsSystem.cpp:30-33`），注释明写 "MVP 单 world；多 world 需 per-world 容器，留后续"；`s_Bodies` 无清空路径，`PhysicsWorld::Shutdown()` 也不动它（`PhysicsWorld.cpp:55-63`）且无调用者。
9. **固定步长的丢时间语义**：$\Delta t > 1/15$ s 时超出部分被丢弃（§4.1），物理时间落后于墙钟；没有"步数打满"的告警。
10. **无插值**：每帧一次取当前物理状态回写（`:136-139`），渲染侧无 alpha 混合，120 Hz 与显示刷新不同相位时有步进抖动（§4.5）。
11. **`TransformComponent.scale` 不参与 Jolt**：建 body 时既不做形状缩放也不写 body 缩放（`PhysicsSystem.cpp:61`），而 CPU 侧半径会乘最大缩放分量（`CollisionSystem.cpp:255-257`）；同一实体在两套世界里尺寸可能不一致。
12. **两套碰撞世界不互通**：Jolt 刚体不参与 `CollisionSystem` 查询，`CollisionSystem` 的形状也不参与 Jolt 求解（除非它是"无刚体的 `CollisionComponent`"，才会被注册成静态体，`PhysicsSystem.cpp:81-110`）；同实体同挂动态 `RigidBodyComponent` 与 `CharacterMovementComponent` 时两个系统都写 `xf->position`（`:137` 与 `MovementSystem.cpp:69`），无仲裁。
13. **胶囊语义分歧**：动态胶囊总高 = `height + 2·radius`（`:43`），静态胶囊总高 ≈ `height`（`:94`）。
14. **盒的分辨率**：动态盒只有单一 `halfExtent`，三轴必须相等（`:42`）；静态盒支持三轴 `halfExtents`（`:99`）。
15. **无碰撞事件**：`Engine` 内搜索 `ContactListener` / `SetContactListener` 无匹配，没有"落地 / 进入触发区"回调，也没有 sensor（触发体积）概念；`CollisionSystem::Overlap` 只能由调用方每帧轮询（示例即如此：`02.Cube.cpp:1026`）。
16. **无 CCD / 无 `MotionQuality` 设置**：`Engine/Physics` 内搜索 `MotionQuality` 无匹配，body 全用 Jolt 默认运动质量；高速小物体存在穿透风险，本模块未做高速保护。
17. **父子层级**：`SceneGraph&` 形参未使用（`:49`），带父级实体用**局部** Transform 建体（`:61`），与 `CollisionSystem` 用世界矩阵的做法不同（`CollisionSystem.cpp:251-254`）；也没有"带父级实体不允许动态"的校验。
18. **质心 vs 原点**：回写用 `GetCenterOfMassPosition`（`:137`），当前三个形状质心在原点所以等价，引入质心偏移形状后会错位。
19. **AI 词表缺两个字段**：`TypeSchema.cpp:22` 只列 9 个字段，缺 `linearDamping` / `angularDamping`；`SceneBuilder.cpp:220-231` 同样只解析 9 个。
20. **无关节 / 约束 / 软体 / 车辆 / 双精度大世界**：`Engine/Physics` 内均无相关代码；`PhysicsInitDesc` 也只有 bodies / pairs / constraints / gravity 四项（`PhysicsWorld.h:24-29`）。
