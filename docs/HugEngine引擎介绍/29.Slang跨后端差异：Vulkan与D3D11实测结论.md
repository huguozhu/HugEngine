# 29.Slang 跨后端差异：Vulkan 与 D3D11 的实测结论与改造

> 本文记录为新增 D3D11 后端而做的着色器改造：**Slang 在 Vulkan（SPIR-V）与 D3D11（HLSL/DXBC）两个目标上的行为差异**，每一条都附实测证据与对应的宏方案。
>
> 所有结论均来自 `slangc 2026.13`（Vulkan SDK 1.4.341.1）的实测，不是推测。

---

## 1. 为什么需要这份文档

引擎的着色器统一用 Slang 编写，原本只编到 SPIR-V。接入 D3D11 后，同一份源码要同时产出：

| 后端 | 目标 | 编译器 | 产物 |
|---|---|---|---|
| Vulkan | SPIR-V | `slangc -target spirv` | `*.spv.h` |
| OpenGL（规划中） | SPIR-V | 同上 | 同一份 |
| D3D11 | HLSL → DXBC | `slangc -target hlsl` → `D3DCompile` | `*.dxbc.h` |
| D3D12（规划中） | HLSL → DXIL | `slangc -target dxil` | — |

问题在于：**Slang 对 D3D 目标的绑定处理与 Vulkan 完全不同**，而引擎的 C++ 侧按**固定绑定编号**绑定资源。编号一旦变化，整个渲染就错乱。

---

## 2. 核心差异一：绑定声明（最关键）

### 2.1 实测结论

| 写法 | → SPIR-V | → HLSL / DXIL | 说明 |
|---|---|---|---|
| `[[vk::binding(3, 0)]] T u;` | ✅ 绑定 = 3 | ❌ **被忽略**，自动编号成 `t0` | `vk::` 命名空间只对 SPIR-V 有效 |
| `[[register(t3)]] T u;` | ⚠️ `warning E31000: unknown attribute` | ❌ 无效 | **不是合法属性**，会被静默忽略 |
| `[register(t3, space0)]` | ⚠️ 同上 | ❌ 无效 | 同上 |
| `[[binding(0)]] T u;` | ⚠️ 未知属性 | ❌ 无效 | 同上 |
| **`T u : register(t3);`** | ✅ | ✅ **编号保留** | **声明后缀语法**，Slang 原生支持 |
| 不写任何绑定 | ✅ 自动编号 | ✅ 自动编号 | 按声明顺序，违背"固定编号"契约 |

**关键结论：Slang 的 `register` 是"声明后缀"语法，不是属性语法。**
写成属性（`[[register(...)]]`）只会得到一个被忽略的警告，退出码仍是 0 —— 这一点极具欺骗性。

### 2.2 但后缀语法与 Vulkan 的属性语法位置相反

```slang
// Vulkan：绑定属性在声明**之前**
[[vk::binding(3, 0)]] StructuredBuffer<float> u_Input;

// D3D11：寄存器后缀在声明**之后**
StructuredBuffer<float> u_Input : register(t3);
```

⇒ 单个"前缀宏"无法同时满足两者 ⇒ **必须让宏生成整条声明**。

### 2.3 解法：`HE_DECL_*` 系列宏

```slang
// Engine/Shader/Shaders/BackendBindings.slang
#if defined(HE_SHADER_LANG_HLSL)
    // D3D11（SM5.0）：没有 space
    #define HE_DECL_SRV(T, N, slot) T N : register(t##slot)
    #define HE_DECL_UAV(T, N, slot) T N : register(u##slot)
    #define HE_DECL_CBUF(N, slot)   cbuffer N : register(b##slot)
    #define HE_DECL_CBV(T, N, slot) T N : register(b##slot)
    #define HE_DECL_SMP(T, N, slot) T N : register(s##slot)
#else
    // Vulkan / OpenGL(SPIR-V)：保持原有语义
    #define HE_DECL_SRV(T, N, slot) [[vk::binding(slot, 0)]] T N
    #define HE_DECL_UAV(T, N, slot) [[vk::binding(slot, 0)]] T N
    #define HE_DECL_CBUF(N, slot)   [[vk::binding(slot, 0)]] cbuffer N
    #define HE_DECL_CBV(T, N, slot) [[vk::binding(slot, 0)]] T N
    #define HE_DECL_SMP(T, N, slot) [[vk::binding(slot, 0)]] T N
#endif
```

调用点：

```slang
HE_DECL_SRV(StructuredBuffer<float>, u_Input, 0);
HE_DECL_UAV(RWStructuredBuffer<float>, u_Output, 1);
HE_DECL_CBUF(MyCB, 5) { MyCBData data; };
HE_DECL_SMP(SamplerState, u_Samp, 9);
```

实测展开结果（同一份源码，只换编译目标）：

| 目标 | 展开 |
|---|---|
| Vulkan | `[[vk::binding(0, 0)]] StructuredBuffer<float> u_Input` |
| D3D11 | `StructuredBuffer<float> u_Input : register(t0)` |
| D3D12 | `StructuredBuffer<float> u_Input : register(t0, space0)` |

**编号完全保留**，且引擎侧 396 处声明已全部改造，Vulkan 侧 20/20 逐字节一致。

## 3. 核心差异二：`space`（寄存器空间）

### 3.1 硬件/API 事实

| 目标 | `space` 支持 |
|---|---|
| Vulkan | ✅ 相当于 `descriptor set` |
| D3D12（SM5.1+） | ✅ |
| **D3D11（SM5.0）** | ❌ **不支持** |
| OpenGL（SPIR-V） | ❌ 无 `set` 语义 |

### 3.2 本引擎的实测分布

扫描全部 456 处绑定声明：

| space | 数量 | 分布 |
|---|---|---|
| 0 | 444 | 98 个文件 |
| 1 | 8 | **全部在 `RT_*.rchit.slang`**（光追） |
| 2 | 4 | **全部在 `RT_*.rchit.slang`**（光追） |

⇒ **非光追着色器的 space 恒为 0** ⇒ D3D11 侧可以直接省略 `space`，不会产生编号冲突。
⇒ 光追用 `HE_DECL_*_SP`（带 space 的变体），而光追本来就不参与 D3D11。

## 4. 核心差异三：资源数组的动态索引

### 4.1 规则

| 写法 | Vulkan | D3D11（SM5.0） |
|---|---|---|
| `Texture2D t[N]` 动态索引 | ✅ | ❌ |
| `StructuredBuffer b[N]` 动态索引 | ✅ | ❌ |
| `SamplerState s[N]` 动态索引 | ✅ | ❌（`X3512: sampler array index must be a literal`）|
| `Texture2DArray` 的动态 **slice** | ✅ | ✅（唯一例外） |
| **单个 `StructuredBuffer` 的动态元素索引** | ✅ | ✅（允许） |

### 4.2 引擎的 bindless 设计撞上了这条规则

引擎用 `u_Textures[]` / `u_Samplers[]` / `u_Materials[]` 这类**无界数组 + 运行时句柄**实现 bindless：

```slang
// 原本的写法（Vulkan 上工作良好）
float4 c = u_Textures[texBase + kGPUMaterialTexSlot_BaseColor].Sample(
               u_Samplers[texBase + kGPUMaterialTexSlot_BaseColor], uv);
```

D3D11 下这是非法的（数组本身动态索引）。

### 4.3 解法：把"访问"也宏化

```slang
// D3D11：固定槽位（每 draw 前由 C++ 把该材质的纹理绑到 t0..t3）
#define HE_MAT_TEX(slot)     u_Textures[(slot)]
#define HE_MAT_SMP(slot)     u_Samplers[(slot)]
#define HE_MAT_TEX_ANY(idx)  u_Textures[0]     // 运行时句柄退化到槽位 0
#define HE_MAT_SMP_ANY(idx)  u_Samplers[0]

// Vulkan：真正的 bindless（一次绑定全场景纹理，draw 只传 texBase）
#define HE_MAT_TEX(slot)     u_Textures[texBase + (slot)]
#define HE_MAT_SMP(slot)     u_Samplers[texBase + (slot)]
#define HE_MAT_TEX_ANY(idx)  u_Textures[(idx)]
#define HE_MAT_SMP_ANY(idx)  u_Samplers[(idx)]
```

调用点变成：

```slang
float4 c = HE_MAT_TEX(kGPUMaterialTexSlot_BaseColor).Sample(
               HE_MAT_SMP(kGPUMaterialTexSlot_BaseColor), uv);
```

⇒ **bindless 在 Vulkan 侧完好无损**，D3D11 侧走等价的固定槽位路径，源码只有一份。

### 4.4 bindless 缓冲的访问宏

```slang
// u_Instances[instanceBufferHandle][id.x] 这种"数组套缓冲"的写法
#define HE_BINDLESS_BUF(name, handle) name[0]        // D3D11
#define HE_BINDLESS_BUF(name, handle) name[(handle)] // Vulkan
```

```slang
// 声明：两个后端要不同的槽位号（见下节）
HE_DECL_SRV_BL2(StructuredBuffer<float4x4>, u_InstanceTransforms,   30, 30);
HE_DECL_SRV_BL2(StructuredBuffer<uint>,     u_VisibleInstanceIndices, 30, 31);
```

### 4.5 为什么需要 `BL2`（双槽位）宏

Vulkan 把所有 bindless SSBO 放在**同一个 binding 30**，靠句柄区分；
而 D3D11 每个 SRV/UAV 必须占**不同的寄存器槽**。

第一次实现时我给三个缓冲都用了 `t30`，报：

```
overlapping register semantics not yet implemented 't30'
```

⇒ 必须能分别指定两个后端的槽位：

```slang
#define HE_DECL_SRV_BL2(T, N, vkSlot, d3dSlot) \
    /* D3D11 */  T N[HE_BINDLESS_CAP] : register(t##d3dSlot)
    /* Vulkan */ [[vk::binding(vkSlot, 0)]] T N[]
```

## 5. 核心差异四：数组形态的语法位置

```slang
// 错误：数组括号跑到 register 后面
Texture2D<float4> u_Tex : register(t2)[4];   // ✗

// 正确：数组括号紧跟在名字后、register 之前
Texture2D<float4> u_Tex[4] : register(t2);   // ✓
```

⇒ 需要单独的数组宏：

```slang
#define HE_DECL_SRV_ARR(T, N, slot, cnt) T N[cnt] : register(t##slot)   // D3D11
#define HE_DECL_SRV_ARR(T, N, slot, cnt) [[vk::binding(slot, 0)]] T N[cnt] // Vulkan
```

无界的 bindless 数组同理，D3D11 用固定上限：

```slang
#define HE_BINDLESS_CAP 64
#define HE_DECL_SRV_BL(T, N, slot) T N[HE_BINDLESS_CAP] : register(t##slot)
```

## 6. 核心差异五：入口点命名与语义

### 6.1 入口点

| 文件后缀 | Slang 入口名 | 说明 |
|---|---|---|
| `*.vert.slang` | `vertexMain` | |
| `*.frag.slang` | `fragmentMain` | |
| `*.comp.slang` | `main` | |

CMake 生成 DXBC 时必须用正确的入口名，否则 `slangc` 报 "undefined identifier"。

### 6.2 HLSL 输出缺少语义（X3502 / X3503）

Slang 生成的 HLSL 里，入口结构体的成员**没有语义**：

```hlsl
struct FSInput_0
{
    float2 uv_0;      // ← 缺语义
};
float4 fragmentMain(FSInput_0 input_0) : SV_TARGET
```

D3DCompiler 报 `X3502: input parameter 'input_0' missing semantics`。

而 Slang 的语义命名也**不是** `[[vk::location(n)]]` 对应的 `TEXCOORDn`，而是它自己的 `VERTEX_IN_n`：

```
D3D11 ERROR: The provided input signature expects to read an element with
SemanticName/Index: 'VERTEX_IN_'/0, but the declaration doesn't provide a matching name.
```

### 6.3 解法

**输入布局**：不猜语义名，用 `D3DReflect` 从 DXBC 里**反射真实签名**再建布局，系统语义（`SV_VertexID`/`SV_InstanceID`）自动排除。

```cpp
D3DReflect(bc->dxbc.data(), ..., &refl);
refl->GetDesc(&sd);
for (UINT i = 0; i < sd.InputParameters; ++i) {
    refl->GetInputParameterDesc(i, &sp);
    if (sp.SystemValueType != D3D_NAME_UNDEFINED) continue;   // 跳过系统语义
    // 语义名/索引直接取自签名，格式按 ReadWriteMask 分量数推导
}
```

**输出/输入结构体语义**：在 `ShaderToDxbc` 工具里做"块级语义注入" —— 按入口签名涉及的结构体逐个补：

```cpp
// 第 1 个 float4 成员 → SV_Position（顶点输出的裁剪空间位置）
// 其余成员        → TEXCOORD0、TEXCOORD1…
```

注意 `SV_Position` **只能是 float4**，其它类型必须用 `TEXCOORD`，否则报 `Input signature parameter type must be float32`。

## 7. 核心差异六：编译器（D3DCompiler vs DXC）

| 项 | D3DCompiler (fxc) | DXC |
|---|---|---|
| 输出 | DXBC（SM5.0） | DXIL（SM6.0+） |
| D3D11 能否用 | ✅ | ❌ |
| D3D12 能否用 | 部分 | ✅ |

⇒ **D3D11 只能走 DXBC**，而 DXBC 只能由 fxc 生成。这带来三个 fxc 特有的限制：

| 限制 | 报错 | 应对 |
|---|---|---|
| 严格模式下强制展开带 `break` 的循环 | `X3511: unable to unroll loop` | 去掉 `D3DCOMPILE_ENABLE_STRICTNESS`；剥离 `[unroll]` |
| 动态边界的大循环也被尝试展开 | `X3511` | 给**不在其他循环内**的循环注入 `[loop]` |
| 嵌套循环加 `[loop]` | `X3531: can't unroll loops marked with loop attribute` | 只给最外层循环加 |
| 复杂控制流 + 密集 UAV 写入 | `internal error: flattened side effect`（**无行号**） | 目前**无解**，需重写 shader |

## 8. 各后端的绑定映射总表

| 后端 | SRV | UAV | CBV | Sampler | `space` | bindless 数组 |
|---|---|---|---|---|---|---|
| **Vulkan** | `[[vk::binding(n, s)]]` | 同 | 同 | 同 | ✅ (`set`) | ✅ 无界 `[]` |
| **OpenGL** | 同 Vulkan | 同 | 同 | 同 | ❌ 语义无效 | ✅（SPIR-V 同源） |
| **D3D11** | `: register(t<n>)` | `u` | `b` | `s` | ❌ | ❌ 退化固定槽位 |
| **D3D12** | `: register(t<n>, space<s>)` | 同 | 同 | 同 | ✅ | ✅ 可用描述符堆 |

## 10. 经验教训

| 教训 | 说明 |
|---|---|
| **Slang 的 `[[register]]` 是非法属性** | 只报警告、退出码 0，极易误判为"支持" |
| **`vk::binding` 对 D3D 目标完全无效** | 且不会报错，只是静默地自动编号 |
| **宏必须生成整条声明** | 因为两个后端的绑定语法位置相反（前置属性 vs 后置后缀） |
| **`space` 只在 SM5.1+ 存在** | 用实测数据（456 处扫描）确认可以安全省略 |
| **D3D11 的 bindless 不可实现** | 不是工作量问题，是 SM5.0 的硬限制 |
| **D3DCompiler 的 `X3511`/`X3531` 是矛盾的一对** | 加 `[loop]` 解决前者，但嵌套时会触发后者 |
| **`flattened side effect` 无解** | fxc 内部缺陷，关闭优化也失败，只能重写 shader |
