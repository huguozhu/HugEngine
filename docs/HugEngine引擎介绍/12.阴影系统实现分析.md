## 1. 结论速览

`Engine/Render/Shadow/` 共 13 个文件（`Engine/Render/CMakeLists.txt:119`–`:132`）：2 个接口头、1 组组合器
`.h/.cpp`、1 个空实现的头、4 个技术的 `.h/.cpp`。4 个技术共用同一对 SPIR-V（`CSMTechnique.cpp:71`–`:76`
等 4 处），差异全在采样端与投影构造上。

| 部件 | 现状 | 成色 / 边界 |
|---|---|---|
| `IShadowSystem` | 对外接口，继承 `IRenderSubsystem`，`Mode{None,Traditional,RayTraced}` | `Mode::RayTraced` **无实现**；`GetMode()` 恒返回 `Traditional`（`ShadowSystem.h:39`） |
| `IShadowTechnique` | 单技术接口：`CollectLights` + `Render` | 契约成立；`CreatePSO` **不在接口上**，靠 `dynamic_cast` 认领（§2.4） |
| `ShadowSystem` | 组合器：4 个技术、贴图索引聚合、`m_AllShadowData`/`m_AllEntities` | 成立；SSBO 只按 `MAX_SHADOWS` 条分配却按 `m_ActiveCount` 写（§10.1） |
| `ShadowNone` | Null Object | **全仓库零实例化**，只有 include（`ForwardPipeline.cpp:16`、`ForwardPipeline_FrameGraph.cpp:5`）+ 编译列表（§2.3） |
| `CSMTechnique` | 方向光 3 级联 ×2048² D32_FLOAT，λ=0.5 混合分割，正交拟合 | 成立；**只渲染第 1 条投影方向光**（§10.3） |
| `PointShadowTechnique` | 点光 512² Cubemap ×6 面，逐面渲染 | 成立；**单 tap 无 PCF**、无剔除、全引擎一张图（§4.4） |
| `SpotShadowTechnique` | 聚光 1024² 单张 2D，FOV=`outerConeAngle×2` | 成立；所有聚光共用一张图；Deferred 忽略 `shadowStrength`（§5.3） |
| `RectLightShadowTechnique` | 矩形光 1024²，FOV=90°，采样侧 5×5 | **Forward 分支不可达、Deferred 完全不接**（§6.3） |
| `Shadow.vert/frag.slang` | 只做位置变换 + 空片元着色器 | 4 个技术共用；深度由固定管线写（`Shadow.frag.slang:12`） |
| `PBR.frag.slang` | Forward 采样端：Dir/Spot/Rect/其余=点光 | Rect 分支被 `>1.5f` 先截获（`:155` vs `:170`） |
| `DeferredLighting.frag.slang` | Deferred 采样端：**只有** Dir 与 `>1.5f` 两支 | 点光（w=1）无分支、矩形光（w=3）落进 Spot 分支（§7.5） |
| Forward `Shadow` pass | 帧图第一段，写 3 张 CSM + 点光 Cubemap + `hdrDepth` 假依赖 | 由 `HasActiveShadows()` 门控（`ForwardPipeline_FrameGraph.cpp:53`） |
| Deferred `Shadow` pass | 写 3 张 CSM + 聚光图 + `gbDepth`/`gbWorldPos` 假依赖 | **无条件注册**；点光/矩形光图不进帧图（`DeferredPipeline_FrameGraph.cpp:187`–`:245`） |
| `GPUShadowData` | 256 B：`lightViewProj[3]` + 3 个 `float4` | `static_assert` 钉死（`Material.h:50`） |
| RT 阴影 | `RTShadowPass` + `RTEffectProvider`，R16_FLOAT 半分辨率遮罩 | 不进 GI 层栈（`RTProvider.h:83`–`:90`）；**只有 Deferred 消费** |
| 测试 | 无阴影专用用例；仅 `ShadowChannel` 谓词/降级单测 | 级联拟合与采样数学**零单测**（§11） |

## 2. 双层策略模式

### 2.1 外层：`IShadowSystem`

继承 `IRenderSubsystem`（`IShadowSystem.h:24`），与 GI/AA/后处理共享生命周期，另有三组专属契约：

- 每帧注入 `NextFrame()` / `SetRenderResources(objBuf, shadowBuf, descSet)`（`:35`–`:38`）；
- 贴图与索引 `GetShadowMapCount()` / `GetShadowMap(i)` / `GetShadowSampler()`（`:43`–`:47`）、 `GetShadowIndex(Entity)`（`:61`，`-1` = 不投影）；
- **按光源类型可选的访问器**：点光/聚光/矩形光各一对 `GetXxxShadowMap` + `GetXxxShadowSampler`， 默认 `nullptr`（`:51`–`:56`）。新增一类贴图不必改接口，覆写即可。

两个带默认实现的查询定义了整套门控语义：`WasShadowMapWritten(index)` 默认 `false`（`:77`），头注释把它定为「绑定方该不该用这张图」的**唯一真值**——`false` 时消费方必须绑占位纹理，否则采到未初始化显存，且这类故障"不报错、画面只是偏暗"（`:71`–`:76`）；`GetLightViewProj(cascade)` 默认单位阵（`:80`）。

### 2.2 内层：`IShadowTechnique`

9 个纯虚函数，三组（`IShadowTechnique.h:22`）：生命周期 `GetName/Initialize/Shutdown`（`:26`–`:30`）；每帧两段式 `CollectLights(world,sg,camera,outData,outEntities) -> u32`（`:38`–`:41`）与
`Render(cmd,world,sg,shadowData,dataStartIndex)`（`:44`–`:47`）；贴图访问 `GetShadowMapCount/GetShadowMap/
GetShadowSampler`（`:50`–`:52`）+ 可选`GetPointShadowMap/Sampler`（`:55`–`:56`）。

`SetRenderResources` 在技术侧只收 `objBuf` + `descSet`（`:33`–`:34`），阴影 SSBO 由组合器独占。
**分派键是"技术自己决定收哪些光源"**：各 `CollectLights` 内部各自 `world.ForEach<he::DirectionalLight>`/`<he::PointLight>`/`<he::SpotLight>`/`<he::RectLight>`（`CSMTechnique.cpp:124`、`PointShadowTechnique.cpp:85`、
`SpotShadowTechnique.cpp:87`、`RectLightShadowTechnique.cpp:86`），接口层完全不知道 CSM 与 Cubemap 的区别。

### 2.3 `ShadowNone`：Null Object（存在但从不出现）

全部纯虚函数为空操作或中性值（`ShadowNone.h:19`–`:42`）：`GetMode()=None`、`GetShadowMapCount()=0`、
`GetShadowMap/GetShadowSampler` 返回 `nullptr`、`GetShadowIndex` 返回 `-1`、`HasActiveShadows()=false`、
`IsEnabled()` 恒 `false`；设计意图是"避免 `ForwardPipeline` 里的 nullptr 检查"（`:10`–`:11`）。

但全仓库搜 `ShadowNone` 只命中类定义、两个 include（`ForwardPipeline.cpp:16`、
`ForwardPipeline_FrameGraph.cpp:5`）与 `CMakeLists.txt:122`，**没有任何实例化**；两条管线都直接造
`ShadowSystem`（`ForwardPipeline.cpp:90`、`DeferredPipeline.cpp:87`）。所以"关阴影"实际走的是三个下游条件：
`HasActiveShadows()`（`ShadowSystem.h:53` → `m_ActiveCount>0`）、调用方是否真的驱了 `Update`（§7.6）、
`WasShadowMapWritten`（`ShadowSystem.cpp:128`–`:139`）。`ShadowNone` 也不覆写 `WasShadowMapWritten`，
靠接口默认的 `false`（`IShadowSystem.h:77`）保持语义一致。

### 2.4 `ShadowSystem` 作为组合器

持有 `std::vector<std::unique_ptr<IShadowTechnique>> m_Techniques`（`ShadowSystem.h:58`），在 `Initialize`
里**按固定顺序**注册 CSM → Point → Spot → Rect（`ShadowSystem.cpp:16`–`:30`）。这个顺序是**索引空间的一部分**：

- **贴图索引**：4 个技术分别是 3/1/1/1，总数 6 ⇒ **0-2=CSM、3=点光、4=聚光、5=矩形光**。
 `GetShadowMapCount()` 求和（`:111`–`:113`），`GetShadowMap(i)` 按前缀偏移落到具体技术（`:115`–`:123`）。
 Deferred 帧图直接写 `GetShadowMap(4)` 并注释"Spot 阴影在索引 4"（`DeferredPipeline_FrameGraph.cpp:216`）。
- **数据索引**：`Update` 按同一顺序拼接 `m_AllShadowData`/`m_AllEntities`（`:78`–`:81`），
 `GetShadowIndex(Entity)` 在 `m_AllEntities` 里**线性查找**并返回下标，找不到返回 `-1`（`:176`–`:180`）。
- `WasShadowMapWritten(index)` 同用前缀偏移定位技术，再查该技术本帧收集数（`:128`–`:139`）。
 注释给出充分性论证："每个 Technique 的 `Render` 只遍历自己 `CollectLights` 收集到的那一段，
 因此『收集数 > 0』就是『它的图被写过』的充要条件"（`:125`–`:127`）——该论证在 §10.2 的越界遍历下不成立。

`GetShadowSampler()` 返回**第一个非空**采样器（`:141`–`:144`）；4 个技术的采样器参数完全相同
（Linear/Linear/ClampToEdge：`CSMTechnique.cpp:88`–`:92`、`PointShadowTechnique.cpp:49`–`:53`、
`SpotShadowTechnique.cpp:40`–`:44`、`RectLightShadowTechnique.cpp:39`–`:43`），聚合无副作用。
`CreateShadowPSO`（`:37`–`:45`）、聚光/矩形光访问（`:156`–`:174`）、`GetLightViewProj`（`:182`–`:188`）
四处用 `dynamic_cast`：4 个技术各自声明同名的**非虚** `CreatePSO`（`CSMTechnique.h:41`、
`PointShadowTechnique.h:43`、`SpotShadowTechnique.h:40`、`RectLightShadowTechnique.h:40`）。

### 2.5 每帧两段式

`Update(ctx)`（`ShadowSystem.cpp:68`–`:90`）：清空三个容器（`:74`–`:76`）→ 依次 `CollectLights`
把条目追加进共享 vector 并记段长（`:78`–`:81`）→ `m_ActiveCount = m_AllShadowData.size()`（`:83`）→
`Map()` 逐条上传（`:85`–`:89`）。`Render(cmd)`（`:96`–`:105`）用累计 `offset` 把"本技术那一段"
传给各技术，`offset += m_PerTechniqueCounts[i]`。世界与场景图经 `Update` 缓存的
`m_CachedWorld`/`m_CachedSceneGraph` 传下去（`ShadowSystem.h:70`–`:71`）。
`SetRenderResources` 把外部 SSBO 记在 `m_ExternalShadowBuffer`（`ShadowSystem.h:61`、`:59`–`:62`），
**只有 `Update` 写它**，技术侧看不到这个缓冲。

## 3. CSM（方向光级联阴影）

### 3.1 资源

分辨率 `kDefaultCSMShadowSize = 2048`（`CSMTechnique.h:10`），级联数
`CASCADE_COUNT = kGPUCascadeCount = 3`（`Material.h:47`、`ShaderTypes.slang:211`）。
3 张**独立 2D 纹理**：`D32_FLOAT`、`2048×2048`、`mipLevels=1`、`arrayLayers=1`、
`usage = DepthStencil|ShaderResource`（`CSMTechnique.cpp:77`–`:87`）。没用 Texture2DArray——
3 个 `unique_ptr<IRHITexture> m_ShadowMaps[3]`（`CSMTechnique.h:57`），因此 shader 侧是 3 个独立 binding
加 3 个独立采样分支（`pbr_common.slang:96`–`:108`）。采样器 `Linear/Linear/ClampToEdge`（`CSMTechnique.cpp:88`–`:92`），
**不设 `compareOp`**，shader 用 `.Sample()` 取深度后手动比较（`pbr_common.slang:99`），不是 comparison sampler。
PSO：`depthTest=depthWrite=true`、`depthCompare=LessEqual`、`depthFormat=D32_FLOAT`、
`colorAttachmentCount=0`、push constant `ShadowPushConstant`（`CSMTechnique.cpp:96`–`:116`），
大小 80 B（`Material.h:55`、`ShaderTypes.slang:339`–`:343`）。

### 3.2 级联划分

混合分割 λ=0.5，阴影距离硬性截到 120 m（`CSMTechnique.cpp:126`–`:137`）：
`shDist = min(cam.farPlane, 120)`（`:129`）、`la = 0.5f`（`:126`）、`p = (c+1)/CASCADE_COUNT`（`:131`）、
`ls = near·(shDist/near)^p`（`:132`）、`us = near + (shDist-near)·p`（`:133`）、
`splitDistances[c] = λ·ls + (1-λ)·us`（`:134`）、
`lightViewProj[c] = ComputeCascadeViewProj(ld, cam, c==0?near:splitDistances[c-1], splitDistances[c])`（`:135`）；
循环后 `splitDistances[3] = shDist`（`:137`）。即对第 $i$ 级（$i=1..N$，$N=3$）：

$$s_i = \lambda\, n\left(\frac{f}{n}\right)^{i/N} + (1-\lambda)\left(n + (f-n)\frac{i}{N}\right),\qquad \lambda = 0.5,\ f = \min(f_{far}, 120)$$

每帧只处理 `enabled && castShadow` 的方向光并受 `MAX_SHADOWS` 限制（`:125`）。
`splitDistances[3]`（`.w`）写入后在 CSM 路径上**无读取点**（采样端读 `splitDistances[2]`，
`pbr_common.slang:77`）——同一个字段在矩形光路径上被当作 `softness`（§6.1）。

### 3.3 投影矩阵拟合

`ComputeCascadeViewProj`（`CSMTechnique.cpp:21`–`:67`）把相机子视锥的 8 个角点装进一张正交投影：

1. 由相机前向/上向构造右向与上向，算近远平面半宽半高，得 8 个世界空间角点（`:23`–`:36`）；
2. **场景中心 = 8 角点平均**（注释："动态计算，替代硬编码"，`:38`–`:41`）：$c = \frac{1}{8}\sum_{k=0}^{7} p_k$；
3. 虚拟光源置于 $c$ 沿光线反向 **500 m** 处，`up` 在 $|\hat{d}_y| < 0.999$ 时取 $(0,1,0)$，否则 $(1,0,0)$（`:43`–`:45`）：

$$L = \mathrm{lookAtRH}\left(c - \hat{d}\cdot 500,\ c,\ u\right)$$

4. 把 8 角点变换到光视图空间取 XY 对称半宽，下限 5 m（`:47`–`:52`）：

$$h = \max\big(\max(-m_x, M_x),\ \max(-m_y, M_y)\big),\qquad h \leftarrow \max(h, 5)$$

5. 深度范围由光视图空间 z 跨度 ±50 m 余量定，并保证 $z_f > z_n$（`:54`–`:65`）：

$$z_n = \max(-M_z - 50,\ 0.1),\qquad z_f = \max(-m_z + 50,\ z_n + 1)$$

6. 组合（`:66`）：$V_c = O_{\mathrm{ZO}}(-h,\ h,\ -h,\ h,\ z_n,\ z_f)\cdot L$。

注意第 3 步把光源放在 500 m 外、第 5 步的裁剪面是在这个视图空间里算的，所以 $z_n \approx 450$、
$z_f \approx 550$（再减/加视锥沿光向的展布），深度跨度约 100 m + 2×展布；`:54`–`:56` 的注释把旧实现
（固定 `near=0.1/far=8000` 导致深度挤在 NDC 0.5 附近、bias 折算成 24 m、阴影被偏置吞掉）作为对照写着。
`m_LightVPs[c]` 在 `RenderCascade` 里缓存（`:156`），经 `CSMTechnique::GetLightViewProj`（`CSMTechnique.h:47`）
→ `ShadowSystem::GetLightViewProj`（`ShadowSystem.cpp:182`–`:188`）暴露；Forward 的 RSM 曾读它，现在改用自己按场景包围盒拟合的固定光锥（理由见 `PBR.frag.slang:210`–`:215`）。

### 3.4 渲染

`Render`（`:146`–`:153`）先对"`sd` 为空 / 外部对象缓冲或描述符集无效"早退，然后**只取 `sd[start]`**（`:149`），
对 3 个级联各调一次 `RenderCascade`，最后把 3 张图从 `DepthStencilRead` 转到 `ShaderResource`（`:150`–`:152`）。
`RenderCascade`（`:155`–`:204`）每次：清深度 1.0、`BeginOffscreenPass(nullptr, depthView, 2048, 2048, &cv)`、
**视口高度为负**（`{0,2048,2048,-2048,0,1}`，`:167`——采样端的 `0.5 - ndc.y*0.5` 正是补偿它，
`pbr_common.slang:88`）、绑 per-frame 描述符集（`:169`）、逐物体推
`ShadowPushConstant{lightViewProj=sd.lightViewProj[ci], objectIndex=oi++}`（`:187`–`:188`）。
物体来自三次 `ForEach`：`MeshComponent`/`CubeComponent`/`SphereComponent`（`:193`–`:195`），跳过 `castShadow==false`（`:174`，注释举例"光源可视化球"）与空索引物体，`oi >= MAX_OBJECTS` 即停止（`:173`）；顺带写物体的世界 AABB 进对象缓冲（`:176`–`:182`，注释：阴影路径自己不读，但同一元素会被别的消费者看到）。DrawCall 标记 `"Shadow C%u Obj#%u"`（`:184`–`:186`），首帧打印一次级联 0 的绘制物体数（`:197`–`:202`）。**阴影路径没有 CPU 侧视锥剔除**：`ForEach` 遍历世界全部网格，只按 `MAX_OBJECTS=1024` 截断（`ShaderTypes.slang:209`）；GPU 剔除（`m_GPUCulling`）只作用于 GBuffer 路径。着色器侧极简：`Shadow.vert.slang:31`–`:37` 用 `u_Objects[objectIndex].worldMatrix` 变换位置再乘
`lightViewProj`；`Shadow.frag.slang:12` 是空函数（无颜色附件，`depthWrite` 由固定管线完成）。

### 3.5 级联选择与 PCF

采样端是 `pbr_common.slang:67`–`:110` 的 `SampleShadowPCF`（Forward/Deferred 共用）：
`viewZ = dot(worldPos - cameraPos, sm.cameraForward.xyz)`（`:75`）；`viewZ > splitDistances[2]` 直接返回 1.0
（`:77`–`:78`，注释：超出阴影距离采 clear 值会造成方形暗区）；级联选择是三次比较的**硬切换**（`:79`–`:81`）；`biasedPos = worldPos + worldNormal * shadowParams.y`（`:84`）；投影后
`uv = (ndc.x*0.5+0.5, 0.5-ndc.y*0.5)`（`:88`）、`depth = ndc.z - shadowParams.x`（`:89`）；
UV 出界返回 1.0（`:91`–`:92`）；`texelSize = 1/2048`（`:94`）；按 cascade 选 3 个分支之一做
**3×3 = 9 tap** 并 `/9.0`（`:96`–`:109`）。

要点与边界：**没有任何级联混合带**（全仓库搜 `CascadeBlend`/混合带零命中，唯一出现
"cascade blending artifacts" 字样的是 `RTShadowPass.h:15` 的 RT 优势说明）；PCF 步长 `1/2048` 是 shader
字面量，与 `kDefaultCSMShadowSize` 是**两份独立常量**，改分辨率必须改两处；两个 bias 走两条独立路径——
`shadowParams.x` 从比较深度里减（`:89`），`shadowParams.y` 加在世界位置沿法线方向（`:84`），
来自 `LightComponent.h:44`–`:45`。

### 3.6 已知限制（CSM 特有）

- **只渲染第一条投影方向光**：`Render` 取 `sd[start]`（`:149`），而 `CollectLights` 会把每条投影方向光 都追加进 `m_AllShadowData` 并各返回一个 `shadowIndex`（`:124`–`:143`）。第 2 条起的投影方向光会拿 **自己的 VP + 别人的深度图**，且不报错（§10.3）。
- Deferred 逐张按 `WasShadowMapWritten(0/1/2)` 门控（`DeferredPipeline_FrameGraph.cpp:1407`–`:1409` → `:1403`–`:1406`），三个索引全落在 CSM 技术上，判据等价于"本帧有投影方向光"。
- Forward **不使用** `WasShadowMapWritten`：3 张 CSM 在 `Initialize` 时一次性绑进描述符集 （`ForwardPipeline.cpp:209`–`:214`），之后不再更新，因此没有"没产出就绑占位"的门控。

## 4. 点光阴影

### 4.1 资源

`kDefaultPointShadowSize = 512`（`PointShadowTechnique.h:10`）。单张 Cubemap 深度图：`D32_FLOAT`、
`512×512`、`mipLevels=1`、`arrayLayers = rhi::kCubemapFaceCount`（=6，`ShaderTypes.slang:199`）、
`usage = DepthStencil|ShaderResource|Cubemap`（`PointShadowTechnique.cpp:35`–`:48`）。`:41`–`:45` 记录了
`arrayLayers=6` 的由来：曾写成 1 层而描述符按 cubemap 采样整张，层 1..5 一直 UNDEFINED，
校验层报 `VK_IMAGE_LAYOUT_DEPTH_STENCIL_READ_ONLY_OPTIMAL` 的 arrayLayer 不匹配。面朝向表 `kCubeFaces[6]`（`:22`–`:25`）：face 0 `dir=+X,up=-Y`；1 `-X,-Y`；2 `+Y,+Z`；3 `-Y,-Z`；4 `+Z,-Y`；5 `-Z,-Y`。

### 4.2 收集与渲染

`CollectLights`（`:82`–`:94`）对每个 `enabled && castShadow` 的点光产出**一条**数据：
位置与范围进 `pointLightData = float4(worldPos, range)`（`:88`），
`shadowParams = float4(bias, normalBias, strength, 1)`——**`.w = 1` 就是"点光"的类型编码**（`:89`）。
`Render`（`:96`–`:147`）：进面循环前先把整张 cubemap 从 `Undefined` 转到 `DepthStencilRead`
（`:99`–`:104`，注释：首帧光照 pass 可能就要采样它）；逐光源（上限 `MAX_SHADOWS`）
`proj = perspectiveRH_ZO(90°, 1, 0.1, range)`（`:108`），逐面 `view = lookAtRH(lp, lp+dir, up)`（`:110`）、
`vp = proj*view`（`:125`）；**视口高度为正**（`{0,0,512,512,0,1}`，`:121`），注释说明点光用方向向量采样
cubemap、无 y 补偿，负高度视口会让深度图上下颠倒（`:117`–`:120`）——与其余三个技术的负高度视口相反；
每面一次 `BeginOffscreenPass`，物体遍历规则与 CSM 相同（`:126`–`:141`）；每面渲染完立刻转 `ShaderResource`
（`:143`–`:144`）。

### 4.3 采样

`SamplePointShadow`（`pbr_common.slang:118`–`:144`）是**单次采样**，无 PCF：`dist > range` 返回 1.0
（`:127`–`:128`）；方向向量直接作 cubemap 坐标取深度（`:131`）；因贴图深度是透视深度（$n=0.1$、$f=$`range`，非线性），先反算线性距离（`:136`–`:140`）：

$$z_{lin} = \frac{n f}{f - z\,(f - n)},\qquad n = 0.1,\ f = \text{range}$$

最后在**归一化空间**比较并减 bias（`:143`）：`normalizedDist = dist/range`，判据
`normalizedDist - bias <= z_lin/range`。注意 `shadowNormalBias`（`shadowParams.y`）在此路径上
**无读取点**，只有 `shadowParams.x` 生效。

### 4.4 已实现 / 缺失清单

| 项 | 状态 | 证据 |
|---|---|---|
| Cubemap 深度阴影、90° FOV、逐面渲染 | 已实现 | `PointShadowTechnique.cpp:108`–`:110` |
| 6 层 array 创建与屏障 | 已实现 | `:46`、`:103`–`:104`、`:143`–`:144` |
| `castShadow` 剔除、`MAX_OBJECTS` 截断 | 已实现 | `:128`、`:127` |
| **PCF / 任何多 tap 过滤** | **缺失**（单 tap，无软阴影） | `pbr_common.slang:131`、`:143` |
| **`shadowNormalBias`** | **不生效** | 只读 `shadowParams.x`（`pbr_common.slang:143`） |
| **面级/视锥剔除** | **缺失**——6 面无条件全渲 | `:109` 循环无提前退出 |
| **多光源** | **缺失**——单张 cubemap，后面的投影点光覆盖前面的 | `.h:48`；`.cpp:105` 顺序覆写同一张 |
| Deferred 采样 | **缺失**——无 cubemap 绑定与分支 | §7.5 |

## 5. 聚光阴影

### 5.1 资源与投影

`kDefaultSpotShadowSize = 1024`（`SpotShadowTechnique.h:10`），单张 2D `D32_FLOAT`、`arrayLayers=1`、
`DepthStencil|ShaderResource`（`SpotShadowTechnique.cpp:29`–`:38`）。投影 FOV = `outerConeAngle × 2`：

$$P_{spot} = \mathrm{perspectiveRH}_{\mathrm{ZO}}\big(2\,\theta_{outer},\ 1,\ 0.1,\ \max(r, 0.2)\big)$$

（`:91`–`:92`）。`lookAtRH` 的 `up` 有平行保护（$|dir_y| < 0.999$ 时用 $(0,1,0)$，否则 $(1,0,0)$，`:93`–`:95`），
`lightViewProj[0] = proj*view`（`:97`）。同时把原始量塞进别的字段供 `Render` 重建：
`pointLightData=(pos,range)`、`splitDistances=(dir, outerConeAngle)`、`shadowParams.w=2`（"聚光"编码，`:98`–`:100`）；
`Render` **重算一遍 VP**（`:117`–`:121`）并把 `lightViewProj[0]` 那份作 push constant 用（`:121`）。

### 5.2 渲染与采样

循环与 CSM 同构：负高度视口（`:128`）、清深度 1.0、`BeginOffscreenPass`、逐物体 push `lightViewProj=vp`、三类物体遍历、`EndOffscreenPass` 后做 `DepthStencilRead → DepthStencilRead` 屏障（`:152`–`:153`）；
`srcState` 必须写 `DepthStencilRead` 而非 `Write`，注释给出 VUID 依据（`:149`–`:151`）。
采样端（`DeferredLighting.frag.slang:350`–`:363`、`PBR.frag.slang:155`–`:169`）：世界位置按法线偏移
`shadowParams.y` → 投影 → UV 用 `0.5 - ndc.y*0.5`（与负高度视口对应）→ `spotZ = ndc.z - shadowParams.x` →
UV 在 `(0,1)` 内才采样、**PCF 3×3**、步长硬编码 `1/1024`（`DeferredLighting.frag.slang:356`、
`PBR.frag.slang:161`）、结果 `/9.0`。

**`shadowStrength` 两条管线行为不一致**：`PBR.frag.slang:169` 在聚光分支末尾有
`shadow = lerp(1.0, shadow, sm.shadowParams.z)`，而 `DeferredLighting.frag.slang:350`–`:363` 的聚光分支
**没有**（同文件方向光分支 `:348`–`:349` 有）——Deferred 下聚光灯的 `shadowStrength` 不生效。

### 5.3 已知限制

- **多聚光共用一张图**：`m_SpotShadowMap` 只有一张（`.h:45`），`Render` 逐光源写入同一张 （`:110` 循环内 `BeginOffscreenPass` 用同一 `depthView`），故只有**最后一个**投影聚光灯的深度留在图里； 先前的光源 `shadowIndex` 仍在，于是用**自己的 VP 采别人的图**。此时 `WasShadowMapWritten` 的"收集数 > 0"判据依旧为真。
- `CollectLights` 对 `up` 做了平行保护（`:94`），`Render` 重建 VP 时**没有**——`dir ≈ ±Y` 时 `lookAtRH(lp, lp+dir, (0,1,0))` 退化（`:120`），两处 VP 可能不一致。
- 阴影距离用 `max(range, 0.2)`，即阴影图覆盖整个影响范围，没有独立的"只在近处投影"的距离参数。

## 6. 矩形光阴影

### 6.1 技术与现状

`RectLightShadowTechnique`（`RectLightShadowTechnique.h:18`）是唯一标注"Phase 2"的技术（`.h:13`）。
资源与聚光同形：单张 `1024²` `D32_FLOAT`（`.h:10`、`.cpp:29`–`:38`），采样器同参数（`:39`–`:43`）。
`CollectLights`（`:83`–`:109`）遍历 `he::RectLight`，取世界位置与**发光面法线**（`:88`–`:89`）；
投影 FOV 固定 **90°**（`glm::radians(90.0f)`，`:92`）：

$$P_{rect} = \mathrm{perspectiveRH}_{\mathrm{ZO}}\big(\pi/2,\ 1,\ 0.1,\ \max(r, 0.2)\big)$$

（`:92`–`:93`）注释说明这里从"矩形对角/range 的窄锥（~17°）"改成宽锥，因为遮挡物偏离法线就落不进视锥、渲染不到、无阴影（`:90`–`:91`）。`up` 有平行保护（`:94`–`:96`），`lightViewProj[0] = proj*view`（`:99`）。字段复用：`pointLightData=(pos,range)`、`shadowParams.w=3`（"矩形光"编码，`:101`）、
`splitDistances = float4(normal, softness)`（`:102`–`:104`；注释写"存 法线 + 宽/高"，实际 `.w` 是 `softness`）。
`Render`（`:111`–`:155`）**直接复用** `CollectLights` 存好的 `lightViewProj[0]` 而不重建（`:120`–`:121`），
其余与聚光相同（负高度视口 `:128`、末尾屏障 `:152`–`:153`）。

### 6.2 采样侧

矩形光分支在 `PBR.frag.slang:170`–`:185`，是唯一用 **5×5 核**的路径：法线偏移后用 `lightViewProj[0]` 投影（`:172`）；`softness = sm.splitDistances.w`（`:176`）；步长随 softness 放大$t_s = \frac{1}{1024}(1 + 4\,s_{soft})$（`:177`）；5×5 共 25 tap、结果 `/25.0`（`:180`–`:183`）；最后按 `shadowStrength` 做 `lerp`（`:185`）。`softness` 默认 0.5（`LightComponent.h:91`），所以默认步长是 `5×1/1024`——**矩形光是唯一"天生软"的阴影路径**，代价是 25 次采样。

### 6.3 已知边界（矩形光特有）

1. **Forward 的矩形分支不可达**：分支顺序是 `w < 0.5` → `w > 1.5` → `w > 2.5`（`PBR.frag.slang:149`、 `:155`、`:170`），矩形光的 `w = 3.0` 先命中 `> 1.5` 的聚光分支，于是永远走不到 `:170` 的 5×5 分支， 而是用 `u_SpotShadowMap`（`:166`）配 `1/1024` 的 3×3 核。
2. **Deferred 完全不接矩形光阴影**：`DeferredLighting.frag.slang` 既无 `u_RectShadowMap` 绑定也无 `ltype == 3` 处理；`DeferredPipeline::CollectLights` 甚至**只遍历 Directional/Point/Spot** （`DeferredPipeline.cpp:870`–`:872`），所以矩形光在 Deferred 下连直接光都没有。 全仓库 `GetRectShadowMap` 只有定义（`ShadowSystem.cpp:166`–`:169`）与一个绑定点（`ForwardPipeline.cpp:247`）。
3. **矩形光仍会写阴影图**：该技术在 `Initialize` 里被无条件注册（`ShadowSystem.cpp:28`–`:30`）， 所以有投影矩形光时 Deferred 会**渲染一张没人采样的图**（帧图也不声明它，§7.4）。

## 7. 阴影数据流

### 7.1 光源组件 → `GPUShadowData`

组件侧 6 个阴影字段（`Engine/Scene/Scene/LightComponent.h:42`–`:47`）：`castShadow`（默认 `false`）、
`shadowMapSize`（`kDefaultShadowMapSize`）、`shadowBias`（0.005）、`shadowNormalBias`（0.02）、
`shadowStrength`（1.0）、`shadowRadius`（0.0）。其中**两个在光栅阴影路径上无读取点**：
`shadowMapSize`（4 个技术各用 `constexpr` 与 `m_ShadowMapSize`/`m_MapSize` 成员，不从组件读）、
`shadowRadius`（只在 RT 侧被读：`RTShadowPass.cpp:208`、`PathTracingPipeline.cpp:290`）。

`GPUShadowData` 布局（`ShaderTypes.slang:257`–`:263`，256 B，`Material.h:50` 钉死）：

| 偏移 | 字段 | 语义 |
|---|---|---|
| 0..192 | `float4x4 lightViewProj[3]` | CSM 3 级联 VP；点/聚光/矩形光只用 `[0]` |
| 192..208 | `float4 shadowParams` | `x=bias, y=normalBias, z=strength, w=类型`（0=Dir,1=Point,2=Spot,3=Rect） |
| 208..224 | `float4 splitDistances` | CSM 分割点；Spot：`xyz=方向, w=外锥角`；Rect：`xyz=法线, w=softness` |
| 224..240 | `float4 cameraForward` | CSM 级联选择用（只有 CSM 写，`CSMTechnique.cpp:138`） |
| 240..256 | `float4 pointLightData` | `xyz=世界位置, w=范围`（点/聚光/矩形光写） |

`w` 的类型编码是**跨 C++/shader 的裸数字**：4 个技术分别在 `CSMTechnique.cpp:139`（0）、
`PointShadowTechnique.cpp:89`（1）、`SpotShadowTechnique.cpp:99`（2）、`RectLightShadowTechnique.cpp:101`（3）
写入，由着色器的 `w < 0.5` / `w > 1.5` / `w > 2.5` 消费（`PBR.frag.slang:149`、`:155`、`:170`）；
`ShaderTypes.slang:259` 只有注释，**没有共享常量**。

### 7.2 索引分配、上限与光源侧字段

`Update` 按注册顺序拼接 4 段（`ShadowSystem.cpp:78`–`:81`），`GetShadowIndex` 在 `m_AllEntities` 里线性查找
（`:176`–`:180`）。每个技术的 `CollectLights` 各自限制"自己那一段"不超过 `MAX_SHADOWS`
（`CSMTechnique.cpp:125`、`PointShadowTechnique.cpp:86`、`SpotShadowTechnique.cpp:88`、
`RectLightShadowTechnique.cpp:87`）。`MAX_SHADOWS = kGPUMaxShadows = 4`（`Material.h:43`、`ShaderTypes.slang:208`）
是**逐技术上限而非总数上限**：`m_ActiveCount` 的理论上限是 $4\times4=16$，而这个 16 是推导值，代码里没有任何断言或 clamp 表达它（§10.1）。

`GPULight.shadowIndex`（`ShaderTypes.slang:252`，`-1` = 不投影）由两条管线收集光源时填
（`DeferredPipeline.cpp:825`、`ForwardPipeline.cpp:570`），两处都对**所有**光源无差别调用
`m_ShadowSystem->GetShadowIndex(e)`；是否投影由"是否在 `m_AllEntities` 里"决定。

### 7.4 帧图接线与执行顺序

**Forward**（`ForwardPipeline_FrameGraph.cpp:51`–`:96`）：门控 `m_ShadowSystem && HasActiveShadows()`（`:53`）；声明写入 3 张 CSM（`:67`–`:69`）+ 点光 Cubemap（`:72`–`:75`）+ `hdrDepth`（`:78`，注释"WAW 依赖：确保 Shadow → FullScene 的执行顺序"），pass 名 `"Shadow"`；pass 体内把 binding 2（`kBindingObjectData`）临时换成阴影专用对象缓冲（`:85`–`:87`），调 `Render`，再换回（`:92`–`:94`）。它是帧图第一段 pass，后面依次是 IBL（`:98`）、RSM（`:126`）、Forward+ 光源剔除（`:160`）。

**Deferred**（`DeferredPipeline_FrameGraph.cpp:187`–`:245`）：位于 GPU 剔除之后、Nanite 接入点与 `GB_Clear`之前，分两段——① `SetRenderResources` + `Update` 在**帧图构建期**执行（`:192`–`:201`，注释"必须在 GBuffer之前……收集光源 → 填充 `GPUShadowData`（光源 VP 矩阵）"）；② 导入贴图：CSM 0..2 逐个
`rg.ImportTexture("CSM_Shadow_C%u", tex)`（`:205`–`:215`）、`GetShadowMap(4)` → `"SpotShadow"`（`:216`–`:217`），
**点光（索引 3）与矩形光（索引 5）不导入**；③ pass 声明写入 3 张 CSM + 聚光图（`:221`–`:225`）+ `gbDepth`/
`gbWorldPos` 两条 WAW 假依赖（`:226`–`:228`）；④ pass 体内换对象缓冲（`:234`–`:236`）→ `Render(c)`（`:238`）
→ 换回（`:241`–`:243`）。这条 WAW 依赖被 Nanite 接入点当成硬约束对待：深度的声明必须保持 `Write`（`:303`–`:304`，"它是 `Shadow` 那条 WAW 假依赖的一半"）。

### 7.5 采样端：两条管线的差异

| | Forward（`PBR.frag.slang`） | Deferred（`DeferredLighting.frag.slang`） |
|---|---|---|
| 遍历 | `ShadeWithLight(GPULight, …)` 逐光源，一函数兼容传统/Forward+（`:105`） | 两段循环：Clustered（`:304`–`:367`）与线性回退（`:368`–） |
| 点光 Cubemap 绑定 | 有（`:50`–`:51`，binding 9） | **无** |
| 矩形光图绑定 | 有（`:54`–`:55`，binding 25） | **无** |

| 点光 Cubemap | ✅（单 tap） | ❌ **无分支、无纹理** |
| 聚光 2D | ✅（3×3） | ✅（3×3，忽略 `shadowStrength`） |
| 矩形光 | ⚠️ 走聚光分支采聚光图（§6.3） | ❌ 连直接光都没有（§6.3） |

### 7.6 谁负责驱动 `Update`

`ShadowSystem::Update` **不是**管线内部自动调的：Deferred 在帧图构建期自己调
（`DeferredPipeline_FrameGraph.cpp:201`）；Forward **要求调用方先调** `SetRenderResources` + `Update`，
否则 `HasActiveShadows()` 恒 `false`、`Shadow` pass 根本不注册——这条约束写在
`ForwardPipeline_FrameGraph.cpp:128`–`:131` 的注释里（原文列举 `02.Cube`/`03.Sponza-Forward`/`AISamples`
都这么做，而 `06.GILab` 曾漏掉）。样例侧确实是手写的：`Samples/02.Cube/02.Cube.cpp:1230`–`:1243`、
`Samples/03.Sponza-Forward/03.Sponza-Forward.cpp:679`–`:680`、`Samples/07.AISamples/AISamples.cpp:172`–`:178`、
`Samples/06.GILab/06.GILab.cpp:933`–`:945`、`Samples/07.Nanite/07.Nanite.cpp:1056`–`:1068`；
非 RG 路径（`ForwardPipeline.cpp:967`–`:984`）同样只调 `Render(cmd)`，不调 `Update`。
`ShadowSystem::NextFrame()`（`ShadowSystem.cpp:55`）推进 `m_CurrentFrameSlot`（`ShadowSystem.h:68`），
但该成员在 `ShadowSystem` 内**再无读取点**——三缓冲是管线自己的事（`m_ShadowBuffers[slot]`/
`m_ShadowObjBuffers[slot]`），槽位同步由 `ForwardPipeline::NextFrame`（`ForwardPipeline.cpp:532`）调这一句完成。
`SceneRenderer`（`Engine/Render/SceneRenderer.{h,cpp}`）**没有任何 shadow 相关代码**（grep `[Ss]hadow` 零命中）：

## 8. 与 RT 阴影的切换关系

### 8.1 `ShadowChannel`：独立枚举，不进 GI 层栈

阴影在配置模型里是与三个 GI 层栈（`diffuse`/`specular`/`ao`）平级但互不隶属的**独立枚举**
（`GITypes.h:33`、`:450`–`:455`）：`enum class ShadowChannel : u8 { None = 0, Raster, RT }`，
默认 `Raster`（`:455`）。派生谓词（`:482`–`:483`）：`ShouldRunShadow()` = `shadow != None`；
`ShouldRunRTShadow()` = `shadow == RT`。RT 阴影被算进 `AnyRTSource()`（决定要不要建 TLAS，`:485`–`:487`），
但 `RTEffectProvider` 对阴影效果 `GetSourceId()` 返回 `GISourceId::None`、`NeedsPass` 改读 `m_RTShadowWanted`（`RTProvider.h:83`–`:90`、`:95`–`:99`）；头注释写明理由："RT 阴影不属于三个层栈通道（阴影是独立枚举）→ 覆写 NeedsPass 判断"（`:12`）。串成闭环的是 `DeferredPipeline_FrameGraph.cpp:1161`（`rtp->SetRTShadowWanted(m_GIConfig.ShouldRunRTShadow())`）与不满足 RT 条件时的清零分支（`:1231`–`:1241`）。设备能力与降级：`GIRegistry::IsAvailable(RT, caps, rtSupported)` 要求设备支持光追（`GITypes.h:626`–`:631`）；Ultra 档选 RT（`:528`）、RT 不可用回退 `Raster`、管线不支持光栅阴影再回退 `None`（`:664`–`:670`）；这些谓词与降级都有单测（`Tests/TestGITypes.cpp:190`–`:193`、`:364`–`:379`、`:518`–`:522`、`:533`、`:562`）。

### 8.2 `rtShadowSource` 的语义

`DeferredLightingPushConstant.rtShadowSource`（`ShaderTypes.slang:368`）由**纹理是否绑定**推导，
不是直接读配置（`LightingPass.cpp:180`）：`lpc.rtShadowSource = in.rtShadowMask ? 1u : 0u;`。
`in.rtShadowMask` 只在 Deferred 帧图里、且 RT 阴影 pass 真的注册时非空
（`DeferredPipeline_FrameGraph.cpp:1226` 记录输出、`:1477` 才赋值给 `in.rtShadowMask`），否则 `LightingPass` 回绑白色占位（`LightingPass.cpp:129`）——白色占位在这条路上同时承担"没产出"与"无阴影"两个含义。着色器侧两条消费路径：全屏因子
`rtShadowFactor = (rtShadowSource != 0) ? u_RT_ShadowMask.Sample(...).r : 1.0`（`DeferredLighting.frag.slang:300`–`:301`）；
逐光源分支被整体短路 `if (light.shadowIndex >= 0 && rtShadowSource == 0u)`（`:344`、`:392`）；
最后 `color *= rtShadowFactor`（`:415`–`:416`）。

### 8.3 全屏乘积 vs 逐光源 PCF 的差异

| | 光栅（`rtShadowSource == 0`） | RT（`rtShadowSource == 1`） |
|---|---|---|
| 作用位置 | 逐光源：`color += BRDF(...) * radiance * shadow`（`:366`、`:411`） | 全屏一次：直接光结算**之后**整体乘（`:415`–`:416`） |
| 粒度 | 每盏灯一个可见度 | 一个像素一个因子，**所有阴影光源共用**；RT pass 内部按光源数组逐光源发线（`RTShadowPass.cpp:200`–`:209`） |
| 覆盖的灯 | 只有 `shadowIndex >= 0` 的灯 | 全部像素，`shadowIndex < 0` 的灯的直接光也一起被乘 |
| 噪声特征 | 无噪声，硬边 + 3×3/5×5 PCF | 射线估计，走 `RTDenoiser`（时域）+ 可选 `DenoiseUpscale`；链尾输出经 `GetShadowOutput() → FinalOutput()`（`RTProvider.h:128`–`:131`、`:343`–`:353`） |
| 强度控制 | `shadowStrength`（CSM/点/矩形；Deferred 聚光除外） | 无逐灯强度：`RTShadowPushConstant` 只有 `maxShadowDist`/`shadowFlags`/`softSPP`/`lightCount`（`ShaderTypes.slang:379`–`:389`） |

RT 侧量化参数（`RTShadowPass.cpp:167`–`:177`）：`maxShadowDist` 取 `cvRTShadowMaxDist`（默认 200，
`RTQualityCVars.cpp:22`）；`softSPP` 取 `cvRTShadowSPP` 并 clamp 到 1..16（默认 4，`RTQualityCVars.cpp:25`）；
`shadowFlags` 的 bit1 = 半分辨率（`m_HalfRes`）、bit2 = 软阴影（`cvRTShadowSoft` 默认 `false`，
`RTQualityCVars.cpp:24`）。输出 `R16_FLOAT`（`RTShadowPass.cpp:127`），默认半分辨率
（`RTShadowPass.h:33`、`:50`）；光源上限 `kShadowMaxLights = 16`（`:39`），每灯 64 B 的 `ShadowLightGPU`（`:31`–`:37`，`static_assert` 在 `:37`）。

### 8.4 切换时**不会**发生的事

`ShouldRunShadow()` / `ShouldRunRTShadow()` 在引擎侧几乎没有调用点（grep 全仓库：`ShouldRunShadow`
只出现在 `GITypes.h:482` 的定义与 `Tests/TestGITypes.cpp` 的断言；`ShouldRunRTShadow` 多一处调用点
`DeferredPipeline_FrameGraph.cpp:1161`）。于是：

- `ShadowChannel::None` **不会**关掉光栅阴影：两个帧图的 `"Shadow"` pass 注册条件分别是 `HasActiveShadows()`（Forward，`ForwardPipeline_FrameGraph.cpp:53`）与无条件（Deferred， `DeferredPipeline_FrameGraph.cpp:187`），都与 `shadow` 枚举无关；真正决定"有没有阴影"的是 `castShadow` 与调用方是否驱动 `Update`（§7.6）。
- `ShadowChannel::RT` **不会**停掉 CSM 渲染：Deferred 照旧渲染 3 张 CSM + 聚光图（`:230`–`:244`）， 只是着色器因 `rtShadowSource == 1` 不再采它们（`:344`）。
- Forward **完全没有** RT 阴影接线（`ForwardPipeline*.cpp` 里 grep `rtShadow`/`RTEffectProvider` 零命中）， 故 Forward 下 `shadow = RT` 只影响是否需要 TLAS，画面差异未实测（§11.6）。

## 10. 已知边界与未实现

### 10.1 阴影 SSBO 容量与写入量不匹配（索引越界）

两条管线都按**一个技术**的容量分配阴影 SSBO：`sizeof(GPUShadowData) * MAX_SHADOWS` = 256 × 4 = **1024 B**（`DeferredPipeline.cpp:82`、`ForwardPipeline.cpp:139`–`:142`）；而 `ShadowSystem::Update` 写的是**全部技术之和**：`m_ActiveCount = m_AllShadowData.size()`（`ShadowSystem.cpp:83`），上限 4 技术 × `MAX_SHADOWS` = **16 条 = 4096 B**（逐技术上限见 `CSMTechnique.cpp:125`、`PointShadowTechnique.cpp:86`、
`SpotShadowTechnique.cpp:88`、`RectLightShadowTechnique.cpp:87`）。写入循环
`for (u32 i = 0; i < m_ActiveCount; ++i) dst[i] = m_AllShadowData[i];`（`ShadowSystem.cpp:87`）
**没有与缓冲容量比较**，`Update` 里也没有任何 clamp 或 `HE_ASSERT`。例如"1 投影方向光 + 1 投影点光 + 1 投影聚光 + 2 投影矩形光"即 5 条 = 1280 B > 1024 B。`Buffer::Map()` 返回 VMA 持久映射指针（`Engine/RHI/Vulkan/VulkanResources.cpp:179`–`:189` 返回 `m_MappedPtr`），越界写入落在 VMA 子分配区内部，运行时后果取决于相邻分配（本次未复现，§11.1）。shader 侧同样少一道边界：`u_ShadowData[light.shadowIndex]`直接索引（`PBR.frag.slang:148`、`DeferredLighting.frag.slang:345`、`:393`），没有任何相对 `MAX_SHADOWS`的检查（`ShaderTypes.slang:252` 只注释了 `-1` 的含义）。

### 10.2 索引范围隔离缺失（技术之间的"越界遍历"）

`ShadowSystem::Render` 传给每个技术的 `dataStartIndex` 是前缀偏移（`ShadowSystem.cpp:100`–`:104`），
但**没有传"本段长度"**；三个多光源技术的循环条件都写成 `li < sd.size() && li - start < MAX_SHADOWS`
（`PointShadowTechnique.cpp:105`、`SpotShadowTechnique.cpp:110`、`RectLightShadowTechnique.cpp:114`）。
只要**后面**的技术收集到了光源，前面的技术在本段为空时仍会渲染"别人的那一段"（最多 `MAX_SHADOWS` 条）。
具体后果举例：聚光收集 0 条、矩形光收集 1 条时，`SpotShadowTechnique::Render` 会把矩形光那条数据
当聚光来重建 VP（`:114`–`:119` 读 `splitDistances.xyz` 当方向、`splitDistances.w`（= 矩形光的 `softness`）
当外锥角）并写进聚光图。这也与 `WasShadowMapWritten` 的论证冲突（`ShadowSystem.cpp:125`–`:127`）：
上例中聚光收集数为 0（`WasShadowMapWritten(4) == false`，Deferred 不绑它），但聚光图**确实被写过**。
反方向（收集数 > 0 ⇒ 图被写）这一半是稳的。

### 10.3 CSM 只渲染第一条投影方向光

`CSMTechnique::Render` 取 `sd[start]`（`:149`），而 `CollectLights` 会把每条投影方向光都追加进
`m_AllShadowData`（`:124`–`:143`）。多于一条时：3 张级联图里是第 1 条光的深度，第 2 条光却按自己的
`lightViewProj`/`cameraForward`/`splitDistances` 去采样（索引由 `GetShadowIndex` 给出），
阴影位置与遮挡关系都不对，且**不报错**。

### 10.4 点光阴影无 PCF、无剔除、单张图

见 §4.4 的清单：单 tap（`pbr_common.slang:131`）、`shadowNormalBias` 不生效、6 面无条件全渲（`PointShadowTechnique.cpp:109`）、单张 cubemap 逐光源覆写（`.h:48`、`.cpp:105`）、视口约定与其余三个技术相反（`.cpp:121` vs `CSMTechnique.cpp:167`、`SpotShadowTechnique.cpp:128`、
`RectLightShadowTechnique.cpp:128`）——这套差异只靠注释维系（`PointShadowTechnique.cpp:117`–`:120`），
代码里没有共享的约定常量。

### 10.5 聚光/矩形光共用一张图，且 Deferred 侧行为不一致

两技术各只有一张 2D 图（`SpotShadowTechnique.h:45`、`RectLightShadowTechnique.h:45`），逐光源覆写（同点光）；
Deferred 的聚光分支不应用 `shadowStrength`（`DeferredLighting.frag.slang:350`–`:363` 缺 `PBR.frag.slang:169`
的 `lerp`）；Deferred 无点光/矩形光分支（§7.5）；矩形光在 Forward 走不到自己的分支（§6.3）。

## 11. 未复核清单

以下是本次**没有**核实到确凿证据、或只做了静态推导而未运行时确认的点，一律不当作结论：

1. **§10.1 的运行时后果未复现**：只核对了"缓冲 1024 B vs 可写 16 条"这对静态事实。实际越界写入是否破坏
 相邻 VMA 分配、是否触发校验层报错、是否只在特定场景配置下出现，均未实测；也未核对 `MAX_SHADOWS`
 是否在别处被放大过。
2. **`Map()` 的映射粒度**：只确认返回 `m_MappedPtr`（`VulkanResources.cpp:179`–`:189`），未核对 VMA 分配
 是否整体映射/按页对齐，因此"越界落在同一映射内 ⇒ 静默"是推断而非结论。
3. **索引空间与聚合访问器混用**：Deferred 用 `GetShadowMap(4)` 取聚光依赖 3/1/1/1 的分布，
