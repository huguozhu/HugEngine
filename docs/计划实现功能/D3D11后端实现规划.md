## 1. 目标与边界

### 1.1 目标

- 新增 `Engine/RHI/D3D11` 后端，`HE_RHI_BACKEND=d3d11` 选择；
- 除光追 / 路径追踪外，样例 01、02、03、04、06、07.Nanite、07.AISamples 在 D3D11 下画面与 Vulkan 基线一致（截图对比）；
- Vulkan、D3D12 两个后端**零回归**（每个里程碑都跑回归）。

### 1.2 非目标

| 项 | 处理 |
|---|---|
| 光追、05.Sponza-PathTracing | 不做；`supportsRayTracing=false` |
| Mesh shader | 不做；Nanite 走 compute 软光栅，01.Triangle 走已有的普通管线分支 |
| DGC | 不做；`supportsDGC=false`，延迟管线已有回退 |
| 异步计算 | 不做；`HasAsyncComputeQueue()=false`，RenderGraph 已有单队列路径 |
| 命令流模式（L4-3） | 第一版不做（D3D12 也未做），放到最后可选里程碑 |
| 性能对标 | 第一版只求正确；性能问题记录不修 |

### 1.3 最低运行环境 **[本文决定]**

| 要求 | 原因 |
|---|---|
| Windows 10 1703+，D3D11.4 运行时（`ID3D11Device5` / `ID3D11DeviceContext4`） | 需要 `ID3D11Fence` 实现时间线围栏，免去 `D3D11_QUERY_EVENT` 退化路径 |
| 特性级别 **11_1** | 64 个 UAV 槽、`*SetConstantBuffers1`（带偏移，常量环必需） |
| `D3D11_FEATURE_D3D11_OPTIONS::ConstantBufferOffsetting` 与 `MapNoOverwriteOnDynamicConstantBuffer` | 常量环带偏移绑定、对动态常量缓冲用 `WRITE_NO_OVERWRITE`（3.5） |
| `D3D11_FEATURE_D3D11_OPTIONS2::TypedUAVLoadAdditionalFormats` | Lumen / Nanite 有 RGBA16F UAV 的读写；DX12 级硬件全部支持，不做 R32 打包退化 |

不满足任一条件：`CreateDevice` 打印中文原因并返回空，样例退出（不静默回退其它后端）。
这样把原方案里的三条“退化路径”全部砍掉，减少约 1 周工作量和大量分支代码。

## 3. 关键设计决策

### 3.1 着色器编译链 **[本文决定]**

```
slangc -target hlsl -DHE_SHADER_D3D11
   → ShaderToDxil --dxbc（同一工具新增模式）
       ① 语义注入   ② uint8_t→uint   ④ SV_InstanceID→HE_INSTANCEINDEX（与 D3D12 共用）
       ③' [loop]：fxc 专用版 —— 只给最外层循环加（嵌套循环加 [loop] 必触发 X3531）；剥掉带 break 循环上的 [unroll]
       ⑤ t / u 寄存器：vk::binding(B, 0) → register(tB / uB)，去掉 space
       ⑥ s / b 寄存器：采样器、描述符集 cbuffer 按出现顺序压缩编号（s0..s15、b1..b13）；[[vk::push_constant]] 块固定 b0（M1.1 实现）
       ⑦ 显式 register(..., spaceN)：D3D11 下一律删除后按 ⑤⑥ 重新分配（原样保留会越界 / 冲突）
       ⑧ 生成绑定重映射表：(set, binding, 类型) → D3D11 槽位
   → D3DCompile（进程内调用，不加 STRICTNESS；vs_5_0 / ps_5_0 / cs_5_0）
   → generated_dxbc/X.dxbc.h（字节码 + 绑定重映射表）
```

- **不新建 ShaderToDxbc 工具**：①②④ 与 D3D12 完全相同，分叉只会让两边各自修 bug；③' ⑤~⑧ 是 `--dxbc` 模式专属。
  工具改名（如 `ShaderToD3D`）可以留到最后，不在本规划内。
- **不逐处改源码里的 `[[vk::binding]]`**：早期实验（29 号文档）改了 396 处声明，那批代码已不在树中；
  D3D12 已证明“构建期补丁”路线可行，D3D11 照搬。
- **为什么 t / u 可以恒等映射、s / b 不行**：非光追着色器全部在 set 0、binding 号约 30 以内，
  t（128 槽）、u（64 槽）直接用 binding 号即可。但**采样器只有 s0..s15**，而现有采样器用到 binding 22 / 24 / 25
  （`PBR.frag.slang:49/51`、`DecalProject.frag.slang:31`）；**常量缓冲只有 b0..b13**，D3D12 的 `b(B+8)` 规则会越界。
  所以 s、b 两类压缩编号，表写进头文件。
- **像素着色器 UAV 的特殊约束**：PS 的 UAV 槽与 RTV 共享编号空间（`OMSetRenderTargetsAndUnorderedAccessViews`
  的 `UAVStartSlot ≥ NumRTVs`）。工具在 PS 里把 UAV 统一平移到 `u8` 以后，并记入重映射表。
- **预处理宏**：命令行同时定义 `HE_SHADER_D3D11` 与新增的 `HE_SHADER_HLSL`（两个 D3D 后端共有）。
  现有 6 个 `#if defined(HE_SHADER_D3D12)` 分支逐个审查：与 SM5.0 无关的部分（如 `SV_InstanceID` 选择）改为
  `HE_SHADER_HLSL`；与 bindless 数组尺寸相关的部分（`common.slang:21`）D3D11 另写分支。
  否则 D3D11 会落入 Vulkan 分支：数组维度为空（无界数组）、使用 `SV_VulkanInstanceID`。
- **fxc 的已知坑**（29 号文档实测）：`X3511` 靠 ③' 解决；`flattened side effect` 无行号内部错误 ——
  若出现，该着色器在 D3D11 下单独改写（见 7 节清单）。
- **编译器版本**：进程内链接 `d3dcompiler.lib`（Windows SDK），运行时加载 `d3dcompiler_47.dll`。
  **M1.0 实测（2026-10-30）**：SDK 10.0.26100 的 fxc（DLL 10.0.26100.8249）用 `cs_5_0` 编译
  `RWTexture2D<float4>` 的读 + 写成功，DXBC 标注 “shader requires: Typed UAV Load Additional Formats”，
  与 1.3 节的设备要求一致；本机系统目录的 DLL（10.0.26100.9711）更新，也可用。
- 光追、mesh shader 不生成 DXBC。

### 3.2 bindless 替代方案（工作量主体）**[本文建议，需你拍板，见第 9 节 Q1]**

D3D11 / SM 5.0 的事实：资源数组只能用**字面量下标**；`Texture2DArray` 的**层号**可以是动态的；单个 `StructuredBuffer` 内部元素可以动态索引。

按依赖面分三类处理：

| 类别 | 现状 | D3D11 做法 |
|---|---|---|
| **A. 绘制级一致的纹理句柄**（Forward 的逐物体绘制路径、Decal、CPU 路径的 GBuffer） | 句柄来自 push constant 或单对象数据，同一次 draw 内不变 | **逐 draw 绑定**：着色器在 `HE_SHADER_D3D11` 下把 `u_Textures[texBase + k]` 换成固定槽 `u_MatTex{k}`（宏 `HE_MAT_TEX(k)`），C++ 侧在 draw 前把材质的 4 张纹理绑上（接口见下） |
| **B. 缓冲数组**（实例矩阵、可见索引、骨骼、材质 SSBO） | `u_InstanceTransforms[handle][i]`，handle 绘制级一致 | 宏 `HE_BINDLESS_BUF(name, handle)` 在 D3D11 下展开为 `name`（单个缓冲），声明改为普通的 set 0 binding；绑定方式同 A |
| **C. GPU 驱动 / 逐像素任意材质**（**Forward 的 GPU 剔除路径**、GBuffer_GPU、Nanite 软光栅） | 命令被原子压缩，材质号来自 GPU 数据，CPU 不知道 | **纹理数组桶**：材质纹理按（尺寸, 格式）归入 ≤ 8 个 `Texture2DArray`，材质数据存（桶号, 层号）；着色器用 `switch(桶号)` 选字面量下标的数组。只在 D3D11 下构建 |

- 能力位：`DeviceCaps::maxBindlessResources = 0` 时渲染层走 A/B；`supportsTextureArrayMaterials`（新增）为真时 C 类可用。
  为假时：**Forward 关闭 `m_UseExecuteIndirect` / GPU 剔除**、GBuffer 强制走 CPU 路径、Nanite 材质用常量色兜底。
- **第一版推荐只做 A + B**，C 类先按上一条兜底，02 / 03 / 04 / 06 样例照样出画。
  C 类作为独立里程碑 M6，做不做由你决定。
- **A / B 的绑定接口** **[本文决定]**：不新增 RHI 接口，沿用 `UpdateDescriptorSet`，但规定 D3D11 的描述符集是
  “立即语义”—— 更新在下一次 draw 生效，同一帧里反复改同一个集是合法的。
  这段渲染层代码只在 `maxBindlessResources == 0` 时执行，Vulkan / D3D12（同帧反复改集是错误的）永远不走，互不影响。

### 3.3 间接绘制：后端内部“参数整形”**[本文决定]**

D3D11 两个问题：① 间接参数缓冲必须带 `D3D11_RESOURCE_MISC_DRAWINDIRECT_ARGS`，且**不能**同时是结构化缓冲；
② 没有 count 版、没有一次多条。

做法（**渲染层和着色器都不改**）：

1. 用途同时含 `Indirect` 与 `Storage` 的缓冲，D3D11 后端内部建两份：主缓冲（结构化，供 CS 写）+ 影子参数缓冲（`DRAWINDIRECT_ARGS | ALLOW_RAW_VIEWS`）；
2. `DrawIndexedIndirect(buf, off, n, stride)` / `DrawIndexedIndirectCount(...)` 前，后端派发一个**内置小 CS**：
   从主缓冲读前 `maxDrawCount` 条命令、从计数缓冲读真实条数，写入影子缓冲，超出条数的 `instanceCount` 置 0；
3. 然后在 CPU 上循环 `DrawIndexedInstancedIndirect`（每条一次）。

代价：每条命令一次 API 调用。Nanite 的 `maxDrawCount` 较大时 CPU 开销明显，记入性能风险，不在第一版处理。
`DispatchIndirect` 同理走影子缓冲（不需要循环）。

### 3.4 命令录制 **[沿用参考方案]**

- 主录制走 immediate context，命令在录制时就已发出，`Submit` 只负责围栏信号。
- **多个命令列表共用一个 immediate context**（见 2.4“多个命令列表并存”）：每个 `D3D11CommandList` 保存自己的
  完整绑定状态（PSO、RT、视口、描述符集、顶点 / 索引缓冲、常量环位置）。设备记录“上一个用过上下文的列表”，
  换人后的第一次 draw / dispatch 前整体重新应用。
- **执行顺序与 Vulkan 不同**：Vulkan 主列表在提交时才执行；D3D11 主列表已录部分先于中途插入的一次性列表执行。
  M2 盘点上述 3 处调用点，确认没有“主列表先录的命令依赖一次性列表结果”的情况。
- 描述符集**不在 `BindDescriptorSet` 时立即下发**：重映射表随 PSO 变化，且描述符集带 `UPDATE_AFTER_BIND`
  语义（绑定后仍可能更新）。改为 Bind / Update / SetPipeline 都只置脏，在 draw / dispatch 前按**当前 PSO 的重映射表**统一下发。
- 多线程二级列表：`D3D11_FEATURE_THREADING::DriverCommandLists` 为真时用 deferred context +
  `FinishCommandList` / `ExecuteCommandList`；否则 `CreateSecondaryCommandList` 返回空，引擎自动单线程录制。
  **放到 M5 之后再做**，第一版直接返回空。
- 屏障接口全部为空操作；`BufferBarrier` 也为空。

### 3.5 推送常量

- 每个命令列表一块常量环（与 D3D12 同规格 4096 × 256B，`D3D11_USAGE_DYNAMIC`）；
- `SetPushConstants` 写入当前槽，draw / dispatch 前若脏则推进一槽，`VS/PS/CSSetConstantBuffers1(b0, offset, 16 常量的整数倍)` 绑定；
- 环绕时用 `Map(WRITE_NO_OVERWRITE)`，整圈用完后 `WRITE_DISCARD` 换新页 —— 天然避免 D3D12 版“无围栏保护”的问题；
- 映射内存只写不可读，而“新槽继承上一槽内容”（`D3D12CommandList.cpp:1143`）需要读旧值 ⇒ CPU 侧保留一份 256B 副本，改副本后整块写入；
- 同一缓冲只换偏移重新绑定可能被运行时当作冗余调用过滤 ⇒ 先绑空再绑（M2 实测确认是否必要）。

### 3.6 帧同步与查询

- `ID3D11Fence` + `ID3D11DeviceContext4::Signal / Wait` 实现时间线围栏与 `RHIFenceHandle`；
- `WaitIdle` = Signal + 等事件，超时 8 秒打印错误（沿用 D3D12 的防挂死做法）；
- 时间戳：`D3D11_QUERY_TIMESTAMP` + 每帧一个 `TIMESTAMP_DISJOINT`；管线统计：`D3D11_QUERY_PIPELINE_STATISTICS`；
  `GetQueryResults(count)` 按查询个数解释，`GetData` 用 `DONOTFLUSH`，未就绪返回 false。

### 3.7 资源冲突解绑

D3D11 运行时会把同时作为 RTV / UAV 与 SRV 绑定的资源**静默解绑**（只有调试层警告）。
后端维护“当前绑定为 SRV 的资源 → 槽位”表，`BeginRenderPass` / 绑定 UAV 前主动清掉冲突的 SRV 槽；
反之绑 SRV 前检查是否仍挂在 RTV / UAV 上。调试层的 `DEVICE_*_HAZARD` 警告作为验收项（必须为 0）。

### 3.8 交换链与 ImGui

- `IDXGISwapChain1`，`FLIP_DISCARD`，3 缓冲，垂直同步关闭时 `ALLOW_TEARING`（撕裂判断照抄 D3D12）；
- **不照抄 D3D12 的每缓冲 RTV**：D3D11 翻转模型只能访问 buffer 0（运行时自动轮换），只建一个 RTV，`AcquireNextImage` 恒返回 0；
- `HE_CAPTURE_FRAME=N` 截图（照抄 D3D12 的实现，便于截图对比）；
- ImGui：从 imgui 上游取**同版本**的 `imgui_impl_dx11.cpp/.h` 加进 `Engine/External`，
  `ImGuiIntegration.cpp` 加 `m_IsD3D11` 分支。

### 3.9 坐标系约定

`PointShadowTechnique.cpp:147` 现在写的是 `== Backend::D3D12`。改成 RHI 提供的
`IsD3DStyleClipSpace(backend)`（D3D11 / D3D12 为真）。RHI 之外只有两处 `Backend::D3D12`，
另一处 `ImGuiIntegration.cpp:38` 是选 UI 后端，**不属于坐标系判断**，单独加 D3D11 分支。

### 3.10 可映射的存储缓冲 **[本文建议，需你拍板，见第 9 节 Q5]**

D3D11 的 `DYNAMIC` 缓冲不能作 UAV，`DEFAULT` 缓冲不能 Map（`MapOnDefaultBuffers` 基本只有集显支持）。
建议 `cpuAccess = true` 的缓冲由三部分组成：

| 部分 | 作用 |
|---|---|
| GPU 缓冲（`DEFAULT`，可作 SRV / UAV） | 着色器读写 |
| CPU 影子内存 | `Map()` 返回它；`Unmap()` 或 `Submit` 前若脏则 `UpdateSubresource` 上传 |
| 每飞行帧一份 `STAGING` 回读缓冲 | 每帧末 `CopyResource`；下一次 `Map()` 前把**已完成帧**的回读内容拷进影子内存 |

代价：CPU 读到的 GPU 结果有 1~2 帧延迟。M2 要盘点 103 处调用点：是否每次写完都 `Unmap`、哪些地方
要求“当帧读到 GPU 写入结果”（D3D12 曾因此出现自动曝光卡初值、粒子池被清零）。

### 3.11 结构化缓冲步长 **[本文建议，需你拍板，见第 9 节 Q6]**

建议 `BufferDesc` 新增 `structureStride`（默认 0），逐个补上结构化缓冲的创建点；
为 0 时 D3D11 后端退化为“首次以结构化视图绑定时，按着色器反射步长重建缓冲并拷贝内容”，同时打印告警提示补字段。
M2 同时盘点“同一缓冲被不同元素类型读取 / 同时作顶点或索引缓冲 / 作原始视图”的情况
（结构化标志与这些用法互斥）。

**M2.3 实现**：`BufferDesc::structureStride` 已加（默认 0，其它后端忽略）；未填时按 DXBC 反射出的
步长（`D3D11_SHADER_INPUT_BIND_DESC::NumSamples`）在第一次结构化绑定时重建。按 2.3b 的盘点结论，
**不必逐个补调用点**：没有任何缓冲需要两种互斥的视图，重建只发生一次。

### 3.12 M2.3b 盘点结果（2026-10-30）

| 盘点项 | 结论 | 对 D3D11 的处理 |
|---|---|---|
| `Map()` / `Unmap()` 配对 | 引擎（不含 RHI）共 167 处 `Map()`、153 处 `Unmap()`；赋值保存映射指针的 155 处里，**18 处是持久映射**（Map 后保存指针、不再 Unmap），全部在 Lumen（16）、DDGI（1）、Lumen 远场（1），都是统计计数 / 射线结果的 GPU→CPU 读回 | 配对的走「Map 时按需同步回读、Unmap 上传」；持久映射的走「绘制 / 派发前上传 CPU 改动、提交时回读 GPU 写入」（3.10，M2.3 已实现）。CPU 读到的是**上一次提交**结束时的内容，与 Vulkan 下「等围栏再读」的时效一致；Q5 的 1~2 帧延迟不会出现，代价是同步等待（性能问题记录不修） |
| 当帧读回 | 配对的 `Map()` 遇到「被 GPU 写过」的缓冲会**当场**同步回读，因此需要当帧结果的调用点（如 `NaniteScene` 上传自检）不受影响 | 无需改调用点 |
| 结构化缓冲互斥用法 | ① 着色器里**没有** `ByteAddressBuffer` / 带类型 `Buffer<>`（非光追），所有存储缓冲都是 `StructuredBuffer`；② **没有**缓冲同时带 `Storage` 与 `Vertex` / `Index` 用途；③ `Storage + Indirect` 7 处（GPU 剔除 / Nanite / 粒子的间接参数），由 M3.5 的影子参数缓冲处理 | 惰性重建永远不会撞上互斥用法，`structureStride` 不必补；Q6 结论：加字段（已加）+ 后端兜底即可 |
| 中途插入的命令列表 | ① `NaniteScene.cpp:190`：一次性列表把资产缓冲拷到读回缓冲后 `WaitIdle`，读回只给 CPU 自检，主列表此前录的命令不依赖它；② `RenderGraph.cpp:547`：只在 `ExecuteWithAsyncCompute` 里创建，而该路径由 `HasAsyncComputeQueue()` 决定，D3D11 恒为 false，**不会走到**；③ `GPUBackend.cpp:395`（AI）：独立列表录一次派发后 `Submit + WaitIdle`，自带管线与描述符集 | 执行顺序差异不影响正确性；③ 会改动 immediate context 的绑定状态，由 M2.6 的「换列表后重新应用」保证主列表不受影响 |

**3.3 实施记录（2026-10-30）**：

- **与规划的差异**：没有把资源写进描述符集，而是新增 RHI 接口 `IRHICommandList::SetNonBindlessHandle(binding, handle)`（其余后端空实现）。渲染层在写推送常量的同一处告知句柄，D3D11 在 `FlushBindings` 时从 bindless 堆按句柄取资源。原因是同一描述符集在一帧内被多次绘制共用，「立即语义」的改集会被后续绘制覆盖；按句柄则与 bindless 的语义完全一致。句柄 0 是合法句柄，「不绑」用 `kNonBindlessNone`。

  - 描述符集与 bindless 堆改为在写入时持有 D3D11 视图。引擎会在写入后销毁局部的占位纹理 / 采样器，原先存裸指针，绑定时就是悬空指针。
  - 单上下文下 GPU 侧围栏等待会死锁，改为不下发。
- **结果**：02.Cube 第 120 帧与 D3D12 画面一致。尚缺 ImGui（M3.6）和 GPU 剔除的 1 万实例网格（M3.5）。

## 6. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| fxc 内部错误（`flattened side effect`）无行号、无解 | 个别 GI / Nanite pass 不可用 | M1 就拿到失败清单，提前评估；必要时 D3D11 专用改写 |
| 影子参数缓冲：结构化缓冲与参数缓冲之间的拷贝方式 | 3.3 方案若不成立需改 6 个 CS | 整形 CS 只读主缓冲的 SRV（结构化可读）、写影子缓冲的原始 UAV，不依赖 `CopyResource` 跨类型 —— M3 第一天先做最小验证 |
| bindless 宏改动影响 Vulkan / D3D12 | 回归 | 3.2 要求 SPIR-V / DXIL **逐字节一致**（宏展开后文本应完全相同） |
| Nanite 逐条间接绘制 CPU 开销 | 07 帧率低 | 第一版只求正确；性能单列 |
| 渲染层运行期频繁建 / 销纹理 | D3D11 自动管理，影响小 | 无需处理（D3D12 曾因此黑屏，D3D11 不会） |
| 调试信息不足导致盲猜 | 定位慢 | M2 起 InfoQueue 必开；`HE_CAPTURE_FRAME` 截图；RenderDoc 对 D3D11 支持最好，优先用 |
