>
> 创建分支：`dx12`

## 2. Vulkan → D3D12 能力映射

### 2.1 核心架构差异

| 概念 | Vulkan | D3D12 | 影响 |
|---|---|---|---|
| **命令内存** | `VkCommandBuffer`（可并发） | `ID3D12CommandAllocator` + `List`（allocator 不可并发复用） | 每帧每线程需独立 allocator |
| **描述符** | `VkDescriptorSet`（可随意更新） | **Descriptor Heap** + 必须先用 `CopyDescriptors` 填好 | 需要"影子堆"做 bindless |
| **描述符更新** | 直接写 | 只能通过 CPU 侧 `CopyDescriptors` 或 shader-visible 堆直接映射 | `UpdateDescriptorSet` 466 处调用需要高效路径 |
| **根签名** | `VkPipelineLayout` | `ID3D12RootSignature` | push constant → root constants（256B 限制） |
| **布局转换** | `vkCmdPipelineBarrier` + image layout | `ResourceBarrier`（状态机） | 需要 layout → D3D12 状态的映射表 |
| **Render pass** | `VkRenderPass` + `vkCmdBeginRenderPass` | `OMSetRenderTargets`（无 pass 概念） | 需要模拟 pass 语义（clear / load） |
| **间接绘制带计数** | `vkCmdDrawIndexedIndirectCount` | `ExecuteIndirect` + count buffer | ✅ 原生对应 |
| **Mesh shader** | `VK_EXT_mesh_shader` | `DispatchMesh`（SM 6.6） | ✅ 原生对应 |
| **GPU 生成命令** | `VK_EXT_device_generated_commands` | `ExecuteIndirect`（原生） | ✅ D3D12 更简单 |
| **光追** | `VK_KHR_ray_tracing_pipeline` | DXR 1.1（`ID3D12Device5`） | ✅ 语义接近 |
| **时间线信号量** | `VkSemaphore` (timeline) | `ID3D12Fence` | ✅ 语义接近 |
| **查询** | `VkQueryPool` | `ID3D12QueryHeap` | ✅ 语义接近 |

### 2.2 关键技术难点

| # | 难点 | 说明 | 对策 |
|---|---|---|---|
| 1 | **bindless 描述符堆** | Vulkan 的 `u_Textures[]`（本引擎 267 处使用）在 D3D12 上需要 shader-visible 大堆 + 稳定索引 | 预分配 64K 纹理槽 + 16 采样器槽的 shader-visible 堆，用空闲链表管理 |
| 2 | **`UpdateDescriptorSet` 的高频更新** | 466 处调用，若每次都 `CopyDescriptors` 会极慢 | 区分"永久"（纹理/采样器，写一次）与"每帧"（CBV/UAV，用 per-frame heap 区段） |
| 3 | **push constant 256B 限制** | Vulkan 的 push constant 在 D3D12 是 root constants（**256 字节上限**） | 引擎最大 push constant 需实测；超限的改走 CBV |
| 4 | **布局转换** | Vulkan 的 image layout 与 D3D12 的 resource state 不是一一对应 | 建立映射表：`ShaderReadOnly → PIXEL_SHADER_RESOURCE`、`ColorAttachment → RENDER_TARGET`、`DepthAttachment → DEPTH_WRITE` |
| 5 | **Render pass 的 clear/load** | D3D12 无 pass 概念，clear 与 load 需显式处理 | `LoadOp::Clear` → `ClearRenderTargetView`；`LoadOp::Load` → 不动 |
| 6 | **多线程命令录制** | 引擎有渲染线程模式（`HE_RENDER_THREADING_MODE`）| 每线程独立 allocator + 每帧回收队列 |
| 7 | **PSO 库 / GPL** | Vulkan 有 `VK_EXT_graphics_pipeline_library` | D3D12 无直接对应，用 PSO 缓存 + 预编译 |

## 3. 实现规划（分 6 阶段）

### 阶段 0：基础设施（预计 1.5 周）

**目标**：设备能创建、能清屏、能 present。

| 交付物 | 内容 |
|---|---|
| `D3D12Device.h/.cpp` | `ID3D12Device`、`IDXGIFactory4`、命令队列、描述符分配器 |
| `D3D12SwapChain.h/.cpp` | FLIP_DISCARD、RTV 堆、每帧 backbuffer |
| `D3D12Converters.h/.cpp` | `Format`/`PrimitiveTopology`/`CullMode`/`CompareFunc` → D3D12 枚举 |
| `D3D12CommandList.h/.cpp` | allocator 管理、`Begin/End`、`Reset` |
| 接入 | `Backend::D3D12` 加入 `Types.h`，`CreateDevice` 分支 |

**验收**：`01.Triangle` 能跑（清屏 + 交换链呈现）。

### 阶段 1：资源与描述符（预计 2 周）

**目标**：Buffer / Texture / Sampler 可用，bindless 堆可用。

| 交付物 | 内容 |
|---|---|
| `D3D12Resources.h/.cpp` | `D3D12Buffer`/`D3D12Texture`/`D3D12Sampler`，上传堆 + 默认堆 + 暂存堆 |
| `D3D12Descriptors.h/.cpp` | 描述符堆管理（RTV/DSV/CBV_SRV_UAV/SAMPLER）、空闲链表 |
| `D3D12BindlessHeap.h/.cpp` | 64K 纹理槽 + 16 采样器槽的 shader-visible 堆 |
| 上传策略 | 小资源直接 `CreateCommittedResource` + `CopyBufferRegion`；大资源用上传堆 |

**验收**：纹理能上传、能采样、bindless 索引可用。

### 阶段 2：管线与命令录制（预计 2.5 周）

**目标**：能跑完整的 Forward 渲染。

| 交付物 | 内容 |
|---|---|
| `D3D12Pipeline.h/.cpp` | `ID3D12RootSignature` + `ID3D12PipelineState`、输入布局、深度/光栅/混合状态 |
| `D3D12RootSignatureBuilder` | 自动从 `DescriptorSetLayoutDesc` + push constant 生成根签名 |
| `D3D12CommandList` 扩展 | `SetPipeline`、`BindDescriptorSet`、`SetPushConstants`、`SetVertexBuffer`、`SetIndexBuffer`、`Draw*`、`Dispatch*`、`PipelineBarrier`、`Begin/EndOffscreenPass*` |
| 屏障映射 | image layout → resource state 转换表 |

**验收**：`02.Cube` 的 Forward 路径能出画（几何 + 材质 + 光照）。

### 阶段 3：高级绘制（预计 1.5 周）

**目标**：间接绘制、GPU 剔除、多帧并行。

| 交付物 | 内容 |
|---|---|
| `ExecuteIndirect` | `DrawIndexedIndirect` / `DrawIndexedIndirectCount` / `DispatchIndirect` |
| 多帧 in-flight | 每帧独立 allocator + fence 回收 |
| 多线程录制 | 线程亲和（复用 `ThreadAffinity.h`）|
| 查询 | `ID3D12QueryHeap`（时间戳、遮挡） |

**验收**：`03.Sponza-Forward` 的 GPU 剔除路径正常。

### 阶段 4：光追（预计 2 周）

**目标**：DXR 1.1 与 Vulkan 光追等价。

| 交付物 | 内容 |
|---|---|
| `D3D12RT.h/.cpp` | BLAS / TLAS 构建、`ID3D12StateObject`、SBT |
| Shader 绑定 | Slang → DXIL（`-target dxil`），`register(tN, spaceS)` |
| 光线查询 | `RayQuery` (inline) + `TraceRay` (pipeline) |

**验收**：`05.Sponza-PathTracing` 能跑。

### 阶段 5：Mesh Shader 与 DGC（预计 1 周）

**目标**：Nanite 路径可用。

| 交付物 | 内容 |
|---|---|
| Mesh shader | `DispatchMesh` + `ID3D12PipelineState` (MS/AS) |
| DGC | 用 `ExecuteIndirect` 的原生能力替代 Vulkan 的 DGC 扩展 |
| Nanite 接入 | `07.Nanite` 能跑 |

**验收**：`07.Nanite` 能跑。

### 阶段 6：打磨与验证（预计 1.5 周）

| 任务 | 内容 |
|---|---|
| 验证层 | `ID3D12InfoQueue` 接入，错误进日志 |

## 4. 着色器策略

### 4.1 编译链

```
Slang 源码
   ↓ slangc -target dxil  (或 -target hlsl + dxc)
DXIL 字节码
   ↓ 嵌入头
*.dxil.h
```

### 4.2 与 Vulkan 的差异

| 项 | Vulkan | D3D12 |
|---|---|---|
| 目标 | SPIR-V | DXIL (SM 6.6) |
| 绑定 | `[[vk::binding(n, s)]]` | `[[vk::binding]]` 无效，用 `register(tN, spaceS)` |
| push constant | `[[vk::push_constant]]` | root constants（需 `register(b0, space0)` 布局一致）|
| bindless | 无界数组 `u_Textures[]` | **需要真正的无界数组**：D3D12 SM6.6 支持 `ResourceDescriptorHeap[]`（但 Slang 支持度待验证）|

### 4.3 bindless 的关键决策

D3D12 有两条路：

| 方案 | 说明 | 优缺点 |
|---|---|---|
| **A. 大数组 + 描述符堆** | `Texture2D u_Textures[65536]` + shader-visible 堆 | 兼容性好，但 64K 描述符占用大（2MB）|
| **B. SM6.6 `ResourceDescriptorHeap[]`** | 直接用堆索引，无需声明数组 | 更优雅，但需 Slang + DXC 支持，且 SM6.6 要求较高 |

**建议先 A**（稳妥），B 作为后续优化。

## 5. 风险与缓解

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| 1 | 216 个虚函数的实现量 | 工作量大 | 分阶段，每阶段只实现引擎实际调用的部分 |
| 2 | 驱动差异（NVIDIA / AMD / Intel）| 某些特性缺失 | 启动时查询 `CheckFeatureSupport`，缺失则降级 |
| 3 | Slang 的 DXIL 后端成熟度 | 编译失败 | 保留 `-target hlsl` + `dxc` 的兜底路径 |
| 4 | 描述符堆大小限制 | bindless 容量不足 | 分堆（纹理 / 采样器 / CBV 分开）|
| 5 | 调试困难 | 定位慢 | 阶段 0 就接入 `ID3D12InfoQueue` |
| 6 | 与 Vulkan 的数值差异 | 逐字节对比失败 | 明确"功能等价"而非"数值等价" |
