# D3D11 后端实施方案

> **性质**：实施计划（2026-10-24 制定）。
> **目标**：实现 D3D11 后端，**除光追外**支持 Vulkan 后端现有的全部功能，并跑通所有样例（01~07）。
> **前置事实**：`IRHIDevice` 96 个虚函数 + `IRHICommandList` 61 个虚函数 = **157 个待实现接口**；
> 着色器有 **668 处 `[[vk::`** 绑定语法；渲染层的 Vulkan 耦合仅 **1 处真实代码依赖**（`GI_RSM.cpp` 的 include）。

---

## 1. 先说清楚：这个项目的五个硬阻塞

不是"照着接口实现一遍"就能完成 —— D3D11 与 Vulkan 在五处**结构性差异**上必须做设计取舍，
这五处的决策会决定整个后端的形态：

| # | 阻塞 | 现状（Vulkan 侧） | D3D11 的现实 | 可选对策 |
|---|---|---|---|---|
| **1** | **Bindless** | 材质/纹理/骨骼全部走 bindless SSBO + descriptor indexing | D3D11 **没有 bindless**（SM5.0 固定槽位，纹理槽上限 128） | ① 材质改"常量缓冲 + 纹理数组"（改 shader 与资源组织）；② 保留 bindless 语义但在 HLSL 里用固定槽位宏展开（限制材质数）；③ 只在 D3D11 上降级为"每 draw 一次 Bind"（CPU 开销大） |
| **2** | **Mesh Shader** | Nanite 用 `VK_EXT_mesh_shader` 硬光栅路径 | **不支持**（SM6.5 起才有，D3D11 无） | Nanite 在 D3D11 上走 **compute 软光栅**（代码里已有 `NaniteRaster` 的 compute 分支）+ 关掉 `m_HardRasterMS` |
| **3** | **DGC / GPU 驱动** | `vkCmdExecuteGeneratedCommandsEXT`、`DrawIndexedIndirectCount` | `DrawIndexedInstancedIndirect` 支持 ✔，但**无 DGC**、**无 indirect count** | GPU 剔除结果回读到 CPU，或改成"固定 maxDrawCount 的 DrawIndexedInstancedIndirect" |
| **4** | **Slang 绑定语法** | 668 处 `[[vk::binding(n, s)]]`、`[[vk::push_constant]]` | D3D11 需要 `register(bN/tN/sN/uN)` | Slang 可同时产出 DXIL/HLSL：把绑定改成**语义化宏**（`HE_BINDING(n,s)`），每个后端各自展开 |
| **5** | **异步计算队列** | `QueueType::Compute` 独立队列 + 栅栏 | D3D11 **只有一个 immediate context**，无独立计算队列 | 异步 pass 退化为"同一命令列表里顺序执行"（牺牲并行，功能等价） |

**结论**：阻塞 1（bindless）和 4（shader 绑定）是**工作量主体**，阻塞 2/3/5 是**功能降级取舍**（可以接受，但要写进文档）。

## 2. 分层实施计划

### 阶段 0：清理与设施（1~2 周）

| 任务 | 内容 | 判据 |
|---|---|---|
| 0.1 | 修掉 `GI_RSM.cpp` 对 `Vulkan/VulkanResources.h` 的 include（改用 RHI 抽象） | 构建通过 |
| 0.2 | 加 `RHIBackend` 选择（`EngineConfig::rhiBackend`：`Vulkan` / `D3D11`） | 启动日志显示所选后端 |
| 0.3 | `DeviceCaps` 能力查询（`bindless` / `meshShader` / `dgc` / `asyncCompute` / `indirectCount`） | 样例可按 caps 降级 |
| 0.4 | 着色器绑定宏化：`[[vk::binding(n,s)]]` → `HE_BINDING(n, s)`，由 Slang 编译目标决定展开 | Vulkan 侧行为不变（20/20 判据） |

### 阶段 1：D3D11 设备与资源（2~3 周）

| 任务 | 内容 |
|---|---|
| 1.1 | `D3D11Device : IRHIDevice` 骨架（创建/销毁/能力查询），先让 96 个虚函数**全部有实现**（多数可先返回空/默认） |
| 1.2 | Buffer / Texture / Sampler / Shader / PSO 的创建与销毁（对应 `CreateBuffer*`/`CreateTexture*`/…） |
| 1.3 | 句柄表（复用 A-3 的 `RHIResourceTable`，与 Vulkan 后端共用同一套语义） |
| 1.4 | SwapChain（`IDXGISwapChain`）+ `FramePresenter` 适配（D3D11 无需 acquire 信号量） |
| 1.5 | 描述符集 / bindless 的 D3D11 映射（**取决于阻塞 1 的决策**） |

### 阶段 2：命令列表（2 周）

| 任务 | 内容 |
|---|---|
| 2.1 | `D3D11CommandList : IRHICommandList` 骨架（61 个虚函数） |
| 2.2 | **deferred context** 承担"录制"，`FinishCommandList` → `ExecuteCommandList` 承担"提交" |
| 2.3 | 流模式（L4-3）复用：D3D11 后端可以直接把 `m_StreamMode` 打开 —— **这正是 L4-3 的价值** |
| 2.4 | `Map/Unmap` 走 immediate context（渲染线程零 API 的前提下由 RHI 线程执行） |

### 阶段 3：着色器（3~4 周，最大工作量）

| 任务 | 内容 |
|---|---|
| 3.1 | 668 处 `[[vk::` 改成语义宏（阶段 0.4 已铺路） |
| 3.2 | 编译目标切换：Slang `-target hlsl` 产出 SM5.0/SM5.1 |
| 3.3 | bindless 替代方案落地（纹理数组 / 固定槽位宏） |
| 3.4 | push constant → 常量缓冲（D3D11 无 push constant） |
| 3.5 | 逐 pass 验证：从最简单（全屏三角形/tonemap）到最复杂（Nanite/Lumen） |

## 3. 与原计划（L4-3）的关系

L4-3（命令流双模式）**已经为 D3D11 铺好了关键一层**：

```
渲染层（零后端 API）
   ↓ IRHICommandList（157 个虚函数之一半）
   ├── VulkanCommandList：直连录制（模式 A）或命令流（模式 B）
   └── D3D11CommandList：deferred context 录制 / immediate context 执行
```

即：**渲染层不需要任何改动**就能换后端（已实测 `Engine/Render` 只有 1 处真实 Vulkan 依赖）。
这也是当初做 L4-3 的**核心收益兑现点**。

## 4. 风险与建议

| 风险 | 影响 | 缓解 |
|---|---|---|
| bindless 替代方案选错 | 可能要重写材质系统 | **先做技术验证**（一个 cube + 1000 材质）再定方案 |
| 668 处 shader 改动 | 回归风险高 | 用宏化改造，Vulkan 侧每次改动都跑 20/20 判据 |
| D3D11 无 mesh shader | Nanite 性能大幅下降 | 走 compute 软光栅；性能目标单列 |
| 双后端维护成本 | 每个新功能都要实现两遍 | 先让 Vulkan 侧成为"参考实现"，D3D11 侧按 caps 降级 |

**建议的推进顺序**：阶段 0 → 1 → 2 →（01/02 样例跑通）→ 3（逐步）→ 4。
在 01/02 跑通之前不要碰 Nanite/Lumen —— 那是最后 20% 却占 50% 工作量的部分。

---

## 5. 明确排除

| 项 | 原因 |
|---|---|
| 光追（`BuildTLAS`/`BindRTPipeline`/05.PortTracing） | 用户明确排除；D3D11 本身也不支持 DXR 的 ray tracing pipeline |
| Mesh Shader | D3D11 不支持，Nanite 改走 compute |
| DGC（设备生成命令） | D3D11 不支持，改走间接绘制 |
| 异步计算队列 | D3D11 只有单一 context，退化为顺序执行 |
