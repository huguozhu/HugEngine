# D3D12 已知问题与未完成功能

> 整理日期：2026-10-30（分支 `dx12`，最新提交 `00b5af16`）
>
> 本文汇总三类内容：
> 1. 截至目前**尚未解决的已知问题**（含引擎层与 Vulkan 侧发现的问题）；
> 2. D3D12 后端相对 Vulkan 后端**仍未实现的大块功能**；
> 3. 本轮已实现但**有限制或未能在实际场景中验证**的功能。
>
> 已完成并提交的修复与功能见 git 日志，不在此重复；第三部分只记录后续需要注意的限制。
>
> **本机测试环境**：Intel UHD Graphics 770（无硬件光追、无网格着色器、驱动最高 SM 6.7）。
> 网格着色器等特性可用 `HE_D3D12_WARP=1` 改用 WARP 软件适配器做功能验证（WARP 支持网格着色器与 SM 6.8）。

## 一、尚未解决的已知问题

### 1.1 确认存在、尚未修复

| # | 问题 | 范围 | 现状 / 线索 |
|---|------|------|-------------|
| 1 | **打开 GPU 验证（GBV）后崩溃** | D3D12 | 原崩溃点在系统自带调试层格式化 GBV 消息的 lambda（`NDebug::CGBVMessageLog::DumpMessages`），出现在 RTX 4060 笔记本上。现已接入 Agility SDK 1.620.1，程序自带新版 `d3d12SDKLayers.dll`；本机（Intel UHD 770，系统未装调试层）用它开 GBV 跑 04 共 90 秒无崩溃、0 报错。**需在原 RTX 4060 笔记本上复测**确认是否已解决。 |
| 5 | **GPU 驱动的 GBuffer 路径未完成（可见数显示为 0）** | 引擎 | 剔除本身在工作（帧首读回 04 为 19 个可见，关掉 Hi-Z 为 41 个），显示为 0 是因为 `Dispatch` / `SignalPTG` 派发后**有意**把 `m_LastVisibleCount` 清零，让 `GBufferRenderer_GPU` 一直退回 CPU 逐物体绘制。直接放开这条路径画面错乱，查到三处问题：① 合批索引已是绝对索引、命令里又填了 `vertexOffset`，顶点被偏移两次 —— **已修**（`MeshBatcher` 改填 0）；② 间接命令用 `firstInstance = objectID`（合批顺序，全部 103 个网格）索引物体缓冲，而每帧物体缓冲是按 CPU 视锥裁剪后的绘制项（04 为 41 个）、按 SceneRenderer 的顺序填的 ⇒ 变换与材质错位，需要按 GPU 场景的全部物体、按合批顺序构建物体缓冲；③ 单阶段 / PTG 剔除只有 1 级 Hi-Z 时在全分辨率深度上只采包围盒投影 4 个角，不是保守判定，会剔掉可见物体，着色器还用包围盒最远深度做比较。②③ 修好后，绘制应改用 `DrawIndexedIndirectCount`（本帧 GPU 计数），不再依赖上一帧读回的可见数。 |
| 6 | **06 截图那一帧偶发后缓冲屏障状态不一致** | D3D12 | `HE_CAPTURE_FRAME` 截图时，截图列表的屏障起始状态（PRESENT）与后缓冲实际状态不符（调试层 id=527），随后主列表也报一次。约 6 次运行出现 1 次，之后多次复跑未再出现，原因未查明。仅影响调试截图。 |

### 1.2 功能已实现，但有限制或缺口

| # | 问题 | 说明 |
|---|------|------|
| 7 | **Vulkan 关闭了 PSO 预编译** | 本机 Intel 驱动在 Vulkan 预编译线程（`igc-default64.dll`）随机崩溃，延迟管线只在非 Vulkan 后端启动预编译。另外引擎里只有 SSAO 调用了 `PrecompileQueuePSO`，预编译覆盖面很小。 |
| 8 | **模式 2 下不支持命令流模式** | 提交路由（模式 2）下回放在 RHI 线程上、落后渲染线程最多两帧，而描述符集内容不按帧分版本：回放时拍的快照、按集内容推导的资源状态转换都已是后面帧写入的内容（实测 06.GILab 约 10 帧后 GPU 挂起）。现在有提交路由时帧主列表自动退回直接录制。要支持需在录制时拍描述符快照并解析资源状态。 |
| 9 | **命令流模式下不绘制 ImGui** | ImGui 直接往原生列表录制，且绘制数据在下一帧 `NewFrame` 后失效，不能推迟到提交时回放；`HE_RHI_COMMAND_STREAM=1` 时跳过 ImGui 并打一次警告。 |
| 10 | **网格着色器在 WARP 上打开 Nanite 网格通道后崩溃** | 网格管线（MeshTest / HardRaster）在 WARP 上创建成功，但设置 `nanite_mesh_test=1`、`nanite_hard_raster=1` 后程序访问空指针崩溃，无符号调用栈，尚未区分是网格绘制本身还是 Nanite 在 D3D12 上的原有问题。留到有 NVIDIA 独显的设备上排查。 |
| 11 | **SM 6.8 特性未启用** | Agility SDK 已接入，但本机 Intel 驱动最高 SM 6.7，着色器仍按 6.6 编译；实例号仍用逐实例序号缓冲绕行（`kInstanceIndexSlot`），需在支持 SM 6.8 的设备上改用 `SV_StartInstanceLocation`。 |

| 17 | `ClearDepthStencil` | 唯一调用方是 05 路径追踪的粒子深度，本机不支持光追、05 无法运行。 |

## 二、D3D12 后端未完成的大块功能

| # | 功能 | D3D12 现状 | 影响 | 实现要点 |
|---|------|-----------|------|----------|
| 1 | **光线追踪（DXR）** | `CreateBLAS` / `CreateTLAS` / `CreateRTPipelineState` 返回空，`GetBLASBuildSizes` / `GetTLASBuildSizes` 返回空尺寸；`BuildBLAS` / `BuildTLAS` / `BindRTPipeline` / `TraceRays` 空实现；句柄版接口未覆盖；加速结构调试命名未覆盖 | 05.Sponza-PathTracing、RT 相关 GI 在 D3D12 下不可用（设备能力报“RT 不支持”） | `ID3D12Device5` 加速结构、状态对象（`ID3D12StateObject`）、着色器表；Slang 需输出 DXR 库（`lib_6_x`），ShaderToDxil 支持 lib 目标。**留到有 NVIDIA 独显的设备上做**（本机 Intel UHD 770 不支持 DXR） |

### 已决定不实施

| 功能 | 原因 |
|------|------|
| 轻量 Begin（`BeginLightweight`） | 默认实现即调用 `Begin()`。D3D12 的 Begin 只轮换本列表自己的帧槽位，没有 Vulkan 那样的全局帧计数推进与延迟销毁副作用，默认实现已正确。 |
| 渲染通道提示（`ID3D12GraphicsCommandList4::BeginRenderPass` 的加载 / 存储提示） | 只对分块渲染（TBDR）的移动端 GPU 有收益，桌面 GPU 几乎无差别。引擎在 pass 中间会为绘制补资源状态转换、切换只读深度视图（需要 `OMSetRenderTargets`），与原生渲染通道的限制冲突，改动面大且本机无法测出收益。 |

## 三、本轮实现的功能与相关开关

| 功能 | 说明 / 开关 |
|------|------|
| 深度模板清除、存储图像查询 | `ClearDepthStencil`、`SupportsStorageImage`（深度格式在 D3D12 下恒不支持 UAV） |
| 异步计算状态处理 | 计算列表过滤图形专用状态，图形队列先做交接转换、计算队列等待后执行 |
| 网格着色器 | 管线状态流创建网格 PSO，`DispatchMesh` 与 `DISPATCH_MESH` 命令签名；`*.mesh` / `*.task` 生成 DXIL。见 1.2-10 |
| DGC 等价实现 | DRAW_INDEXED 命令签名 + 带计数缓冲的 `ExecuteIndirect`，缓冲按 GPU 地址登记反查 |
| PSO 创建限流 | `EnqueuePSOCreate` / `ProcessPSOCreateQueue` / 句柄版占位创建 |
| Agility SDK 1.620.1 | configure 时从 nuget.org 下载并校验 SHA256（`cmake/AgilitySDK.cmake`，`HUGENGINE_D3D12_AGILITY` 可关闭）；样例 exe 导出 `D3D12SDKVersion` / `D3D12SDKPath`，运行时放在 exe 旁的 `D3D12\` 子目录，**缺少该目录时建设备失败**（日志有明确提示） |
| 瞬态纹理内存别名 | RenderGraph 传入生命周期，生命周期不重叠的纹理共用内存。见 1.3-14 |
| 提交路由（模式 2） | `HE_RENDER_THREADING_MODE=2`：Submit / Present 交给 RHI 线程；命令列表按帧槽位各持原生列表，提交数据打包入队 |
| 命令流模式 | `HE_RHI_COMMAND_STREAM=1`：帧主列表录成数据流，提交时回放到影子列表。见 1.2-8、1.2-9 |
| WARP 适配器 | `HE_D3D12_WARP=1`：改用 WARP 做功能验证 |

### 建议顺序

1. **复测 GBV 崩溃（1.1-1）**：在原 RTX 4060 笔记本上开 `HE_D3D12_GPU_VALIDATION=1` 复现，确认 Agility 调试层是否已解决。
2. **GPU 剔除可见数为 0（1.1-5）**：它让 GPU 驱动的 GBuffer、DGC、间接绘制路径都走不到，修好后才能真正验证 1.3-16。
3. **Lumen 计数竞争（1.1-2）、缩放泄漏（1.1-3）、日志清理（1.1-4）、NaniteRaster 绑定核实（1.4-18）**：引擎侧问题，工作量小。
4. **有 NVIDIA 独显后**：DXR（二-1）、网格着色器崩溃排查（1.2-10）、SM 6.8 去掉实例号绕行（1.2-11）。
5. **模式 2 下支持命令流（1.2-8）**：在实际需要渲染线程与提交线程分离录制时再做。
