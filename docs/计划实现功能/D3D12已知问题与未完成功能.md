## 一、尚未解决的已知问题

### 1.1 确认存在、尚未修复

| # | 问题 | 范围 | 现状 / 线索 |
|---|------|------|-------------|
| 1 | **打开 GPU 验证（GBV）后崩溃** | D3D12 | 用下载的 d3d12SDKLayers 符号符号化后，崩溃点在调试层自身格式化 GBV 消息的 lambda（`NDebug::CGBVMessageLog::DumpMessages`）。已排除：描述符内容、ImGui 字体槽、根参数表范围、`BufferBarrier`、资源状态跟踪（`DISABLE_STATE_TRACKING` 仍崩）、句柄错配（句柄 8/1/9 均有效）、越界访问。根因未知。 |
| 2 | **Lumen 统计与反馈计数存在 CPU/GPU 读写竞争** | 引擎 | CPU 直接读 GPU 仍在写的映射缓冲：反馈请求数 D3D12 为 2040、Vulkan 为 14；命中与辐照度统计持续累积。只修了屏幕探针计数（改为 GPU 时间线清零 + 读回已完成帧的副本），其余计数需按同样方式改造。 |
| 3 | **每次窗口缩放泄漏一个描述符集**（约 22 个槽） | 引擎 | Vulkan 下同样增长，属于引擎侧缩放重建流程未释放旧集。 |
| 4 | **其它模块每帧刷日志** | 引擎 | RenderGraph 的每帧日志已降为 TRACE（16 秒日志行数从 39770 降到 13124）。仍每帧输出的有：`[CSMB]` / `[CSMP]` 的 printf；粒子调试（Particle / EmitIndirect / DrawArgs / DeadList / Counters / AlivePre / AlivePost）；`TransientAllocator` 切换堆；DDGI 网格拟合；D3D12 纹理创建处的 `[TEX-BIG]`（用的是 ERROR 级别）。 |

### 1.2 功能已实现，但有限制或缺口

| # | 问题 | 说明 |
|---|------|------|
| 5 | **异步计算列表不处理图形专用状态** | D3D12 的计算列表上不能做涉及 `PIXEL_SHADER_RESOURCE` / `RENDER_TARGET` / `DEPTH_*` 的状态转换，而现有资源状态跟踪是设备级、不区分队列。现有样例的异步计算 pass 数为 0，因此暂不出错；一旦有真正的异步 pass，很可能触发调试层错误。需要：计算列表转换时过滤图形状态，或由图形队列在交接前转到计算可用状态。 |
| 6 | **瞬态纹理只做帧内线性分配** | ① 放在复用内存上的渲染目标 / 深度纹理内容未定义，未发 `DiscardResource` / 清除做初始化，依赖使用方先清除；② 没有按 RenderGraph 计算出的别名池做同帧内存复用，也没有别名屏障（`D3D12_RESOURCE_BARRIER_TYPE_ALIASING`）。 |
| 7 | **Vulkan 关闭了 PSO 预编译** | 本机 Intel 驱动在 Vulkan 预编译线程（`igc-default64.dll`）随机崩溃，延迟管线只在非 Vulkan 后端启动预编译。另外引擎里只有 SSAO 调用了 `PrecompileQueuePSO`，预编译覆盖面很小。 |

### 1.3 已修复，但未能在实际场景中触发验证

| 8 | Profiler 在有异步 pass 时改在计算列表上重置查询池 | 样例中异步计算 pass 数为 0，该路径未被执行。 |
| 9 | D3D12 多线程录制（bundle 实现的二级命令列表） | 样例绘制数达不到 64 条的并行门槛，正常运行不走并行路径；仅在临时降低门槛时验证过（03 / 06 画面与基线一致、调试层 0 报错）。 |
| 10 | D3D12 瞬态纹理 | 样例中 RenderGraph 自建纹理数为 0（全部为导入资源）；仅用临时自检验证过分配、峰值扩容与回退。 |

## 二、D3D12 后端未完成的大块功能

下表对照 `IRHIDevice` / `IRHICommandList` 接口与 Vulkan 后端，列出 D3D12 仍为空实现或使用默认实现的部分。

| # | 功能 | D3D12 现状 | 影响 | 实现要点 |
|---|------|-----------|------|----------|
| 1 | **光线追踪（DXR）** | `CreateBLAS` / `CreateTLAS` / `CreateRTPipelineState` 返回空，`GetBLASBuildSizes` / `GetTLASBuildSizes` 返回空尺寸；`BuildBLAS` / `BuildTLAS` / `BindRTPipeline` / `TraceRays` 空实现；句柄版接口（`CreateBLASHandle` / `CreateTLASHandle` / `CreateRTPipelineStateHandle`）未覆盖 | 05.Sponza-PathTracing、RT 相关 GI 在 D3D12 下不可用（设备能力报“RT 不支持”） | `ID3D12Device5` 加速结构、状态对象（`ID3D12StateObject`）、着色器表；Slang 需输出 DXR 库（`lib_6_x`）；ShaderToDxil 支持 lib 目标 |
| 2 | **网格着色器** | `DrawMeshTasks` / `DrawMeshTasksIndirect` / `DrawMeshTasksIndirectCount` 空实现 | Nanite 硬件光栅路径（`NaniteRaster` 调用 `DrawMeshTasks`）在 D3D12 下不绘制 | `ID3D12GraphicsCommandList6::DispatchMesh`；网格着色器 PSO 需用 `D3D12_PIPELINE_STATE_STREAM_DESC`；间接版用 `DISPATCH_MESH` 命令签名 |
| 3 | **设备生成命令（DGC）** | `InitializeDGC` 等未覆盖、`ExecuteGeneratedCommands` 用默认空实现 | `GBufferRenderer_GPU` 的 DGC 路径不可用（会回退普通 ExecuteIndirect） | 用带状态切换参数（根常量 / 顶点缓冲视图 / 索引缓冲视图）的命令签名 + `ExecuteIndirect` 实现等价语义 |
| 4 | **PSO 创建限流 / 句柄版异步创建** | `EnqueuePSOCreate` / `ProcessPSOCreateQueue` / `GetPendingPSOCreateCount` / `EnqueuePSOCreateHandle` 未覆盖 | 依赖逐帧限流创建 PSO 的调用方在 D3D12 下拿不到 PSO | 队列 + 每帧取若干个创建；句柄版先登记占位句柄再填充；可复用已实现的 PSO 缓存块 |
| 5 | **命令流模式 / 提交线程路由** | `EnableCommandStream`、`SetSubmitRouter` / `ExecuteSubmit` / `ExecutePresent` 未覆盖 | 渲染线程录制、提交线程回放的架构（L4-3）在 D3D12 下不可用 | 参照 Vulkan 的回放列表实现 |
| 6 | **深度模板清除（命令列表接口）** | `ClearDepthStencil` 用默认空实现 | 路径追踪管线每帧把粒子深度清成远平面的调用在 D3D12 下无效（`PathTracingPipeline.cpp`） | 转到 `DEPTH_WRITE` 后 `ClearDepthStencilView`，需要该纹理的 DSV |
| 7 | **深度格式存储图像查询** | `SupportsStorageImage` 用默认实现恒返回 false | Nanite 深度存储图像路径在 D3D12 下按不支持处理 | `CheckFeatureSupport(D3D12_FEATURE_FORMAT_SUPPORT)` 查询 `TYPED_UNORDERED_ACCESS_VIEW` |
| 8 | **Shader Model 6.8 / Agility SDK** | 未接入 Agility SDK，系统 D3D12Core 最高 SM 6.7 | 无 `SV_StartInstanceLocation` 等新特性（实例号已用逐实例序号缓冲绕过）；DXR 1.1 / 新特性受限 | 随程序附带 `D3D12Core.dll` 并导出 `D3D12SDKVersion` / `D3D12SDKPath` |
| 9 | **异步计算的状态与所有权** | 跨队列所有权转移（`QueueOwnershipTransfer` / `ReleaseToQueue` / `AcquireFromQueue`）为空操作；计算列表不过滤图形状态 | 见 1.2-5 | D3D12 无需所有权转移，但需保证交接时资源处于双方队列都可用的状态 |
| 10 | **瞬态纹理的真正内存别名** | 帧内线性分配，无同帧复用 | 见 1.2-6，显存占用未减少 | 按 RenderGraph 的别名池分配同一偏移，交接处发别名屏障，首次使用前 `DiscardResource` |
| 11 | **轻量 Begin、渲染通道提示** | `BeginLightweight`、`SetRenderPassHint` 用默认实现 | 功能等价，无性能优化 | 可选：`BeginRenderPass`（`ID3D12GraphicsCommandList4`）利用 tile 化 GPU 的加载 / 存储提示 |
| 12 | **加速结构调试命名** | `SetResourceDebugName(IRHIAccelerationStructure*)` 未覆盖 | 依赖第 1 项 | 随 DXR 一并实现 |

### 建议顺序

1. **深度模板清除（#6）、存储图像查询（#7）**：工作量小，直接影响现有路径的正确性。
2. **异步计算状态处理（1.2-5 / #9）**：在出现真正的异步 pass 之前补上。
3. **网格着色器（#2）**：Nanite 硬件光栅依赖。
4. **DGC 等价实现（#3）、PSO 限流（#4）**。
5. **Agility SDK（#8）→ DXR（#1）**：DXR 依赖较新的运行时与着色器模型，适合放在 Agility SDK 接入之后。
6. **瞬态纹理真正别名（#10）、命令流模式（#5）**：在有实际使用场景后再做。
