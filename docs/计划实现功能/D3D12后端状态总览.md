### 1.2 各任务详情

#### T1 复测 GPU 验证（GBV）崩溃

- **原问题**：打开 GBV 后崩溃，崩溃点在系统自带调试层格式化 GBV 消息的 lambda（`NDebug::CGBVMessageLog::DumpMessages`）。此前已排除描述符内容、ImGui 字体槽、根参数范围、`BufferBarrier`、状态跟踪、句柄错配、越界访问。
- **根因**：崩溃发生在系统自带调试层；程序改用 Agility SDK 1.620.1 自带的 `d3d12SDKLayers.dll` 后不再复现。
- **做法**：依次运行 02 / 04 / 06 / 07，设置 `HE_D3D12_DEBUG_LAYER=1` + `HE_D3D12_GPU_VALIDATION=1`，确认日志「运行时」一行指向 exe 旁的 `D3D12\D3D12Core.dll`。若仍崩：用 `cmake --preset default -DHUGENGINE_D3D12_AGILITY=OFF` 换回系统调试层对比；用 `HE_D3D12_DRED=1` 找出事的命令列表与 pass 名；再按 GI 源 / Nanite / 粒子二分定位。注意不要只删 `D3D12\` 目录：exe 导出了 `D3D12SDKVersion`，缺目录时建设备会直接失败。
- **验证数据**：RTX 4060 Laptop 上 02 / 04 / 06 / 07 各 45 s：无崩溃，`[D3D12 ERROR]` 0 条，`GPU-BASED VALIDATION` 报错 0 条。此前在 Intel 本机用同配置开 GBV 连续 90 秒也无崩溃、0 报错。
- **遗留**：复测时长为每样例 45 s，短于指南建议的 2 分钟；验证依赖 Agility 的 `D3D12\` 目录。

#### T2 复核 Lumen 统计读数

- **原问题**：`LumenStatsReadback` 改造后，D3D12 与 Vulkan 的同名统计量级不一致，且会逐帧累积；原记录提到同名统计曾出现 2040 对 14 的量级差。原实施记录称本机（Intel UHD 770）Lumen「每帧 25 秒」，统计未能在合理时间内跑出，故转到 4060 复核。
- **根因**：统计回读与 GPU 时间线未对齐（旧路径会读到未完成 / 更早的值并逐帧累积）；Lumen 远场与 DDGI 缺少 DXIL；远场结果缓冲在重建时存在释放竞争。
- **做法**：追踪 / 着色 / SH / 辐照度 / 探针滤波 / 远场对照与合并 / 距离分桶统计统一改为「GPU 时间线清零 + 读 `kMaxFramesInFlight` 帧前的回读副本」；反馈请求槽位为 `kMaxFramesInFlight + 1`，读已执行完的那份。补齐 Lumen 远场与 DDGI 的 DXIL；远场结果缓冲按 1.25 倍预留，重建前 `WaitIdle`，`BuildAS` 对空映射显式跳过。复核时对照日志里每 40 帧一次的各步读数：`LumenScene 探针追踪（步骤 21）`、`LumenScene 逐像素辐照度（步骤 24）`、`LumenScene 探针滤波（步骤 35）`、`Lumen Feedback CPU 分解（步骤 37）… 请求 N 条`。
- **验证数据**：06.GILab 1801 帧，0 设备丢失、0 报错；逐像素辐照度均值 0.456 对 Vulkan 0.430（改前 0.047 对 0.433）。
- **遗留**：远场与 SDF 的相对差一致性仍低于 Vulkan；绝对辐照度已对齐。

#### T3 网格着色器：硬件验证与 WARP 崩溃排查

- **原问题**：网格着色器在 Intel 上未做硬件验证；WARP 上设置 `nanite_mesh_test=1`、`nanite_hard_raster=1` 后访问空指针崩溃，且无符号栈；`GBuffer.mesh` 仍是未完成的桩。
- **根因**：WARP 崩溃是访问空指针（具体栈未符号化），后随二维派发与材质 bindless 落位修复消失。DXIL 校验要求 `SetMeshOutputCounts` 只调用一次且支配所有输出写入。
- **做法**：网格管线经管线状态流创建（`D3D12PipelineState::InitializeMeshPso`）；`*.mesh.slang` / `*.task.slang` 生成 `ms_6_6` / `as_6_6` DXIL（`Engine/Shader/CMakeLists.txt`）；`ShaderToDxil` 用 `PatchMeshSignature` 修正 Slang 输出的参数修饰；`Nanite_HardRaster.mesh.slang` 已重写为 `hardRasterSelectCluster` 统一返回三角形数，且**不要**在 `SetMeshOutputCounts` 后紧跟 `if (count == 0) return;`，dxc 优化会把调用复制成两份。硬光栅改为二维派发，宽 `kNaniteRasterDispatchWidth = 1024`，网格组数单维上限 65535。
- **验证数据**：RTX 4060 上 `nanite_mesh_test=1`：`网格管线创建成功 name=NaniteMeshTest MS=3432B`，日志无 `[D3D12 ERROR]`；再加 `nanite_soft_raster=1` + `nanite_hard_raster=1`，软 / 硬光栅四个计算 PSO 与 `NaniteHardRaster` 图形 PSO 均创建成功、无崩溃。WARP 上（`HE_D3D12_WARP=1`）网格管线同样创建成功，不再崩溃。
- **遗留**：`GBuffer.mesh` 桩仍未生成 DXIL；`D3D12PipelineState::IsMesh()` 为真时 `SetPipeline` 仍会设图元拓扑（无害）；网格管线的资源状态转换依赖 DXIL 反射（`Initialize` 已把 `meshShader` / `amplificationShader` 纳入反射）。

#### T4 Nanite 软光栅在 D3D12 下画面错误

- **原问题**：只开 Nanite 时正常；`nanite_enable=1` + `nanite_soft_raster=1` 后场景几何几乎全部消失，只剩天空与远景。此前已修两处（材质数组落错 space、派发超限），修后调试层与 GPU 验证 0 报错，但画面仍错。
- **根因**：不是 D3D12 后端缺陷。`nanite_soft_max_triangles=16` 把绝大多数簇分流给硬光栅，D3D12 与 Vulkan 表现一致；复核表明真因不在深度键 / 深度解析这条链路，「整屏只剩天空」只是分流后的表象。
- **做法**：按五趟数据流逐段检查：`Nanite_GBufferClear.comp` 清 8 张 GBuffer → A 趟 `Nanite_SoftRasterDepth.comp` 逐像素 `InterlockedMin(u_DepthKey[p], key)` → B 趟 `Nanite_SoftRasterWinner.comp` 用 `InterlockedMin(u_WinnerID[p], 候选号)` 选确定性赢家 → C 趟 `Nanite_SoftRaster.comp` 等值复检后写 4 张 GBuffer → `Nanite_DepthResolve.frag` 全屏三角形按深度键输出 `SV_Depth`（哨兵 `0xFFFFFFFF` 写 1.0 远平面，PSO 为 `depthTest=true` + `Always` + `depthWrite=true`）。用 PIX / RenderDoc 检查 `u_DepthKey`、派发参数、绑定缓冲、GBuffer 与深度附件；用 `NaniteRaster::ReadbackSoftStats`（`kNaniteSoftStat*`：像素数、深度解析像素数、ties 等）与 Vulkan 逐项对比。
- **验证数据**：RTX 4060 上 `nanite_soft_raster=1`：`ReadbackSoftStats` 与 Vulkan 逐字段相同、GBuffer 五张落盘图 MD5 逐位相同、hdr 均值 0.17205 对 0.17206、0 报错。
- **遗留**：无代码遗留。对比时需确认两边 `nanite_soft_max_triangles` 配置一致，否则软光栅看起来「几乎没画东西」是预期分流。

#### T5 光线追踪（DXR）

- **原问题**：D3D12 后端没有光追实现；`D3D12Device::CreateDeviceAndQueue` 里 `m_Caps.supportsRayTracing = false;` 写死；Storage 缓冲的堆类型、DXIL 库、状态对象、SBT、RayQuery 全部缺失。
- **根因**：缺少 `D3D12RayTracing` 模块，光追能力探测被硬编码关闭。
- **做法**：
  - 新增 `D3D12RayTracing.h/.cpp` 与 `D3D12AccelerationStructure`：BLAS / TLAS 用 DEFAULT 堆缓冲 + `ALLOW_UNORDERED_ACCESS`，初始及常驻状态 `D3D12_RESOURCE_STATE_RAYTRACING_ACCELERATION_STRUCTURE`；`GetRaytracingAccelerationStructurePrebuildInfo` 取构建尺寸；`BuildRaytracingAccelerationStructure` 后对 AS 发 UAV 屏障。
  - 光追 PSO 用 `ID3D12Device5::CreateStateObject`；组句柄用 `ID3D12StateObjectProperties::GetShaderIdentifier`，每组 32 字节；着色器表起始 64 字节对齐；`maxRayRecursionDepth = 31`（`D3D12_RAYTRACING_MAX_DECLARABLE_TRACE_RECURSION_DEPTH`）。
  - `BindRTPipeline` 用 `SetPipelineState1` + `SetComputeRootSignature`；AS 型描述符写 SRV 时 `ViewDimension = D3D12_SRV_DIMENSION_RAYTRACING_ACCELERATION_STRUCTURE`，`RaytracingAccelerationStructure.Location = AS 的 GPU 地址`，`pResource = nullptr`。
  - 全局根签名与图形 / 计算共用布局：8 个根 CBV + 每个 space 的 SRV / UAV / 采样器表；推送常量仍走根 CBV `b0` 常量环。
  - SBT 缓冲用 UPLOAD 堆（CPU 写、GPU 读，状态 `GENERIC_READ`）；scratch 用 DEFAULT 堆 + `ALLOW_UNORDERED_ACCESS`（构建前转 `UNORDERED_ACCESS`）；TLAS 实例缓冲用 UPLOAD 堆（CPU 每帧 `Map` 写 64 字节，GPU 地址 64 KB 对齐，满足 16 字节要求）。
  - 几何与实例：`RGB32_FLOAT` → `DXGI_FORMAT_R32G32B32_FLOAT`，索引 `R32_UINT` / `R16_UINT`，`IndexCount = maxPrimitiveCount * 3`，`Transform3x4` 可为 0。构建标志映射 `ALLOW_UPDATE` / `ALLOW_COMPACTION` / `PREFER_FAST_TRACE` / `PREFER_FAST_BUILD` / `MINIMIZE_MEMORY`；update 时加 `PERFORM_UPDATE` 并设 `SourceAccelerationStructureData`。TLAS 实例是 64 字节布局，与 `D3D12_RAYTRACING_INSTANCE_DESC` 逐字段一致（3×4 行主序变换、InstanceID:24、Mask:8、ContributionToHitGroupIndex:24、Flags:8、BLAS GPU 地址），实例标志数值也相同（1 剔除关闭 / 2 逆时针为正面 / 4 强制不透明 / 8 强制非不透明），可直接作为 `InstanceDescs`，`DescsLayout = ARRAY`。
  - DXIL 库：`RT_SLANG` 增加 DXIL 段，按 `.rgen/.rmiss/.rchit/.rahit/.rcall/.rint` 选 stage，`ShaderToDxil` 对 `lib` 默认 `lib_6_6`；状态对象用 `D3D12_EXPORT_DESC` 把每个库的 `main` 重命名为 `S<序号>`，命中组导出 `H<组序号>`；`PatchRegisters` 为 `RaytracingAccelerationStructure` 生成 `register(t0, space0)`；库反射改用 `ID3D12LibraryReflection` 遍历每个函数的绑定资源。
  - `TraceRays`：按 `BuildSBT` 的 `RayGen → Miss → Hit → Callable` 布局，段大小取「下一段起点 − 本段起点」，最后一段取「缓冲大小 − 起点」；`stride` 为 0 的段 `SizeInBytes` 也设为 0；调用前 `EnsureBoundResourceStates()`、`FlushRootArgs()`（`BindRTPipeline` 把 `m_IsComputePipeline` 置真），之后 `AfterDrawOrDispatch()`。
  - RayQuery 只需 TLAS 的 SRV 与 SM 6.5+（DXIL 已 6.6），`RaytracingTier >= 1.1` 即可，不需要状态对象。
  - 加速结构永远停在 `RAYTRACING_ACCELERATION_STRUCTURE` 状态，`EnsureBoundResourceStates` 与设备状态跟踪跳过它（SRV 的 `pResource` 为空，`GetSetResource` 返回空即跳过）。
- **验证数据**：RTX 4060 上 05.Sponza-PathTracing（`HE_D3D12_RT=1`）稳定运行，调试层与 GPU 验证 0 报错，截图 978 KB，与 Vulkan 同帧落盘统计量一致。
- **遗留**：RT 管线的 FXAA 在 D3D12 下偏暗，已默认关闭（`HE_PT_FXAA=1` 可复查）；`ClearDepthStencil`（05 粒子深度）与 06 的 DDGI 光追、RT 反射、Lumen 远场的专项截图对照未单列结果。

#### T6 SM 6.8：用 `SV_StartInstanceLocation` 去掉实例号绕行

- **原问题**：D3D12 的 `SV_InstanceID` 不含起始实例，而 Vulkan 的 `gl_InstanceIndex` 含。原绕行是 `ShaderToDxil` 的 `PatchInstanceId` 把 `SV_InstanceID` 改成逐实例属性 `HE_INSTANCEINDEX`，PSO 在 `kInstanceIndexSlot = 14` 绑一个 `0,1,2,…` 的序号缓冲（`D3D12Device::GetInstanceIndexBufferView`，容量 `kInstanceIndexCount = 1<<20`），IA 取逐实例数据时自动加上起始实例。
- **根因**：两个 API 的实例号语义不同。
- **做法**：顶点着色器目标改 `vs_6_8`；`ShaderToDxil` 把 `SV_InstanceID` 改为「`SV_InstanceID` + 新增参数 `uint heStart : SV_StartInstanceLocation`」，并在入口首行累加；删除 `HE_INSTANCEINDEX` 属性、14 号输入槽与 1M 项实例序号缓冲及相关反射逻辑。
- **验证数据**：01 / 02（10000 实例）/ 04 / 05（光追）/ 07 均 0 报错。
- **遗留**：D3D12 后端自此要求 SM 6.8 设备；Intel UHD 770（SM 6.7）无法运行，未保留 6.7 双变体（原方案 B）。

#### T7 GPU 驱动的 GBuffer 路径

- **原问题**：`gbuffer_mode=1`（GPU 模式）下 GBuffer 一直走 CPU 回退。`GPUCulling::Dispatch` / `SignalPTG` 派发后把 `m_LastVisibleCount` 清零，`GBufferRenderer_GPU` 因 `visCount == 0` 回退；剔除本身在工作（修复前 04 帧首读回 19 个可见，关 Hi-Z 为 41 个）。
- **根因**：① 间接命令以 `firstInstance = objectID` 索引物体缓冲，`objectID` 是合批顺序（全部网格，04 为 103 个），而每帧物体缓冲由 `SceneRenderer::Prepare` 按 CPU 视锥裁剪后的绘制项（04 为 41 个）、按自己的顺序填写；② 单阶段 / PTG 剔除在只有 1 级 Hi-Z（`m_HiZMipCount = 1`）时，`PersistentCull.comp.slang` 的 `IsOccluded` 在全分辨率深度上只采包围盒投影的 4 个角，不保守，且用包围盒最远深度 `max(ndc.z)` 与样本比较，保守判定应使用最近深度。
- **做法**：去掉 `Dispatch` / `SignalPTG` 里把 `m_LastVisibleCount` 清零的代码；`GBufferRenderer_GPU` 的条件改为「GPU 剔除开启 + 间接缓冲与计数缓冲有效」，绘制改 `DrawIndexedIndirectCount(indirectBuf, 0, countBuf, 0, GPUCulling::kMaxObjects, sizeof(IndirectDrawCommand))`（本帧 GPU 计数），DGC 分支的 `maxDrawCount` 同样改为 `kMaxObjects`，`m_LastVisibleCount` 只作上一帧统计。对齐合批序号 / GPUScene 下标 / `firstInstance` / 物体缓冲下标，使间接命令的 `objectID` 与物体缓冲条目一一对应；`MeshBatcher` 的间接命令与 DGC 序列 `vertexOffset` 改为 0（合批索引本身已是绝对索引）；Hi-Z 改取最近点并修正 NDC→UV 的 Y 轴；GBuffer 片元改用顶点阶段传入的 `objectIndex` 取材质；实例化网格仍走 `InstanceCuller`，物体缓冲上限 `kGPUMaxObjects = 1024`。
- **验证数据**：04 实测：GPU 可见 40（Vulkan 同为 40）、GPU 与 CPU 3D 区域平均差 0.0104（上一轮 CPU 模式两次运行之间为 0.01）、0 报错。回退开关 `HE_DISABLE_GPU_GBUFFER=1`。
- **遗留**：DGC 分支仍被 `kDGCEnable=false` 关闭；物体缓冲上限 1024；实例化网格不进合批；GPU / CPU 仍有约 0.0104 的平均差，属于光栅化与剔除细节差异，非结构性错误。

#### T8 PSO 预编译

- **原问题**：PSO 只在需要时创建，运行中途切换 GI 源 / 管线会出现单帧尖峰；启动预编译只在非 Vulkan 后端开启，且引擎只有 SSAO 调用了 `PrecompileQueuePSO`。
- **根因**：Vulkan 预编译线程在本机 Intel 驱动（`igc-default64.dll`）上随机崩溃，因此只在非 Vulkan 后端启动；覆盖面也不足。
- **做法**：新增 `BeginPSOPrecompileBatch` / `EndPSOPrecompileBatch`（默认空实现，Vulkan 不变）；`DeferredPipeline::Initialize` 在批内批量预编译。D3D12 预编译线程创建 PSO 并 `StorePsoBlob` 保存驱动缓存块，之后同描述的 PSO 以 `CachedPSO` 创建。
- **验证数据**：02.Cube 与 04 的「PSO 预编译完成」由 3/3 提升到 46/46、06.GILab 到 56/56；初始化后再创建的 PSO 由 5 个降到 2 个；04 初始化 4.93 s → 4.39 s。
- **遗留**：Vulkan 侧「按厂商判断（Intel 仍关闭、其余开启）」在现有记录中未见落实；预编译只对运行中途才创建的 PSO 有意义，具体清单仍需靠临时调试记录确认。

#### T9 截图偶发的后缓冲屏障报错

- **原问题**：06 用 `HE_CAPTURE_FRAME` 截图时偶发调试层 id=527：截图列表的 `StateBefore = PRESENT` 与后缓冲实际状态不符，随后主列表的 `RENDER_TARGET → …` 转换再报一次。约 6 次运行出现 1 次。
- **根因**：后缓冲有两套状态记录：交换链的 `m_BackBufferState`（`BeginRenderPass` 置 RENDER_TARGET，Present 置回 PRESENT）与设备的资源状态表（`BeginOffscreenPass` 以后缓冲 RTV 为附件时经 `FindViewResource` 登记 RENDER_TARGET）。若某帧只经后者写后缓冲，`m_BackBufferState` 仍是 PRESENT：Present 不发 `→ PRESENT` 屏障，截图以 PRESENT 为起点，而设备表认为它是 RENDER_TARGET。
- **做法**：后缓冲状态并入设备状态表：`CreateBuffers` 登记 RTV 与资源并置 PRESENT；Present 与 `BeginRenderPass` 的 `StateBefore` 查设备表；离屏 pass 以后缓冲为附件时同步镜像；呈现屏障失败改为报错；Resize 注销旧登记。
- **验证数据**：06.GILab 连续 10 次截图运行（`HE_CAPTURE_FRAME=150`，每次约 40 秒）：0 条 `[D3D12 ERROR]`、0 条 id=527。原排查步骤为循环运行 20 次以上统计出现率。
- **遗留**：无已知遗留；如需更高置信度可把循环加到 20 次以上。

#### T10 模式 2 下支持命令流

- **原问题**：提交路由（模式 2）下，RHI 线程的回放落后渲染线程最多两帧，而描述符集内容不按帧分版本：回放时拍的描述符快照、`EnsureBoundResourceStates` 按集内容推导的资源状态转换，用的都是后面帧写入的内容（实测 06 约 10 帧后 GPU 挂起）。当时有路由时 `D3D12CommandList::EnableCommandStream` 自动关闭流模式。
- **根因**（流模式把一切「依赖可变引擎状态」的解析都推迟到了回放时）：
  1. `PrepareSetTables` 在回放时才拍描述符快照，内容是录制之后帧写入的；
  2. `EnsureBoundResourceStates` 在回放时才按 PSO 反射 + 集内容 + 设备纹理状态表推导转换，导致屏障 `StateBefore` / 目标资源错位；
  3. pass 附件（RTV / DSV）转换、显式纹理屏障、拷贝的临时转换同样在回放时才查设备状态表；
  4. 回放列表在 RHI 线程上写设备状态表，与录制线程下一帧的写并发（既错序又是数据竞争）。
- **做法**：「录制期解析 + 回放纯命令」。
  1. **录制期解析**（`D3D12CommandList` 的 `m_StreamMode` 分支）：`PrepareSetTables` 在流模式下立即 `SnapshotDescriptorSet` 并编码 `CmdResolvedDescriptorTables`（set / srv / uav / sampler 的 GPU 句柄随流走，相当于「描述符集内容按帧分版本」）；`EnsureBoundResourceStates`、pass 附件转换（新增 `ResolveAttachmentTransitions`）、`PipelineBarrier(texture)`、`CopyBuffer` / `CopyTextureToTexture` / `CopyTextureToBuffer` / `ClearDepthStencil` 的状态转换在录制期算好，经 `EmitBarrier` 编码 `CmdResolvedBarrier`（转换 / UAV / 别名 / Discard 四种 op）；设备级纹理状态表只在录制线程上更新；缓冲状态仍按列表从 COMMON 起跟踪（录制期算）；绘制 / 派发统一走 `StreamDrawPrologue`（补资源状态 + 拍描述符表）→ 命令入流 → `StreamDrawEpilogue`（绘制后屏障 + 消费常量槽）。
  2. **回放纯命令**：回放列表 `MarkAsReplayList()` 后跳过 `PrepareSetTables` / `EnsureBoundResourceStates` / `TransitionBuffer` / 各类转换，只执行流里的数据；新增 `ApplyResolvedBarrier` / `ApplyResolvedDescriptorTable` / `ApplyResolvedRenderTargets` 三个 RHI 入口。
  3. **生命周期 / 帧槽位**：录制期拍下的描述符快照块掩码经 `RHICommandList::AuxMask` 随流交接，回放提交后按回放列表的围栏 `MarkSetRingChunks` 登记，GPU 用完之前不会覆盖；命令流槽位 = 飞行帧数 + 1（背压允许渲染线程领先 2 帧，而 Begin 在 Submit 之前，多留一槽才不会覆盖仍在回放的流）；影子列表在渲染线程上先创建（`CreateCommandList` 会登记设备命令列表表，非线程安全）。
  4. **失效场景回退**：命令流无法承载的调用（光追 BLAS / TLAS 构建、RT 管线绑定、`DispatchRays`）会把列表标成 `m_StreamFallback` 并打印明确原因，从下一帧起帧主列表改回直接录制（本帧不挂起、不静默丢整帧）。
  5. **顺带修的既有缺陷**：除 06 外的样例（02 / 03 / 04 / 05 / 07）都没给 `RenderThread` 登记设备，壳模式泵帧时 `RenderThreadContext.device` 为空，导致各 pass 的 `ResB` / `ResT` 解析恒为 nullptr 后空指针。现在 `RenderThread::PumpOnce` 在未登记时退回进程级 RHI 设备（各样例都调过 `rhi::SetDevice`），02.Cube 也补上了显式的 `renderThread.SetDevice`。

### 1.4 规划六阶段的完成情况

**规划基线（原《D3D12 后端实现规划》第 1、2、6 节）**

- **规模基线**：目标是功能与 Vulkan 后端完全等价；基于 `main` 分支 `4e14fe3b`，创建 `dx12` 分支。原估算 12 周（阶段 0＝1.5、1＝2、2＝2.5、3＝1.5、4＝2、5＝1、6＝1.5 周）、8000～10000 行，首个里程碑 `02.Cube` 预计 6 周。

- **Vulkan 参考实现**：32 个文件 / 8893 行。主要文件行数：`VulkanDevice.cpp` 1456、`VulkanCommandList.cpp` 1206、`VulkanPipeline.cpp` 738、`VulkanResources.cpp` 696、`VulkanCommandList_RenderPass.cpp` 570、`VulkanDevice_Descriptors.cpp` 462、`VulkanSwapChain.cpp` 254、`VulkanPipelineLibrary.cpp` 228、`VulkanCommandList_Submit.cpp` 197、`VulkanDGC.cpp` 193、`VulkanDevice_MeshShader.cpp` 142、`VulkanConverters.cpp` 138、`VulkanDevice_DebugUtils.cpp` 89、`VulkanRT.cpp` 446、`PSOPrecompileManager.cpp` 404、`VulkanBindlessHeap.cpp` 87、`VulkanDevice_GPL.cpp` 53、`VulkanTextureLiveness.cpp` 35。
- **调用热度**：`UpdateDescriptorSet` 466、Bindless 相关 267、`SetPipeline` 112、`SetPushConstants` 106、`BindDescriptorSet` 105、DGC 相关 98、`PipelineBarrier` 87、`Dispatch` 55、`EndOffscreenPass` 45、`BeginOffscreenPass` 40、`DrawIndexedIndirectCount` 38、`Draw` 33、`SetVertexBuffer` / `SetIndexBuffer` 20 / 20、`CopyBuffer` 13、`DrawIndexed` 14、`BeginRenderPass` / `EndRenderPass` 6 / 6、`BeginOffscreenPassMRT` 5、`DrawIndexedIndirect` 5、`CopyTextureToBuffer` 4、`CreateBLAS` 3。
- **架构映射**：Vulkan 的命令内存需换成每帧每线程独立的 D3D12 allocator；描述符需影子堆；push constant 受 256 B 限制；image layout 需映射为 resource state（如 `ShaderReadOnly → PIXEL_SHADER_RESOURCE`、`ColorAttachment → RENDER_TARGET`、`DepthAttachment → DEPTH_WRITE`）；Render pass 的 clear / load 需显式模拟；间接绘制、Mesh Shader、DGC、DXR 1.1、fence、query 在 D3D12 有原生对应。
- **关键对策**：bindless 用 64K 纹理槽 + 16 采样器槽的 shader-visible 堆（实际 `maxBindlessResources = 65536`）；`UpdateDescriptorSet` 区分「永久」（纹理 / 采样器）与「每帧」（CBV / UAV）路径；push constant 超限改走 CBV；建立 layout → state 映射表；`LoadOp::Clear` 用 `ClearRenderTargetView`，`LoadOp::Load` 不动；每线程独立 allocator + 每帧回收；PSO 库 / GPL 用 PSO 缓存 + 预编译替代。
- **风险与兜底**：216 个虚函数按调用热度分阶段实现；驱动差异用 `CheckFeatureSupport` 探测并降级；Slang DXIL 失败保留 `-target hlsl` + `dxc` 兜底；描述符分堆避免容量不足；阶段 0 就接 `ID3D12InfoQueue`；定位是「功能等价」而非「数值等价」。

### 2.4 已决定不实施

| 功能 | 原因 |
|---|---|
| 轻量 Begin（`BeginLightweight`） | 默认实现即调用 `Begin()`。D3D12 的 Begin 只轮换本列表自己的帧槽位，没有 Vulkan 那样的全局帧计数推进与延迟销毁副作用，默认实现已经正确。 |
| 渲染通道提示（`ID3D12GraphicsCommandList4::BeginRenderPass` 的加载 / 存储提示） | 只对分块渲染（TBDR）的移动端 GPU 有收益，桌面 GPU 几乎无差别。引擎在 pass 中间会为绘制补资源状态转换、切换只读深度视图（需要 `OMSetRenderTargets`），与原生渲染通道的限制冲突，改动面大且无法测出收益。 |

### 2.5 后续验证建议

按价值从高到低排列。除特别说明外，均要求 `HE_D3D12_DEBUG_LAYER=1`，`[D3D12 ERROR]` 为 0 条；涉及 GPU 行为的再加 `HE_D3D12_GPU_VALIDATION=1`。

1. **DGC 端到端验证（最高价值）**：把 `DeferredPipeline_FrameGraph.cpp:38` 的 `kDGCEnable` 改为 `true`；04 的 cfg 设 `gbuffer_mode=1`、`gpu_cull=1`；用 `HE_CAPTURE_FRAME=200` 各截 DGC 开 / 关一帧，比较 ImGui 面板以外区域，确认 GPU 计数非 0、绘制数正常。再在 4060 的 Vulkan 上确认 `VK_EXT_device_generated_commands` 是否可用，做同场景对照。判据：0 报错、DGC 开 / 关截图差异接近 0、GPU 计数与可见物体数一致。
2. **命令流承载光追（已完成，见 1.6）**：根因是回放侧用 `PayloadAt` 读 `EnqueueArena` 编码的 `CmdBuildBLAS`（长度校验必失败）⇒ BLAS 构建被静默跳过、光线全未命中。改为 `ArenaPayloadAt` 并默认开启后：05 + `HE_RENDER_THREADING_MODE=2` + `HE_RHI_COMMAND_STREAM=1` 跑 143.5 s / 20341 帧、0 报错、0 设备丢失；`HE_CAPTURE_FRAME=90` 截图与模式 0 直录在场景区域逐像素相同。后续可补：04 / 06 的光追效果做同帧截图对照（04 开流已验证 0 报错）。
3. **命令流下的 ImGui**：为 ImGui 的绘制数据做每帧快照（或在回放阶段重建 draw data），解除「绘制数据跨帧失效」的限制。用例：06 / 04 同时开模式 2 + 命令流，打开 Profiler / GI 面板，缩放窗口，确认面板内容与模式 0 一致。判据：面板可见、数值不串帧、0 报错。
4. **真实异步计算 pass**：把 GPU 剔除、SSAO 或某个后处理明确放到计算队列，确保异步 pass 数 > 0；验证 `DEPTH_WRITE → COMMON`、`PIXEL|NON_PIXEL → NON_PIXEL` 的交接、图形队列等待、Profiler 在计算列表重置查询池。用例：04 或 06 打开异步计算开关跑 300 帧以上。判据：0 报错、时间戳不串、画面与同步路径一致。
5. **瞬态纹理 / 内存别名真实用例**：让 04 / 06 的中间渲染目标按生命周期走 RenderGraph 瞬态分配（或新增一个带 3 张瞬态纹理的测试样例），构造生命周期 [1,2]、[3,4] 重叠、[2,3] 与二者都重叠的组合。用调试层检查别名屏障与 `DiscardResource`，并打印分配偏移确认复用。判据：重叠纹理同偏移、不重叠纹理不互相踩、0 报错、显存占用下降。
6. **多线程录制 bundle 的真实门槛**：用绘制数足够多的场景（03.Sponza-Forward 或 04），或临时把 64 条门槛降到 8 / 16，确认 bundle 真正执行。对比单线程录制的截图与帧时间，检查命令列表的线程安全。判据：截图一致、0 报错、无数据竞争（可用调试层 / 线程检查）。
7. **Storage 缓冲迁到 DEFAULT 堆的性能验证**：在 4060 上先给 `D3D12Buffer::Initialize` 加临时统计，列出 `Storage` 且 `cpuAccess=false`、引擎从不 `Map` 的缓冲（GPU Scene、Lumen、Nanite、粒子）；改为 DEFAULT 堆 + 必要的拷贝 / 屏障，测量重载场景帧时间与 Vulkan 的差距。判据：0 报错、画面一致、帧时间下降；若某缓冲仍被 `Map`，保留 CPU 可见堆。
8. **05 粒子深度与 06 光追效果可视化验证**：运行 05（含粒子），确认 `ClearDepthStencil` 生效、粒子不再被错误遮挡，与 Vulkan 同帧截图对比；06 打开 `gi_blend_diffuse_lumen=1` 与 DDGI / RT 反射 / Lumen 远场对应层，固定相机跑 400 帧以上，检查 `LumenScene 远场光追前置检查` 的 `tlas=` 非 0，与 Vulkan 同帧截图对比，并对照 T2 的辐照度 / 命中 / 未命中统计。判据：05 粒子遮挡正确；06 三项效果可见且与 Vulkan 同量级；0 报错。
9. **T8 的 Vulkan 侧与中途 PSO 覆盖**：在 `D3D12Device::CreatePipelineState` 临时记录第 1 帧之后创建的 PSO（调试名 + 耗时），跑各样例与 GI 面板切换，列出高耗时项；在对应模块 `Initialize` 里补 `PrecompileQueuePSO`。Vulkan 侧改为按厂商判断（Intel 关闭、其余开启），在 4060 上长时间运行确认不崩。判据：Release 下切换 GI / 管线的单帧尖峰下降，Vulkan 长跑稳定。
10. **长稳与全量回归**：按指南建议把 T1 的每样例复测从 45 s 加到 2 分钟；T9 的截图循环从 10 次加到 20 次以上；对 01～07 做一轮 Debug + 调试层 + GBV 的回归，记录帧数、`[D3D12 ERROR]` 数、`capture_frameN.png` 字节数与 GPU 时间。性能相关测量用 Release（输出在 `Build\bin\Release`）。判据：全部 0 报错、无设备丢失、截图与 Vulkan 基线一致（允许动画噪声）。
